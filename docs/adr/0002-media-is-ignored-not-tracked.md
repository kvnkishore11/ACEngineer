# 0002 — Media is ignored, not tracked

- **Status**: accepted
- **Date**: 2026-08-13

## Context

The repository carries ~22 GB of lesson video: 8.9 GB of finished recordings and
13 GB of raw capture, plus 1.2 GB of recorder frame stills.

None of it was ignored. `.gitignore` was four lines, and its only real rule
pointed at `multi-agent-orchestration/asset/*.safetensors` — a path that had
moved, so the rule matched nothing. The result was 10,606 untracked paths and a
`git status` that returned roughly 14,000 lines: unreadable for a human and pure
noise for an agent trying to orient itself.

`.git` is already ~11 GB against ~4,700 tracked files.

## Decision

**Ignore the bytes. Track a manifest.**

`media/MANIFEST.md` records path, size and SHA-256 for every file under
`media/` — 5,428 files, 21.5 GB — and is regenerated by
`tools/media/make_manifest.py`. `make check-media` verifies a checkout against
it. The tree stays auditable and any missing or corrupted file is detectable,
without the bytes entering history.

Two details that matter more than they look:

**Ignore by extension, not by directory.** The obvious rule — ignore
`media/raw/` — is unrecoverable, because git cannot re-include a file whose
parent directory is excluded. That would have silently dropped the `*-sync.json`
sidecars the recorder validation reads, and `media/MANIFEST.md` itself. The
policy therefore ignores `*.mp4`, `*.m4a`, `*.mov`, `*.webm` and `*.aac`, so the
JSON and Markdown metadata stays tracked with no negation games.

**Scope the frame-capture rule.** The recorder writes 5,286 `.jpg` stills
(1.2 GB). A global `*.jpg` rule would also have dropped ~400 legitimate catalog
thumbnails and course-page images, so the rule is scoped to `media/raw/`.

## Alternatives rejected

**git-lfs.** Installed (3.7.1) and unused. Rejected: it means paying for and
syncing 22 GB on every clone, for a study archive whose videos are
re-downloadable and already hardlinked locally. LFS solves "large files must be
versioned and distributed"; here they need to be neither.

**Commit the bytes.** Rejected outright — it would roughly triple an already
oversized `.git`, permanently, on a repository that is mostly text.

**A separate media repository or external object store.** Rejected as
disproportionate: it adds a sync step and a second source of truth to solve a
problem that a manifest already solves, and it would break the hardlink between
`media/final/` and the catalog.

## Consequences

- `git status` is readable again; the working tree went from 13,875 dirty paths
  to 0.
- A fresh clone has an empty `media/`. That is expected. `media/README.md` and
  `media/MANIFEST.md` describe what should be there, and the structure test
  asserts that no media file is ever tracked.
- The 18 finished recordings remain hardlinked into `catalog/courses/*/video/`,
  so they cost 8.9 GB rather than 17.8 GB. Any operation that copies rather than
  moves them silently doubles that; `stat -f '%l'` returning `2` is the check.

## Explicitly out of scope

Shrinking the existing ~11 GB `.git`. Large blobs are already in history, and
removing them needs `git filter-repo` or BFG plus a force-push to `origin` —
destructive, coordination-requiring, and unrelated to layout. This decision only
stops the bleeding. History cleanup should be raised as its own, explicitly
approved piece of work.
