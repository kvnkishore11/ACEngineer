Tactic 07 · Target Zero-Touch Engineering

Build the system that can finish without you.

This lesson trains you to command a software-delivery system at presence one: you express intent once, then programmable agents route the work, create an isolated world, plan, implement, test, review, repair, document, and—only for an earned class of work—ship it. The skill is not “trust the model.” It is designing prompts, permissions, launchers, state, and evidence gates so any single worker is replaceable and the loop can close without borrowing your attention.

human intent → trigger → isolated agent relay → proof → recover or ship
In-loopContinuous human steering.
Out-loopPrompt, then human review. Presence ≈ 2.
ZTE targetPrompt only; embedded gates remain. Presence = 1.

04 · Why these files exist for agents

Four contracts turn model calls into an agent OS

The durable design is not a particular model name. It is a set of inspectable interfaces that a fresh worker can obey.

.claude/commands/*.md · .claude/commands/conditional_docs.md · README.md

1 · Prompt contract — what the worker may understand

Slash-command files define one purpose, arguments, context boundaries, and the exact artifact to return. The planning prompts explicitly start at README.md and route extra reading through .claude/commands/conditional_docs.md, preventing every worker from swallowing the whole repo.

The ZTE interlock also lives in language: lowercase zte must downgrade to reviewed SDLC; only explicit uppercase ZTE authorizes the dangerous route.

Dan’s design intent: encode judgment once, invoke it many times, and keep workers narrow enough to replace.

classify_adw.mdprompt evidence
- IMPORTANT: DO NOT RUN the
  adw_sdlc_ZTE_iso workflows unless
  ZTE is EXPLICITLY uppercased.
  …
  If zte is not capitalized, then run
  the non zte version /adw_sdlc_iso.
.claude/settings.json · .claude/hooks/pre_tool_use.py · .mcp.json

2 · Tool and permission contract — what the worker may do

The settings allow a small Bash vocabulary plus writes, deny force-push and recursive removal, and attach lifecycle logging hooks. Playwright MCP gives the reviewer a headless Chromium surface with 1920×1080 screenshots/video.

But source reality defeats the intended guardrail twice: every template launch sets --dangerously-skip-permissions, and the pre-tool hook is wrapped with || true. Its exit code 2 cannot block real .env access or broader dangerous-remove patterns.

Dan’s design intent: capability is engineered, not wished into the model. A failed safety contract is still a contract failure—fix the harness.

settings.jsonpermission evidence
"allow": ["Bash(uv:*)", "Write"],
"deny": [
  "Bash(git push --force:*)",
  "Bash(rm -rf:*)"
],
"command":
  "uv run .../pre_tool_use.py || true"
adws/adw_modules/agent.py · adws/adw_*_iso.py · adws/adw_triggers/

3 · Harness and launcher — how the worker is called

execute_template selects a model from the run’s base/heavy policy, constructs a slash-command prompt, saves it, launches a fresh non-interactive Claude Code process in the worktree, streams JSONL, and retries infrastructure errors on a 1/3/5-second ladder.

Orchestrators remain deliberately thin: they run phase scripts and interpret exit codes. That makes adw_sdlc_zte_iso.py one composition, not the definition of agentic engineering.

Dan’s design intent: agents are programmable processes. Swap the worker, preserve the contract and artifacts.

agent.pylauncher evidence
cmd = [CLAUDE_PATH, "-p", request.prompt]
cmd.extend(["--model", request.model])
cmd.extend(["--output-format", "stream-json"])
if request.working_dir:
    mcp_config_path = os.path.join(request.working_dir, ".mcp.json")
    if os.path.exists(mcp_config_path):
        cmd.extend(["--mcp-config", mcp_config_path])
.claude/commands/test.md · .claude/commands/review.md · adws/adw_test_iso.py · adws/adw_review_iso.py · adws/adw_ship_iso.py

4 · Verification contract — how the system knows it may continue

Tests return structured results and enter capped repair loops. Review compares the diff to the spec, boots the isolated app, captures proof, and treats only blocker severity as release-stopping. Ship refuses to begin until eight state fields and the worktree validate.

ZTE stops on test or review failure, but documentation failure warns and continues. Both SDLC composers hardcode --skip-e2e; browser E2E exists only as a standalone test path. Do not claim proof the harness did not collect.

Dan’s design intent: close loops with evidence. Replace human checking only after the system can prove value and refuse bad transitions.

adw_sdlc_zte_iso.pygate evidence
test = subprocess.run(test_cmd)
if test.returncode != 0:
    sys.exit(1)
review = subprocess.run(review_cmd)
if review.returncode != 0:
    sys.exit(1)
document = subprocess.run(document_cmd)
  • Current-practice translation: command prompts map naturally to Skills; the subprocess wrapper maps to an Agent SDK; hand-built worktrees map to native isolated agents. The interfaces remain even when the plumbing shrinks.
  • Source beats prose: the ADW README says approve + squash, while adws/adw_ship_iso.py fetches, checks out main, pulls, merges with --no-ff, and pushes directly.

05 · Operate like Dan

Run the system from intent to evidence

These commands come from the two real README files. Use the reviewed path until a narrow class has earned ZTE through clean runs and honest presence data.

1

Install the application surfaces

Provision both runtimes so plan, test, review, and app-launch contracts have real tools to call.

cd tac/tac-7/app/server
uv sync --all-extras

cd ../client
bun install
2

Provision credentials without committing them

Copy the server template, authenticate GitHub, and export the ADW variables named by adws/README.md. CLAUDE_CODE_PATH defaults to claude; GITHUB_PAT is optional when gh is already authenticated.

cd ../server
cp .env.sample .env
# edit app/server/.env with provider keys

gh auth login
export ANTHROPIC_API_KEY="..."
export CLAUDE_CODE_PATH="claude"
3

Prove the patient can boot

The launcher reads .ports.env inside a worktree and falls back to 8000/5173 in the main checkout.

cd ../..
./scripts/start.sh
# Ctrl+C stops both services
4

Write a small, observable issue

State acceptance criteria and include one routing keyword. Use adw_patch for a narrow correction or a reviewed composer for a full relay. The issue number becomes the input handle.

gh issue create
# body example: /chore adw_sdlc_iso — concise intent + pass criteria
5

Start with reviewed automation

Plan, build, unit-test, review, and document in one isolated worktree. The composed path always skips browser E2E, so run the standalone test phase without --skip-e2e when that evidence is required.

cd adws
uv run adw_sdlc_iso.py <issue-number>

# optional explicit browser-E2E path after obtaining the ADW ID
uv run adw_test_iso.py <issue-number> <adw-id>
6

Inspect artifacts, not keystrokes

Read the persisted state, phase logs, spec, test result, review screenshots, PR, and KPI row. Ask whether your manual review changed the outcome.

cd ..
cat agents/<adw-id>/adw_state.json
git worktree list
./scripts/check_ports.sh
gh issue view <issue-number> --comments
7

Target ZTE only after the class earns it

Uppercase ZTE in the issue text is the source-era intent interlock. Running the script directly bypasses that natural-language downgrade and will merge to main if its gates pass.

cd adws
# direct invocation — irreversible main-branch path
uv run adw_sdlc_zte_iso.py <issue-number>

Commander checklist

  • Is the problem class narrow and previously successful?
  • Is the environment isolated and disposable?
  • Do tests and review prove different things?
  • Did browser E2E actually run?
  • Can the loop stop cleanly?
  • Are merge credentials tightly scoped?
  • Will presence be recorded honestly?
Irreversible edge: source code does not approve and squash a PR. It performs a local --no-ff merge and pushes origin/main. Treat branch protection and required CI as external prerequisites, not assumptions.

06 · Common agent failures

When the OS is wrong, intelligence cannot save the run

Mis-prompting: contradictory output contract

.claude/commands/review.md says “JSON array,” but shows an object and the Pydantic parser expects ReviewResult.

Repair: make prose, example, and parser name the same schema; test the boundary.
Over-permission: safety that cannot block

Every worker launches with permission bypass, and || true neutralizes the pre-tool hook’s exit 2.

Repair: default deny, make bypass explicit and environment-scoped, fail closed for secret access.
Missing verification: assuming E2E happened

Both SDLC composers pass --skip-e2e regardless of their parsed flag.

Repair: expose an honest gate in the composer and record which evidence actually ran.
False green: process success, domain failure

A clean CLI exit can still return an empty classification. A required value is missing even if the subprocess says success.

Repair: validate semantic output before moving state; empty required fields are failures.
Shared mutable world: correct agents collide

Without worktrees and dedicated ports, two agents can check out different branches, reset one database, or fight over 5173.

Repair: one ADW ID → one worktree → one branch → one port pair → one state record.
Staying in the loop: human as transition engine

If you manually nudge every phase, the workflow is a macro around your attention, not a closed loop.

Repair: externalize transitions and reserve human presence for intent, authority, and OS improvement.
Doc drift: trusting the README over behavior

The README says squash; source merges --no-ff. The webhook README claims signature validation; the endpoint does not verify one.

Repair: verify irreversible and countable claims against executable source.
Global ZTE: treating a target as identity

“We are autonomous now” removes review across novel, risky, and unmeasured work.

Repair: advance chores → bugs → features per class; move backward when evidence weakens.

07 · Lab · change the agent system

Make one prompt and one guardrail tell the truth

Do not change the SQL application. Repair two operating contracts, then prove the new behavior without shipping anything.

A · Align the review output contract

  1. Open .claude/commands/review.md.
  2. Change “Return ONLY the JSON array” to “Return ONLY one JSON object matching ReviewResult.”
  3. Make the example valid JSON: quote keys, remove trailing commas, and keep success, review_summary, review_issues, and screenshots.
  4. Add one sentence: for UI work, an empty screenshot list makes the review unsuccessful.

B · Make the secret-access hook fail closed

  1. Open .claude/settings.json.
  2. Remove || true from only the PreToolUse hook command. Leave observational logging hooks fail-open.
  3. Probe the hook directly with a fake Read of .env; expect exit 2.
  4. Probe a fake Read of README.md; expect exit 0.
cd tac/tac-7
printf '%s\n' '{"session_id":"lab","tool_name":"Read","tool_input":{"file_path":".env"}}' | uv run .claude/hooks/pre_tool_use.py
echo $?  # expected: 2

printf '%s\n' '{"session_id":"lab","tool_name":"Read","tool_input":{"file_path":"README.md"}}' | uv run .claude/hooks/pre_tool_use.py
echo $?  # expected: 0

Pass criteria · observable, not vibes

  • The review prompt names one JSON object everywhere; no “array” contradiction remains.
  • A sample response can be parsed as the real ReviewResult shape.
  • The secret-file probe exits 2 and prints the block reason; the README probe exits 0.
  • settings.json remains valid JSON.
  • No file under app/ changed, and no ZTE or ship workflow ran.

Reveal a model teach-back

The human commander owns intent, problem-class risk, credentials, workflow choice, and the authority to permit shipping. A fresh worker knows its bounded job through one slash-command prompt plus conditional context and an exact output artifact. The launcher chooses compute, saves the prompt, starts a headless Claude Code process in the run’s worktree, captures JSONL, and validates the result. The ADW state file, Git branch, worktree, ports, and artifacts let every phase restart without inheriting another agent’s conversation. Tests, spec review, screenshots, and bounded patch loops either produce proof or stop the pipeline before ship. ZTE is earned per problem class when presence data shows review adds no value, while deterministic and agentic gates still refuse unsafe transitions.
