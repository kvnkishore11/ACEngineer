Seven Levels Agentic Prompt Formats

A prompt is an interface around an agent: the human chooses the job and risk; structured workflows, tool boundaries, launchers, sub-agents, and proof let the agent carry the work.

01 · Hook · Agent mission

Train the commander to program the worker

This lesson trains you to turn a capable but replaceable Claude Code agent into bounded, callable labor. You choose the lowest prompt level that supplies the needed capability, expose inputs and outputs, grant only the tools the play requires, move long work into a harness or delegate, and demand evidence strong enough to accept, repair, or restart the run.

×100

One vague line can fan into hundreds of tool calls. That is why Dan calls the prompt the fundamental unit of engineering: its clarity or ambiguity is multiplied by the agent system around it.

02 · Picture the actors

The cast: authority stays human; execution moves outward

03 · Agent surface map

The repository is a socket around the model

The Vue app is the lesson’s visual grader. The agent OS lives around it: prompts tell an agent what work means, permissions determine reach, launchers determine lifecycle, and evidence determines whether the commander trusts the result.

The seven levels as operating-system moves

L1Call it

Save one repeatable request.

L2Sequence it

Give input, ordered work, output.

L3Guard it

Branch, loop, stop, retry.

L4Fan it out

Prompt and launch other agents.

L5Feed a plan

Keep wrapper stable; vary input.

L6Compile prompts

Generate interfaces from a template.

L7Update knowledge

Change Expertise, not procedure.

Dan’s leverage rule

This is a capability map, not a maturity ladder. Levels 1–4 cover most work. Add the next level only when the system needs its new move.

04 · Control loop · worked run

Leave the tool-call loop; keep the decision loop

Outside-the-loop does not mean absent. The commander moves from approving every action to defining the boundary and judging durable evidence.

Human stays in

Define the artifact, choose Level 3 versus 4, decide whether permission bypass is acceptable, and accept evidence or change the contract.

Agent moves out

Turn the Workflow into a plan, use tools, prompt sub-agents, update durable reports, run checks, and repair bounded failures.

One worked run: plan file in, verified change out

Commander states the job

Run /quick-plan. The Level-2 planner writes a specification with success criteria instead of touching implementation.

in loop

Commander supplies the returned plan path

Run /build <returned-plan-path>. The plan file makes the stable build wrapper a Level-5 higher-order prompt.

boundary

Builder plans and acts

The primary agent reads the plan, uses Read / Write / Bash, and follows the implementation contract without requiring approval for each ordinary step.

out of loop

Report returns weak evidence

/build asks for a concise summary and git diff --stat. That proves a change exists, not that the app works.

out of loop

Verifier closes the gap

Run the app package’s real bun run build, inspect the diff, and compare the artifact to the plan’s success criteria.

in loop

Recover or accept

If the build fails, send the failure back into the bounded workflow. If evidence passes, accept without replaying every tool call.

decision
↻

Name the pattern: prompt as programmable agent interface. Variables form the call signature; Workflow is the procedure; allowed tools are authority; Report is the return shape; verification decides whether the call succeeded.

05 · Why these files exist for agents

Four contracts make the model operational

The files are not the lesson’s protagonists. They are interfaces that shape what an agent understands, can do, how it is launched, and what counts as success.

Prompt contract

.claude/commands/build.md · .claude/agents/docs-scraper.md · CLAUDE.md

Command files enter as task-local user prompts. Agent definitions act as narrow system prompts. The repository’s CLAUDE.md is empty, so permanent project knowledge is not silently loaded; /prime and the README must establish working context.

description: Build the codebase based on the plan
argument-hint: [path-to-plan]
allowed-tools: Read, Write, Bash

## Variables
PATH_TO_PLAN: $ARGUMENTS

## Workflow
- If no PATH_TO_PLAN is provided, STOP.
- Read the plan and implement it.

Evidence excerpt from .claude/commands/build.md.

Dan’s design intent. Make the task legible to the stakeholder trifecta. A named input, an early return, ordered work, and a return shape turn prose into a callable interface.

Tool / permission contract

command frontmatter · agent frontmatter · .claude/settings.json · MCP samples

Frontmatter names task capabilities; specialist agents declare their own smaller toolbelt. MCP samples attach external services. Settings wire lifecycle hooks, but they do not replace permission design.

allowed-tools:
  Task, WebFetch, Write, Edit, Bash(ls*),
  mcp__firecrawl-mcp__firecrawl_scrape

# settings.json
"PostToolUse": [{
  "matcher": "Read|Write",
  "command": "...context_bundle_builder.py --type file_ops"
}]

Condensed evidence from load_ai_docs.md and settings.json.

Dan’s design intent. Capability should be inspectable before execution. The command may orchestrate; the worker gets only the tools its narrow role requires; hooks observe state transitions for later recovery.

Harness / launcher

.claude/commands/background.md · scripts/bg_claude_code_test.sh

The Level-4 background prompt launches a second primary agent, passes a task unchanged, appends a report-writing system contract, and lets the interactive commander continue working.

claude --print \
  --model "${MODEL}" \
  --output-format text \
  --dangerously-skip-permissions \
  --mcp-config .mcp.json \
  --append-system-prompt "You are running as a background agent. Document your progress continuously in ${REPORT_FILE}. When starting, create the report file and write your understanding of the task. Update it as you work through the task. Include any findings, blockers, or important information. When complete, rename the file to ${REPORT_FILE}.complete.md. If you fail or cannot complete the task, rename it to ${REPORT_FILE}.failed.md." \
  "${USER_PROMPT}"

Verbatim runnable invocation from scripts/bg_claude_code_test.sh; its argument-routing defects are covered below.

Dan’s design intent. Treat the agent as callable compute with a durable status channel. The course-era launcher is intentionally vivid; production use must make model, MCP set, report path, isolation, and permission bypass explicit.

Verification contract

apps/prompt_tier_list/package.json · command Reports · hook JSONL

The generic builder reports a diff, while the app package owns an actual typecheck-and-build command. Reports and hook logs improve observability, but neither independently proves the requested behavior.

cd apps/prompt_tier_list
bun run build
git diff --stat
git diff

Dan’s design intent. Put proof where another human or agent can inspect it. “Done” is a claim; a passing build, constrained diff, expected artifact, and explicit terminal state are evidence.

Scope changes the prompt

The seven-level tier list grades task-local user prompts. A system prompt persists across many tasks, so keep its role and broad behavior stable; move deterministic job workflows into commands that can be selected when needed.

06 · Operate like Dan

Run the system from mission to evidence

These are the repository’s real interfaces. The app commands come directly from its README; the slash commands are the Markdown files Claude Code discovers under .claude/commands/.

Packaging changed; the pattern did not

This course-era repository packages reusable workflows as slash-command Markdown and sub-agent definitions; it contains no SKILL.md. Current agent systems often package a Level 2–4 workflow as a discoverable Agent Skill. Keep the seven-level contract vocabulary, but treat its delivery format as replaceable infrastructure.

Enter the repository and start the primary agent

The root README documents claude aliases; use the ordinary CLI first so authority remains visible.

cd agentic-horizon/agentic-prompt-engineering
claude

Prime only the context the job needs

/prime inventories the repo and reads the README. Add /prime_tier_list only when operating the teaching app; use /prime_cc for Claude infrastructure.

/prime
/prime_tier_list

Boot the grader from the real app README

/start wraps the same development sequence. Keep this terminal alive; the visual grid is a teaching instrument, not the agent’s verifier.

cd apps/prompt_tier_list
bun install
bun run dev

Choose the lowest capability level

Use Level 2 for a stable sequence, Level 3 for STOP / loop / retry, Level 4 only when independent workers add leverage, and Levels 5–7 only when prompts or knowledge themselves become inputs.

Separate planning from building

The planner writes a spec; a fresh context can then consume that file through the stable Level-5 build wrapper.

/quick-plan "describe the bounded change"
/clear
/build <returned-plan-path>

Delegate with an explicit return path

For parallel reads, the primary authors self-contained sub-agent prompts and synthesizes them. The background primary is higher risk because the shipped prompt explicitly bypasses permission checks.

/parallel_subagents "audit prompt contracts" 3
/background "bounded long-running task" sonnet report.md

Verify independently, then close the loop

Use the real package build, inspect the diff, and compare it to the plan. If it fails, repair the contract or implementation; if it passes, accept without supervising every tool call.

cd apps/prompt_tier_list
bun run build
git diff --stat
git diff

Compound only trustworthy expertise

The hook-expert triad plans, builds, then reviews recent evidence. The improve command may update only ## Expertise; “no update needed” is a valid closed-loop outcome.

/experts:cc_hook_expert:cc_hook_expert_plan "..."
/experts:cc_hook_expert:cc_hook_expert_build <spec-path>
/experts:cc_hook_expert:cc_hook_expert_improve
07 · Fail the system on purpose

Common agent failures—and the seam to repair

A longer prompt or a stronger model is not a universal repair. Diagnose which contract produced the bad state.

Mis-prompting: “handle the repo”

No bounded artifact, Workflow, or Report exists, so the agent invents missing intent.

Repair: prompt → purpose, input, ordered work, proof.

Level inflation

A simple workflow becomes meta, delegated, and self-updating because seven sounds better than two.

Repair: design → add only the capability the task requires.

Empty memory mistaken for context

CLAUDE.md is empty. An unprimed agent has no repository-specific standing instructions from that file.

Repair: context → run the relevant prime and read the README.

Over-permissioned autonomy

--dangerously-skip-permissions plus a vague background task creates a large, unattended blast radius.

Repair: authority → narrow tools, path, prompt, MCP set, and isolation.

Stateless sub-agent gets a fragment

Delegation assumes the worker shares the parent’s hidden context, so outputs diverge or stall.

Repair: delegate prompt → self-contained inputs and return schema.

Specialist route points nowhere

crypto-coin-analyzer.md references an absent .claude/commands/agent_prompts/... path and lacks Read despite asking the agent to read that file.

Repair: system prompt → real target path plus least-privilege tools.

Report treated as verification

/build asks for a summary and diff stat; neither proves the Vue app typechecks or builds.

Repair: verifier → run bun run build and inspect acceptance evidence.

Hooks log but never judge

The hooks record lifecycle payloads and context bundles; they do not assert task success.

Repair: loop → pair observability with explicit pass/fail checks.

Observability leaks sensitive state

The universal logger stores full hook payloads; prompts and tool data can be sensitive even in ignored files.

Repair: evidence → redact, retain briefly, and restrict access.

Course-era pins become runtime errors

Pinned model IDs, named tools, Firecrawl/Replicate MCP, and exact CLI flags can drift while the pattern remains sound.

Repair: config → update environment-specific values; preserve the role and contract.

Capability config does not parse

.mcp.json.playwright_10k.sample contains an extra closing brace, so copying it verbatim produces invalid JSON before the agent gains any browser capability.

Repair: capability → parse configuration before activation, then test the named tool.

Documentation drift wins over executable truth

Older prose says twelve prompt sections; entities.ts defines thirteen, including High Level Prompt.

Repair: source hierarchy → use executable data, record the drift, do not hide it.

Human stays inside every tool call

Constant supervision consumes the attention the harness was meant to free.

Repair: lifecycle → durable progress, bounded authority, terminal state, independent proof.

08 · Lab · agent ops

Repair a specialist agent contract

Change the agent system, not the tier-list application. The real crypto specialist is miswired in two observable ways, and the repair requires no network call, API key, or financial analysis.

Mission: make the system prompt route to a readable, real prompt

  1. Open .claude/agents/crypto-coin-analyzer.md. Read its tools: field and final Read and Execute: instruction.
  2. Confirm that the referenced .claude/commands/agent_prompts/crypto_coin_analyzer_agent_prompt.md path does not exist.
  3. Confirm that the actual prompt exists at .claude/commands/crypto_coin_analyzer_agent_prompt.md.
  4. Change the system-prompt route to that real path.
  5. Change the specialist tool list to Read, WebSearch, Bash: Read is required to load the contract; Write is unnecessary because the target prompt reports analysis but writes no file.
  6. Run the static checks below. Do not launch the specialist; live market research is outside the lab’s pass criteria.
test ! -f .claude/commands/agent_prompts/crypto_coin_analyzer_agent_prompt.md
test -f .claude/commands/crypto_coin_analyzer_agent_prompt.md
rg -n '^(tools:|Read and Execute:)' .claude/agents/crypto-coin-analyzer.md
git diff -- .claude/agents/crypto-coin-analyzer.md
Route proof

The Read and Execute: value names the real command file exactly.

Capability proof

The allowlist includes Read, WebSearch, and Bash.

Least-privilege proof

Write is absent because the delegated prompt has no file-output contract.

No-spend proof

All checks are local; no sub-agent, search, or API call runs.

Scope proof

The diff changes only the real agent definition, not application logic.

Teach proof

You can name the two repaired seams: prompt routing and tool authority.

Dan’s design intent

A specialist is replaceable only when its interface is explicit. The parent should be able to select it, the worker should be able to load its procedure, and the commander should be able to inspect its authority before launch.
