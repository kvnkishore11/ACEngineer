Tactic #4 · Stay Out The Loop

The agent OS around the code

AFK is not a more obedient chatbot. It is an operating system that moves a human request through bounded agents, deterministic transitions, and reviewable evidence without using the human as the process manager.

AFK
Agent mission

Train a human commander to supply a constrained GitHub issue, choose a trigger and bounded environment, then let a programmable workflow classify, branch, plan, implement, commit, and open a pull request—while saved prompts, run traces, tests, and issue comments make the unattended work observable and recoverable.

01 · WHO ACTS?

A cast, not one giant agent

The word “agent” hides important boundaries. TAC-4 works because a commander, triggers, an orchestrator, fresh CLI workers, deterministic adapters, and reviewers own different moves.

In-loop boundary

Human commander

Writes the issue’s outcome and constraints, selects an environment, enables a trigger, reviews the pull request and evidence, then improves the system when a class of error repeats.

Event actors

Manual, cron, or webhook trigger

adw_plan_build.py, trigger_cron.py, and trigger_webhook.py answer one question: what event is allowed to start unattended work?

Deterministic control plane

ADW orchestrator

adw_plan_build.py sequences the run, validates narrow returns, posts status, exits loudly on failure, and keeps stochastic judgment inside explicit step boundaries.

Fresh reasoning workers

Eight Claude Code micro-agents

Classifier, branch generator, planner, plan finder, two committers, implementer, and PR creator are independent top-level CLI processes with fresh context—not a parent agent’s subagent fleet.

Tools and witnesses

Adapters, scripts, and hooks

agent.py, github.py, shell scripts, and five configured hook events turn model intent into subprocesses, GitHub actions, environment operations, and session logs.

Not present as a role

No dedicated verifier agent

The implementer runs prompt-defined validation; hooks record events; the human reviews the plan, tests, behavior, and PR. SubagentStop is a telemetry hook, not proof that subagents were configured.

Name the pattern

PITER outside; ADW inside; micro-agents at the judgment points. Prompt input, trigger, environment, and review surround deterministic workflow code that calls replaceable agents through narrow contracts.

02 · WHAT DOES THE AGENT TOUCH?

The repository is an operating surface

The useful map is not a directory tree. It is the chain of interfaces that tells an agent what work exists, what context to load, what authority it has, how to act, and where proof must land.

Dan’s leverage move

The app does not import the agentic layer. That separation makes the agents replaceable, the prompts improvable, and the product shippable without the machinery that edits it.

03 · HOW DOES CONTROL MOVE?

Plan → act → verify → recover

AFK does not remove the human from engineering. It moves human judgment to the request, authority, and acceptance boundaries while the workflow owns the transitions in between.

04 · WHY THESE FILES EXIST

Four contracts make AFK work possible

Each contract answers a different systems question: What should the agent understand? What may it do? How is it called? What observation counts as success?

1. Prompt contract · turn prose into machine-sized returns

The thirteen files under .claude/commands/ are not chat suggestions. They are versioned interfaces. Planning prompts restrict research and output shape; glue prompts demand a single class, branch, path, commit message, or URL.

Dan’s design intentKeep ad hoc prompt strings out of orchestration code. A prompt should be independently improvable, and its last line should make the next deterministic step obvious.
.claude/commands/classify_issue.mdexact return vocabulary
## Instructions
Respond exclusively with '/' followed by the command.

/chore · /bug · /feature
or 0 if none apply.

2. Tool and permission contract · decide where trust lives

.claude/settings.json pre-approves twelve patterns, denies three, and wires five hook events. But every ADW template run sets dangerously_skip_permissions=True. Interactive policy and headless policy are therefore different surfaces.

Dan’s design intentMove unattended authority into a bounded environment you can afford to lose. Then still layer narrow tools and tested gates; isolation is a boundary, not an excuse to stop designing permissions.
.claude/settings.jsonabridged · exact entries
"allow": ["Bash(uv:*)", "Bash(npm:*)", "Write"],
"deny": ["Bash(git push --force:*)", "Bash(rm -rf:*)"]

"PreToolUse":
  "uv run .../pre_tool_use.py || true"

3. Harness and launcher · call the agent like a primitive

adw_plan_build.py chooses when judgment is needed. execute_template() turns a slash command plus arguments into a fresh request. prompt_claude_code() invokes the CLI, streams JSONL, converts it to JSON, and extracts the final result object.

Dan’s design intentUse deterministic code for ordering, error policy, persistence, and reporting; use the agent only where interpretation is valuable. A replaceable CLI call should not own the whole workflow.
adws/agent.py · command shape
claude -p "/implement specs/<plan>.md" --model sonnet --output-format stream-json --verbose --dangerously-skip-permissions

4. Verification contract · make success observable

Pre-flight checks inspect environment, Git, GitHub CLI, and a live Claude call. Planning templates require validation commands. The harness checks each result and posts a visible ❌ before exiting. Saved prompts, JSONL, hook logs, commits, tests, behavior, and the PR form a ladder of evidence.

Dan’s design intentAn agent run is not done when the model says “done.” It is done when the review surface contains enough independent evidence to accept the outcome or route a precise repair upstream.
README verification surfaces
uv run adws/health_check.py
cd app/server && uv run pytest
cd app/client && npm run build
cat agents/*/sdlc_planner/raw_output.jsonl | tail -1 | jq .

Course-era surface · durable contract

The lesson’s local extract flags the hand-built subprocess wrapper, pinned model names, flat slash-command packaging, and full permission bypass as period details. Preserve the architecture when tools move: scoped prompt in, bounded authority, structured events out, saved artifacts, explicit failure, and an independent review path.

Source: _extracts/tac-4-afk-agents/outdated-vs-current.md; re-check product-specific choices before adopting them.

A real policy bug hiding in plain sight

pre_tool_use.py exits with code 2 when it sees broad destructive rm patterns or non-sample .env access. The configured command appends || true, which converts that failure to shell success. As written, treat this hook as telemetry—not an enforcement boundary—until you remove the fail-open wrapper and test both allow and deny cases.

05 · OPERATE LIKE DAN

Run the system from boundaries, not from the chat

Start with a manual, low-risk chore in a repository and checkout you control. Prove every PITER role before adding an always-on trigger.

  1. Own the environment first

    Use your own remote and a disposable checkout. Copy sample environment files, then enter keys locally; never paste secret values into an issue or agent prompt.

    README · environment setup
    cp .env.sample .env
cd app/server
cp .env.sample .env

  2. Install the target application

    The agent can only verify what the environment can run. Install both sides before blaming a model for missing tools.

    README · dependencies
    cd app/server && uv sync --all-extras
cd app/client && npm install

  3. Prove the runway

    Run the ADW health check before a paid multi-agent chain. Inspect warnings about the remote, GitHub authentication, CLI availability, and the live model call.

    README · pre-flight
    uv run adws/health_check.py

  4. Create one constrained chore issue

    State the outcome and constraints. Avoid dictating an implementation; /classify_issue and /chore own classification and planning. This is Prompt input in PITER.

  5. Fire manually from the project root

    The root working directory is part of the contract because Claude Code discovers .claude/commands/ there. The main README’s root-path form also matches the webhook launcher’s cwd=project_root.

    README · manual ADW
    uv run adws/adw_plan_build.py <issue-number>

  6. Review the evidence bundle

    Follow the ADW ID through issue comments, agents/<id>/, hook sessions under logs/, branch, commits, plan, tests, and PR. Repeat the decisive validation yourself.

    adws/README.md · troubleshooting
    cat agents/*/sdlc_planner/raw_output.jsonl | tail -1 | jq .

  7. Only then swap the trigger

    Cron and webhook are alternate T implementations. They do not improve a weak prompt, unsafe environment, or missing review surface.

    README · alternate triggers
    uv run adws/trigger_cron.py
uv run adws/trigger_webhook.py

  8. Stop listeners when the drill ends

    Use Ctrl+C for the foreground process. The repository also includes scripts/kill_trigger_webhook.sh and scripts/stop_apps.sh for local cleanup.

Working-directory trap

adws/README.md also says to cd adws/ before launching. But command discovery is rooted at the repository, the video preserves a real wrong-directory “Failed to spawn,” and trigger_cron.py currently launches its child with cwd=adws. Treat working directory as an explicit harness invariant, not an incidental shell detail.

06 · WHEN THE AGENT SYSTEM LIES

A capable model cannot compensate for an incoherent operating surface. Diagnose the boundary that failed before changing application logic.

Artifact repair

Fix this PR by hand

The immediate output improves, but the next run can reproduce the same error. Human presence and review load remain unchanged.

System repair

Fix the producing interface

Change the prompt, permission gate, launcher invariant, or verification step; rerun stable input; prove the error class disappears.

07 · LAB · AGENT OPS

Make one guardrail enforceable—and make completion prove itself

Do not touch app/. Change the operating system around the agent, then close a local, observable loop without running a destructive command.

Mission · repair the permission and verification contracts

Work on a disposable branch. First make the existing PreToolUse guard fail closed. Then strengthen /implement so a completion report must include validation evidence.

1

Observe the mismatch

Read .claude/settings.json and .claude/hooks/pre_tool_use.py. Explain why exit code 2 cannot block when the configured shell command ends in || true.

2

Repair the tool contract

Remove || true from the PreToolUse command only. Leave logging hooks alone. Validate the JSON after editing.

local contract check
python -m json.tool .claude/settings.json > /dev/null
3

Test the hook without executing the tool

Pipe synthetic hook input directly to the Python file. A harmless ls request must exit 0. A destructive rm -rf request and a Read request for .env must exit 2. The hook receives descriptions; it does not execute those commands.

dry inputs · inspect each exit code
printf '%s' '{"session_id":"lab-safe","tool_name":"Bash","tool_input":{"command":"ls"}}' | uv run .claude/hooks/pre_tool_use.py; printf 'safe exit=%s\n' "$?"

printf '%s' '{"session_id":"lab-rm","tool_name":"Bash","tool_input":{"command":"rm -rf ./build"}}' | uv run .claude/hooks/pre_tool_use.py; printf 'rm exit=%s\n' "$?"

printf '%s' '{"session_id":"lab-env","tool_name":"Read","tool_input":{"file_path":".env"}}' | uv run .claude/hooks/pre_tool_use.py; printf 'env exit=%s\n' "$?"
4

Strengthen the completion contract

Edit .claude/commands/implement.md. Require the final report to list every validation command actually run, its exit status, and the observed result. Require an explicit “not run” reason; forbid claiming completion when a required check failed.

5

Review the agent-system diff

The diff should touch agent interfaces only. Explain which PITER element changed, which loop is now closed, and why this is more reusable than repairing one application patch.

scope proof
git diff -- .claude/settings.json .claude/commands/implement.md
git diff --name-only
01settings.json parses and PreToolUse no longer contains || true.
02The safe synthetic request exits 0.
03Both dangerous synthetic requests exit 2 without reading or deleting anything.
04implement.md demands command, exit status, and observed result.
05No file under app/ changed.
06You can name the failed contract, the repaired boundary, and the observable proof.

Pass: a guard that previously looked safe now proves its decision through exit status, and the implementer can no longer report “done” without exposing the validation it performed.

Stretch · close the launcher loop

The timeout handler in agent.py catches TimeoutExpired, but its subprocess.run() call supplies no timeout. Add a typed timeout field, pass it to the subprocess, and prove a deliberately tiny timeout returns success=False without launching a real engineering run.

08 · RETRIEVAL

Explain the agent OS in six sentences

Close the page. Reconstruct the system without file-by-file narration. One sentence per responsibility.

Six-sentence test

  1. Human boundaryWhat does the commander decide before leaving and after returning?
  2. PITERWhat are Prompt input, Trigger, Environment, and Review in this repository?
  3. ADWHow does deterministic code carry one issue from fetch to pull request?
  4. Micro-agentsWhy are the eight CLI runs independent, narrow, and replaceable?
  5. Authority + evidenceWhere do permissions live, and what proves more than a success flag?
  6. RecoveryWhen review fails, why does Dan repair the producing interface instead of only the artifact?

Are TAC-4’s micro-agents Claude Code subagents?

Reveal answer

No. The recorded ADW uses separate top-level claude -p processes. A SubagentStop hook is configured for telemetry, but no explicit subagent definition or parent-to-child delegation layer ships here.

What is the most dangerous misunderstanding in this repository?

Reveal answer

Believing the allow/deny list and intended pre-tool hook automatically constrain headless ADW runs. Template runs request permission bypass, and the configured PreToolUse shell command currently fails open with || true.

What did run 5f2e861e prove—and not prove?

Reveal answer

It proved the eight-step issue-to-PR chain completed and left detailed artifacts. It did not prove every statement in the resulting PR was accurate; semantic acceptance still belongs to review.
