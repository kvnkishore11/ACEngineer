Tactic 08 · The Agentic Layer

Build the ring that operates the code.

This lesson trains you to turn human judgment into callable agent interfaces: a prompt says what “good” means, an authority boundary says what may change, a launcher creates a focused worker, and a verifier decides whether the loop closes or recovers. The application stays at the center; your leverage comes from programming the system around it.

human intent → prompt contract → capable agent → artifact → verifier → recover or accept
Dan’s bias: spend at least half of engineering effort improving the ring. Drop into application code for a deadline, a manual test, or an in-loop prompt check.

01 · Who acts?

The commander is not the runtime

The five examples add roles without changing the boundary: the human supplies intent and authority; agents and deterministic scripts carry work; verifiers produce evidence. “Agent” below means both reasoning workers and the scripts that schedule or constrain them.

ActorOwnsDoes not own
Human commanderIntent, risk, credentials, acceptance. Chooses the problem class, reads the contracts, grants the smallest useful authority, and decides whether evidence is enough.Does not manually shuttle every intermediate artifact once the workflow is trusted.
CLI workerOne prompted purpose. A fresh claude -p process can prime, plan, build, test, review, or document.Does not invent product intent or silently enlarge its permission boundary.
Subagents / relayPlanner → builder → tester → reviewer. Separate workers or subagents inherit narrow prompt contracts, making each role replaceable and each handoff inspectable.Does not depend on one long, fragile conversation.
Trigger / orchestratorState transitions and scheduling. Cron pollers, ADWs, task-board parsers, and worktree launchers claim work and start the right worker.Does not judge semantic correctness; it enforces deterministic policy.
VerifierObservable proof. Tests, review prompts, screenshots, status writes, and exit codes decide pass, retry, or stop.Does not treat “the model returned text” as success.
Embedded AEAA persistent product conversation. App 5 stores agent, ADW, and Claude session IDs so an in-app agent can resume after refresh.It is the deliberate exception—not permission to make every workflow conversational.
Default rule: one agent, one prompt, one purpose. The AEA keeps a session because continuity is the product feature; the delivery workflows prefer fresh workers and explicit artifacts.

04 · Why these files exist

Four contracts make the agent programmable

These are not configuration trivia. They are the agent OS. Change one contract and you change what the system understands, can do, or counts as done.

tac8_app1__agent_layer_primitives/.claude/commands/chore.md

1. Prompt contract

The planner must research the request, write a plan with prescribed validation, then return one parseable path. adw_chore_implement.py extracts that path and hands it to the builder. A prose sentence is therefore also an API.

prime.md separately controls what the worker reads before acting. Context is selected, not dumped.

Dan’s design intent: write a template meta-prompt for a class of work, then let disposable agents solve instances. Keep the output grammar rigid enough for the next program to consume.

prompt evidencechore.md
## Plan Format
...
## Validation Commands
...
## Report
Return the path to the plan file created.

tac8_app5__nlq_to_sql_aea/.claude/settings.json · adws/adw_modules/agent.py

2. Tool and permission contract

The tracked settings show the intended split: routine commands and writes are allowed; force push and recursive removal are denied. Hooks add policy and telemetry. Worktrees, safe environment filtering, and MCP configuration further shape the worker’s world.

The course launchers also include a broad permission-bypass flag. Treat that as period-specific course evidence, not a default. Audit the prompt, use a disposable clone, and prefer the narrowest sandbox and allowlist your runtime supports.

Dan’s design intent: capability creates leverage only when authority is explicit. A “yes” from an overpowered worker is not a reliable system.

settings evidencesettings.json
{
  "permissions": {
    "allow": ["Bash(uv:*)", "Write"],
    "deny": [
      "Bash(git push --force:*)",
      "Bash(rm -rf:*)"
    ]
  }
}

tac8_app1__agent_layer_primitives/adws/adw_prompt.py · adw_chore_implement.py

3. Harness and launcher

The gateway generates an ADW ID, launches Claude in print mode, streams JSON, and writes raw output plus parsed receipts under agents/{adw_id}/{agent}/. The composed workflow runs the planner, extracts its plan path, and invokes the builder with that artifact.

claude -p <prompt> --model <model> --output-format stream-json --verbose

Apps 2 and 4 add polling, task claiming, routing tags, concurrency limits, and detached worktrees. App 5 adds isolated SDLC stages and a resumable in-product agent.

Dan’s design intent: stop copy-pasting between chats. Give every transition a deterministic owner, an ID, and an artifact.

tac8_app5__nlq_to_sql_aea/.claude/commands/test.md · review.md · adws/adw_sdlc_zte_iso.py

4. Verification contract

Receipts prove execution, not correctness. The scaled example asks the test worker for structured results across Python compilation, Ruff, pytest, TypeScript, and frontend build; review compares the diff with the spec and may gather browser evidence.

The zero-touch workflow stops on failed test or review. The non-ZTE workflow is more permissive and can continue after a warned test failure. Read the gates—do not infer them from the filename.

Dan’s design intent: close the loop with evidence that can change control flow. If failure cannot stop, retry, patch, or escalate, Review is only theater.

Execution
exit code + raw JSONL receipt
Behavior
lint + compile + unit + build results
Intent
spec-versus-diff review + screenshots
Closure
hash / status / merge or recorded failure

05 · One worked run

Operate like Dan: learn small, then compose

Start in App 1. Watch one worker, inspect its receipts, then let the two-stage workflow carry the plan. Run in a disposable clone after reading the prompt and launcher authority.

Enter the minimum viable layer

Work from tac/tac-8/tac8_app1__agent_layer_primitives. Its README defines the application center and the three agent interfaces: commands, specs, and ADWs.

cd tac/tac-8/tac8_app1__agent_layer_primitives

Audit before authority

Read README.md, .claude/commands/chore.md, implement.md, and adws/adw_modules/agent.py. Confirm the model, environment, output directory, and permission mode.

Call one focused worker

Use the exact one-shot example in adws/README.md. This is the smallest proof that the harness can invoke the agent and save receipts.

./adws/adw_prompt.py "Write a hello world Python script"

Inspect the receipt, not just stdout

Open the new agents/<adw_id>/<agent>/ directory. Find the submitted prompt, raw JSONL stream, parsed response, and summary. Ask: can another program tell whether this stage ran?

Compose planner and builder

Run the supplied lesson-lab workflow. The planner must return a spec path; the launcher parses it; the builder implements from that file.

./adws/adw_chore_implement.py "create a .sh version of main in apps/*"

Verify the seam

Check that a specs/chore-*.md plan exists, the implementation summary names both phases, the validation commands ran, and the requested shell entry point—not an unrelated refactor—is the material change.

Commander gate

Do not press “autonomous” until you can answer:

  • What exact artifact hands off to the next stage?
  • What can this process modify or call?
  • What evidence changes the next branch?
  • Where is failure recorded?
  • Can a new worker resume without chat memory?

Escalation rule: open a fresh shell at the repository root. Every command below enters its own app before invoking a tracked source interface.

06 · Fail, name, repair

Agent failures are often system failures

When output looks wrong, inspect the contract that shaped it before blaming the model. These failure signatures are visible in—or exposed by—the lesson snapshot.

Mis-prompting breaks the relay

The planner returns commentary instead of one specs/chore-*.md path; the regex cannot hand off to the builder.Repair: preserve a rigid Report grammar and test it as an interface.

Over-permission hides design debt

A broad bypass makes the allowlist look meaningful while the headless process can act beyond it.Repair: narrow the runtime boundary, isolate the checkout, and make exceptions visible.

A receipt impersonates proof

JSONL shows that Claude answered. It does not prove the behavior builds, matches the spec, or is safe.Repair: attach behavioral and intent gates to control flow.

Failure is logged but cannot stop

A hook ending in || true, or an SDLC that warns and continues, turns a red gate into decoration.Repair: decide explicitly which signals fail open, fail closed, retry, or escalate.

Two workers claim the same task

Polling without an immediate state transition creates duplicate branches and conflicting worktrees.Repair: claim with status + ADW ID before delegation.

The human remains a message bus

The commander copies plan text into a second chat and manually updates statuses after every stage.Repair: give handoffs and state transitions deterministic owners.

Review disappears too early

Changing PITER to PITE because the cron works removes judgment without replacing it.Repair: encode the review decision as tests, reviewers, thresholds, and recovery routes first.

Machine assumptions leak into the OS

The AEA start script contains a developer-specific Claude path; another commander cannot launch it unchanged.Repair: parameterize executable paths and verify prerequisites at startup.

Documented architecture ≠ wired architecture

App 3’s README draws Hook Scripts → HTTP POST → Bun Server, and send_event.py exists, but the tracked .claude/settings.json invokes local logging hooks rather than that sender. Treat the page as a design plus a wiring audit—not as proof the live dashboard receives every event.Repair: compare every architecture arrow with the configured callback and a failing integration test.

07 · Lab · Agent operations

Strengthen the planner contract—without touching app logic

Your target is App 1’s agent OS. You will make plans more verifiable while preserving the exact report sentence the launcher parses.

Change one interface

  1. Use a disposable clone. From tac8_app1__agent_layer_primitives, inspect .claude/commands/chore.md and the path extraction in adws/adw_chore_implement.py.
  2. Run a planner-only baseline:
    ./adws/adw_slash_command.py /chore lab0001 "write a plan to add a shell entry point beside apps/main.py"
  3. Save the generated plan and receipt. Do not implement it. Point SUMMARY at the gateway’s printed summary path, then exercise the composer’s first plan-path pattern against the saved output:
    SUMMARY=agents/<run-adw-id>/executor/custom_summary_output.json python -c 'import json,re,sys; s=json.load(open(sys.argv[1]))["output"]; m=re.search(r"specs/chore-[a-zA-Z0-9-]+\.md",s); assert m,"composer could not extract plan path"; print(m.group(0))' "$SUMMARY"
  4. Edit only .claude/commands/chore.md. Add required Acceptance Criteria and Evidence to Capture sections to its Plan Format. Preserve Return the path to the plan file created.
  5. Run the same planner request with lab0002. Compare the two plan artifacts, inspect the new receipt, and repeat the parser-only check with the second summary.
  6. Use git diff -- .claude/commands/chore.md and git status --short apps/ to prove the human changed the agent system, not the application.
Make it fail on purpose: temporarily replace the Report instruction with “Summarize the plan without naming its file path.” Run the planner and the parser-only check; the assertion should fail even though a plan may exist. Restore the strict sentence, run again, and name the pattern: structured artifact handoff.

Observable pass criteria

  • The second generated plan contains both new headings.
  • Each acceptance criterion names an observable outcome.
  • Evidence items point to commands, files, or output—not “looks good.”
  • The planner still returns one valid specs/chore-*.md path.
  • A receipt exists under the run’s agents/ directory.
  • No file under apps/ changed.
  • Your only manual source edit is the prompt contract.

08 · Retrieval check

Explain this agent OS in six sentences—without looking

The human commander owns…
The prompt contract converts…
The permission and harness contracts determine…
The out-of-loop controller moves work by…
Verification closes the loop when…
Dan’s leverage move is…
Compare with a model answer
The human commander owns intent, authority, risk, and the final acceptance decision. The prompt contract turns a class of work into a bounded role with a parseable artifact. Permissions define the worker’s authority, while the harness gives it an ID, context, isolation, and a place to leave receipts. Out of the loop, a trigger claims state, launches fresh specialists, and carries explicit artifacts between them. Verification closes the loop only when evidence can stop, retry, patch, or escalate the run. Dan’s leverage move is to improve this replaceable operating ring until the human designs the system instead of serving as its runtime.
