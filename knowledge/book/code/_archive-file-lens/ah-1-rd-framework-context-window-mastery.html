AH-1 · Code deep dive

Elite Context Engineering

Dan built a laboratory for one idea: an agent performs better when every token has a job. The repo reduces automatic context, loads task-specific context on demand, delegates isolated work, and records enough evidence to restart cleanly.

Would you staple a 79 KB handbook to every tiny request?

The large memory file is not merely documentation. It is a controlled demonstration of context bloat.

The active CLAUDE.md is 1,222 bytes. The deliberately bloated CLAUDE.large.md is 79,709 bytes—about 65× larger. If the large version were always loaded, even “rename this variable” would begin under thousands of unrelated lines about CQRS, caching, tracing, APIs, and testing.

Dan’s architecture answers a simple question at every boundary: does this information deserve to be present now? If yes, prime it. If another worker can own it, delegate it. If it may matter later, write a compact artifact instead of carrying the entire conversation.

Architecture

Four design moves explain almost everything

01 · COST

Make startup cheap

Keep universal memory short and launch only the MCP schemas a job needs.

02 · TIMING

Load late

Slash commands turn optional knowledge into an explicit choice at the moment of use.

03 · OWNERSHIP

Move the job

Sub-agents and separate processes carry their own exploration instead of polluting the primary window.

04 · EVIDENCE

Write the trail

Specs, JSONL bundles, logs, session IDs, and reports survive after a context reset.

Why this design is a teaching repo

Some files deliberately disagree with the checkout or contain rough edges. Dan is demonstrating context bloat, context rot, isolation, and control mechanisms—not shipping one cohesive production application.

Walk the code · Reduce

1. Shrink what every session pays for

README.mdThe conceptual spine and twelve-technique syllabusPurpose

Job: teach the R&D framework, then point at each executable example in the repository. The README progresses from measurement and MCP reduction through priming, output control, sub-agents, architect/editor separation, bundles, primary agents, and experts.

README.mdthe governing rule
There are only two ways to manage your context window effectively:

**R and D - Reduce and Delegate**

- **Reduce**: Remove junk context, minimize token usage, focus on what matters
- **Delegate**: Offload work to sub-agents, separate agents, or specialized systems
  1. The twelve techniques are not twelve unrelated tricks. Each implements Reduce, Delegate, or both.
  2. The repository contains probes and configurations for the techniques; it is not the frontend/backend product described by some stale instructions.

Walk the code · Evidence

3. Turn invisible context into an append-only trail

.claude/settings.jsonThe event router for both logging systemsWiring

Job: attach hooks to Claude Code lifecycle events. Every event goes to the universal logger. User prompts plus successful Read/Write operations also go to the compact context bundle.

settings.jsonselected routes
{
  "PostToolUse": [
    {
      "matcher": "Read|Write",
      "hooks": [{
        "type": "command",
        "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/context_bundle_builder.py --type file_ops"
      }]
    },
    {
      "matcher": "*",
      "hooks": [{
        "type": "command",
        "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/universal_hook_logger.py"
      }]
    }
  ]
}
  1. PreToolUse logs the proposed action; PostToolUse logs its result.
  2. UserPromptSubmit feeds both loggers, while Stop, SubagentStop, Notification, PreCompact, SessionStart, and SessionEnd feed the universal logger.
  3. The Python files are executable UV scripts, so settings can invoke them directly through their shebangs.
.claude/hooks/context_bundle_builder.pyA compact replay index, not a transcriptPython hook

Job: preserve just enough history to reconstruct a focused session: user prompt prefixes, file paths, Read ranges, and Write content lengths.

context_bundle_builder.pydata reduction
log_entry = {
    "operation": tool_name.lower(),
    "file_path": file_path_relative
}

if tool_name == "Read":
    if "limit" in tool_input:
        tool_input_filtered["limit"] = tool_input["limit"]
    if "offset" in tool_input:
        tool_input_filtered["offset"] = tool_input["offset"]

# UserPromptSubmit path
log_entry = {
    "operation": "prompt",
    "prompt": prompt[:500]
}
  1. It exits early for tools other than Read/Write and failed Write responses.
  2. It converts paths under CLAUDE_PROJECT_DIR to relative paths, keeping outside paths absolute.
  3. It appends one JSON object per line to a day/hour + session filename. JSONL makes each observation cheap to append and easy to stream.
  4. It never stores written content, and it truncates prompts at 500 characters. That is intentional reduction.
Boundary to notice

The bundle directory is relative to the hook process’s current working directory, while the universal logger anchors itself to CLAUDE_PROJECT_DIR. If the hook runs from an unexpected directory, the two logs can land under different roots.

.claude/hooks/universal_hook_logger.pyFull-fidelity lifecycle diagnosticsPython hook

Job: retain the complete incoming payload for each event, enriched with an ISO timestamp and separated by session and hook name. Unlike the compact bundle, this is diagnostic evidence.

universal_hook_logger.pyfull payload
def create_log_entry(input_data: dict) -> dict:
    return {
        "timestamp": datetime.now().isoformat(),
        "payload": input_data
    }

log_dir = Path(project_dir) / "agents" / "hook_logs" / session_id
log_file = log_dir / f"{hook_name}.jsonl"

Its broad except returns exit code 0 so observability cannot block the agent. The tradeoff is silent data loss after one terse stderr message. Full payloads may also contain sensitive prompt or tool data, so the generated log directory must remain private.

.claude/commands/load_bundle.mdThe reset-and-replay algorithmCommand

Job: read one JSONL bundle, understand prior prompts without executing them, deduplicate file entries, and replay each file once with the most comprehensive recorded range.

load_bundle.mdselection rule
If ANY entry has no tool_input parameters, read the ENTIRE file.
Otherwise prefer offset 0, then the largest limit.
If all reads start later, choose the largest offset + limit.
If a file appears more than three times, read the entire file.

The command separates intent history from action authority: prompt entries explain what the previous user asked, but the loader is explicitly forbidden from acting on those old prompts.

Walk the code · Delegate

4. Give isolated research to isolated agents

.claude/commands/load_ai_docs.md → .claude/agents/docs-scraper.mdOne URL per focused workerFan-out

Job: read the URL inventory in ai_docs/README.md, keep fresh cached files, delete stale ones, and launch one docs-scraper task per missing URL in parallel.

load_ai_docs.mddelegation boundary
For each url in ai_docs/README.md that was not skipped,
Use the Task tool in parallel and follow the scrape_loop_prompt:

Use @agent-docs-scraper agent - pass it the url as the prompt

The parent retains the URL list and final report. Each child carries webpage chrome, scraping details, cleanup, and file writing in its own window. The agent’s exact response contract—success/failure, saved path, source URL—keeps the result small.

.claude/agents/research-docs-fetcher.md · .claude/agents/meta-agent.mdBroader research and specialist generationAgents

Research agent: accepts URLs or topics, skips research artifacts younger than 24 hours, cleans sources into Markdown with metadata, and reports batch successes and failures.

Meta-agent: reads current sub-agent documentation, infers the minimum tools for a requested role, and writes a new configuration into .claude/agents/. Its job is to design the isolated context boundary itself.

Why two documentation agents?

docs-scraper is a narrow URL-to-file worker used by /load_ai_docs. research-agent can search a topic, manage freshness, batch sources, and cross-reference results. Different purpose means different context.

.claude/commands/background.md · scripts/bg_claude_code_test.shA separate primary agent that reports through a fileProcess

Job: launch a complete claude --print process with its own model, system prompt, tool context, and report file. This is stronger isolation than a sub-agent because the whole primary session is separate.

background.mdprimary-process handoff
claude \
  --model "${MODEL}" \
  --output-format text \
  --dangerously-skip-permissions \
  --append-system-prompt "...continuously update ${REPORT_FILE}..." \
  --print "${USER_PROMPT}"

The durable report is the communication channel. The parent does not need the worker’s intermediate conversation; it can inspect progress and the final renamed artifact.

Demo sharp edges

The shell probe assigns REPORT_FILE=${2:-...}, so its second argument doubles as both model and report path; the command contract correctly describes report file as $3. The Markdown example also contains fragile shell interpolation/line-continuation text. Treat these as experiments to repair before production use.

5. Spend exploration once, then hand over a crisp artifact

.claude/commands/quick-plan.md → .claude/commands/build.mdPlanner and builder communicate through a spec pathPipeline

Planner job: explore the request, architecture, edge cases, tests, and success criteria, then save a kebab-case specification. Builder job: accept only PATH_TO_PLAN, read it, implement it, and report the diff.

build.mdtiny editor contract
## Variables
PATH_TO_PLAN: $ARGUMENTS

## Workflow
- Read the plan at `PATH_TO_PLAN`. Think hard about the plan and implement it.

## Report
- Summarize the work in a concise bullet list.
- Report files and total lines changed with `git diff --stat`.

The planner is allowed to be messy. The builder begins with the cleaned artifact instead of the planner’s search history—that is Reduce achieved through Delegate.

.claude/commands/experts/cc_hook_expert/Three real commands: cc_hook_expert_plan.md, cc_hook_expert_build.md, cc_hook_expert_improve.mdExpert trio

Plan loads hook docs and current infrastructure, chooses events/output formats, and writes a specification. Build converts that spec into executable UV hooks, settings, tests, and documentation. Improve reviews recent hook diffs and updates only the stable commands’ ## Expertise sections when a reusable lesson exists.

expert control loopknowledge compounds
request
  → cc_hook_expert_plan      (investigate + specify)
  → cc_hook_expert_build     (implement + validate)

Contract versus checkout

The expert files reference fetched AI docs and generated spec directories that are absent here. They are dependencies the commands expect to create or load, not files in the audited tree.

.claude/output-styles/ · .claude/settings.local.concise.jsonControl how much output returns to contextOutput

Job: make response size an explicit mode. The styles range from one-word Done. and ultra-concise fragments to hierarchical bullets and valid YAML. The TTS style keeps visible text short, then calls ElevenLabs for a spoken summary.

concise-done.mdextreme reduction
Respond with only "Done."

There are only three exceptions:
1. A different response was explicitly requested.
2. A direct question needs a concise answer.

6. Move the same controls behind a TypeScript boundary

apps/hello_cc_1.ts · apps/hello_cc_2.tsTwo minimal probes of the async SDK streamProbe

Job: reveal the Claude Code SDK message protocol before building an abstraction. Both call query(); one permits Bash for a time lookup and two turns, while the other permits no tools and one turn.

hello_cc_2.tsstream inspection
for await (const message of query({
  prompt: "Hello! Please respond with a friendly greeting...",
  options: {
    model: "sonnet",
    maxTurns: 1,
    systemPrompt: "You are a helpful AI assistant...",
    allowedTools: []
  }
})) {
  if (message.type === "system" && message.subtype === "init") {
    console.log(`Session started: ${message.session_id}`);
  }
  if (message.type === "result") console.log(message.result);
}

The examples surface session ID, model, working directory, tools, duration, cost, turns, and success. Measurement comes before abstraction.

apps/cc_ts_wrapper/types.tsThe small public language of the wrapperTypes

Job: define what callers may configure and what they get back. ClaudeSettings holds turn/tool/system/session controls; ReusablePromptConfig holds a named prompt template; PromptResult normalizes success, messages, error, and session ID.

types.tssafe defaults
export const DEFAULT_SETTINGS: ClaudeSettings = {
  maxTurns: 5,
  allowedTools: ["Bash", "Read", "Write", "Edit", "WebSearch"],
};

The types are the seam: the CLI and future programmatic callers do not need to understand every SDK message variant.

apps/cc_ts_wrapper/core.tsOne-shot adapter plus reusable prompt registryCore

Job: offer two paths over one execution primitive. adhoc_prompt() calls the SDK directly. reusable_prompt() looks up a named configuration, expands {USER_PROMPT}, layers defaults, then delegates to adhoc_prompt().

core.tsthe shared execution seam
const mergedSettings = { ...DEFAULT_SETTINGS, ...settings };

for await (const message of query({
  prompt,
  options: {
    abortController,
    maxTurns: mergedSettings.maxTurns,
    customSystemPrompt: mergedSettings.systemPrompt,
    allowedTools: mergedSettings.allowedTools,
    continue: mergedSettings.continue,
    resume: mergedSettings.resume,
  }
})) {
  if (message.type === "result" && message.subtype === "success") {
    result.messages.push(message.result);
  }
  if (message.type === "system") result.sessionId = message.session_id;
}
  1. The in-memory Map is enough because commands are registered at process startup.
  2. Layering is global defaults → command defaults → call settings; a call can specialize a reusable expert without editing it.
  3. Only successful result text is collected. System messages contribute the session ID; other stream messages stay internal.
Subtle merge bug

Spreading an object that contains undefined overwrites a real default. The CLI always constructs keys for maxTurns and allowedTools, even when flags are absent, so direct ad-hoc calls can erase DEFAULT_SETTINGS. Filter undefined keys or merge with ?? before production use.

apps/cc_ts_wrapper/cli.tsThe human-facing argument and command boundaryCLI

Job: register /analyze and /refactor, parse Bun arguments, list commands, translate flags into ClaudeSettings, choose reusable versus ad-hoc execution, and print normalized results.

cli.tsa reusable expert definition
register_prompt("/analyze", {
  name: "analyze",
  description: "Analyze code or system performance",
  systemPrompt: "You are a senior engineer analyzing code quality and performance",
  defaultSettings: {
    maxTurns: 10,
    allowedTools: ["Read", "Grep", "Bash"]
  },
  promptTemplate: "Analyze the following: {USER_PROMPT}"
});

This is the programmatic version of context engineering: a purpose-specific system prompt, tool allowlist, turn budget, and prompt template travel as one reusable object.

Why the lab uses --list

The list path proves registration and argument parsing without spending model tokens or requiring an API key. It is the smallest feedback loop around the extension seam.

.claude/utils/llm/ · .claude/utils/tts/Small provider adapters behind output experimentsUtilities

LLM job: the Anthropic, OpenAI, and Ollama scripts expose the same three operations: prompt a fast model, generate a short completion message, and generate a one-word agent name with fallbacks. Provider details stay behind matching function names.

TTS job: the ElevenLabs, OpenAI, and offline pyttsx3 scripts accept text from argv and play it immediately. UV inline metadata makes each script self-declaring; environment variables select remote credentials.

These utilities are supporting experiments, not wired into the hooks. concise-tts.md explicitly calls the ElevenLabs script. The Ollama metadata lists openai twice, and several files import unused modules—more evidence that this is an instructional workbench.

Put it together

How a focused run works end to end

  1. Start with the universal floor.

    Claude loads the concise project contract. A strict MCP launch can restrict startup tool schemas to the selected project file.

  2. Prime for this purpose.

    /prime loads only inventory + README; /prime_cc composes the extra agentic layer when the task concerns Claude Code.

  3. Record the request.

    UserPromptSubmit sends a shortened prompt to the bundle builder and the full lifecycle payload to the universal logger.

  4. Execute one bounded job.

    A command may work locally, fan out URLs to docs agents, hand a spec from planner to builder, or launch an independent primary process.

  5. Capture tool evidence.

    Every tool event is logged; successful Reads/Writes also add reduced path/range metadata to the context bundle.

  6. Return a small result.

    An output style or a specialist’s response contract controls what comes back into the primary context.

  7. Reset without amnesia.

    After /clear, /load_bundle reconstructs the most comprehensive unique reads while treating old prompts as history, not new instructions.

The SDK path is the same architecture in code

  1. CLI parses intent.

    Flags and positionals become a command name, prompt, and settings object.

  2. Registry supplies purpose.

    A reusable command contributes its system prompt, tool allowlist, turn budget, and template.

  3. Core opens the stream.

    adhoc_prompt() calls query() and observes system/result messages.

  4. Normalized evidence returns.

    The caller receives success, result messages, error, and session ID instead of the raw stream.

Common fail

Six ways the idea gets misapplied

“Concise means correct.”

The active memory is short but names absent app directories. Reduce size and verify freshness.

“Available tools are free.”

MCP schemas consume startup context even if unused. Launch with the narrow strict configuration.

“The bundle is a backup.”

It stores prompt prefixes and Read/Write metadata, not full conversation or file contents.

“Every delegation is the same.”

A sub-agent is a partially isolated worker; /background launches an independent primary process with a file channel.

“Spreads preserve defaults.”

An explicit undefined overwrites defaults in JavaScript. The wrapper’s CLI/core boundary demonstrates the trap.

“Observability is harmless.”
