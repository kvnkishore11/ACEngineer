ZTE Secret of Agentic Engineering

Dan’s zero-touch workflow is not one super-agent with permission to merge. It is six ordinary programs, joined by a tiny state file, isolated in one worktree, and forced through explicit failure gates before the final program touches main.

Hook

Would you let this code merge itself?

That sounds like a yes-or-no question. It is the wrong question. The useful question is: what must become true, and what evidence proves it, before the merge program is even reachable?

Dan’s answer: make “ship” the last small primitive in a chain. Plan leaves a spec. Build leaves a diff. Test leaves structured results. Review leaves issues and screenshots. State points to the shared worktree. Non-zero exits stop the chain.

The secret is not “trust the model.” It is move trust into composition: narrow workers, durable artifacts, deterministic isolation, typed outputs, bounded repair loops, and a final irreversible action behind gates.

Architecture

Five design moves make ZTE legible

01

Compose processes

The ZTE script starts focused phase programs and branches on exit codes.

02

Share pointers

Ten small state fields identify the issue, plan, worktree, ports, and history.

03

Isolate reality

Every run gets a worktree and port pair, enabling concurrent work.

04

Make judgment data

Pydantic contracts make tests, severity, screenshots, and retries branchable.

05

Put danger last

Only ship checks out main, merges, and pushes.

The reusable primitive is smaller than the SDLC

ZTE is one composition with a ship primitive appended—not a separate monolith.

The ZTE file is intentionally boring

adws/adw_sdlc_zte_iso.pyThe six-phase conductor and top-level stop policy.orchestrator

The strongest fact is what this file does not do. It never asks one model to complete “the whole SDLC.” It ensures a run ID, then invokes six scripts. Each child reloads durable state and starts focused agents.

adws/adw_sdlc_zte_iso.pylines 90–145
plan = subprocess.run(plan_cmd)
if plan.returncode != 0:
    print("Isolated plan phase failed")
    sys.exit(1)

build = subprocess.run(build_cmd)
if build.returncode != 0:
    print("Isolated build phase failed")
    sys.exit(1)

  1. subprocess.run makes each phase an operating-system boundary. A phase cannot silently continue the parent’s context.
  2. The return code is the composition protocol: zero makes the next phase reachable; non-zero stops ZTE.
  3. GitHub comments are observability, not control. The gate remains the child result.

Read policy from branches, not from the happy-path list

Plan, build, test, review, and ship failures stop ZTE. Documentation does not. The top-level --skip-e2e flag is parsed, but the test command always appends --skip-e2e; this composition never runs browser E2E.

Tests and review are repair loops, not ceremonies

adws/adw_test_iso.pyStructured testing with bounded per-failure repair.evidence loop

The tester calls /test, parses TestResult, gives each failure to a focused resolver, and reruns. Unit attempts cap at four; optional E2E attempts cap at two.

ExitMeaningZTE
success=trueLatest suite is green.Review is reachable.
no repairResolvers changed nothing.Stop.
budget spentLoop did not converge.Stop.
agent/parse errorNo trustworthy result.Stop.

ZTE always passes --skip-e2e. Its merge gate is unit tests plus review—not the browser recipes.

adw_review_iso.py + .claude/commands/review.mdSpec judgment, screenshots, severity, blocker repair.review loop

Review compares git diff origin/main with the spec, prepares the app, captures one to five screenshots, and returns ReviewResult. Only blockers fail success. Up to three review attempts permit repair and re-review.

Prompt contradiction

The prompt says “JSON array,” but its example and Pydantic parser expect a JSON object. Tight output contracts should not contradict themselves.

adw_document_iso.pyDiff + spec + screenshots → product docs and KPIs.handoff

Documentation can decide no docs are needed; otherwise it writes app_docs/, updates conditional retrieval, tracks KPIs, commits, and pushes. KPI failure is non-blocking, and ZTE treats the whole documentation phase as non-blocking.

The factory’s patient: natural language → SQL → table

The orchestration is generic. The product supplies something concrete to plan, change, test, review, document, and ship.

main.ts → api/client.ts → server.pyOne query crosses browser and server.product flow
  1. Capture intent.

    main.ts debounces 400 ms, disables input, builds QueryRequest.

  2. Cross the API seam.

    api.processQuery posts JSON; Vite proxies /api in development.

  3. Expose schema.

    FastAPI reads SQLite tables, columns, and row counts for the model prompt.

  4. Generate SQL.

    Available keys prioritize OpenAI, then Anthropic; model output is fence-stripped.

  5. Validate and execute.

    Dangerous SQL/comments/injections are rejected before SQLite.

  6. Render evidence.

    Rows, columns, SQL, timing, and CSV export controls become DOM.
