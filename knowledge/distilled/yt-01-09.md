## YT-01: I Can SEE EVERYTHING — Claude Code Hooks for Multi-Agent Observability
**Thesis:** Once you scale past one Claude Code instance, observability is everything — hooks streaming every lifecycle event to a simple one-way client/server pipeline let you "see everything" your agents do.

**Nuggets:**
- "When it comes to multi-agent systems, observability is everything." Running a single agent "is just the beginning."
- Architecture is deliberately minimal: hooks → HTTP POST → Bun server → SQLite (persist) + WebSocket (stream) → Vue client. "This one-way data stream keeps things really simple."
- Every Claude Code hook event is tracked: PreToolUse, PostToolUse, Notification, Stop, SubagentStop, PreCompact — with session ID and source app on every row.
- Hash the app name + session ID into a color so you can visually tell agents apart at a glance — cheap UX that matters at 5–10 agents.
- Each event runs a summarization prompt via a small fast model (Haiku) *before* sending — "thousands of events... less than 20 cents." "This is where small fast models really shine."
- The Stop event carries the full chat transcript path — perfect time to copy the entire log and filter/inspect it (all reads, all globs, all assistant responses).
- "If you don't measure it, you can't improve it. If you don't monitor it, how will you know what's actually happening?"
- Hooks give "deterministic control over Claude Code's behavior" — steer, monitor, control.
- "Frameworks are irrelevant when it comes to raw productivity. Your agent knows all of them" — the Vue client is disposable; convert it to any framework with a prompt.
- The codebase-wrapping "agentic layer" (`.claude/`, hooks, apps) is a new layer around your code that "will change the way you engineer forever."
- Endgame: "prompting back and forth, one prompt at a time is not the way to engineer. It's a great place to start. It's a terrible place to finish." Push toward off-device, fully programmable agentic coding.

**Tools/tech:** Claude Code hooks (all 6+ lifecycle events), Bun server, SQLite, WebSockets, Vue.js, Astral UV single-file Python scripts, Haiku for event summaries, TTS notifications (from prior hooks video).

**Repo:** `disler/claude-code-hooks-multi-agent-observability` — full hooks→server→client observability stack for multiple concurrent Claude Code instances.

**Drill (build):**
1. Clone the repo; wire the `.claude/hooks` `send_event` script into one codebase's settings.json.
2. Start the Bun server + client; fire a Claude Code session and confirm events land in SQLite and stream to the UI.
3. Add a second codebase/instance and confirm both stream in with distinct session colors.
4. Enable the `--summarize` flag path so PreToolUse/PostToolUse rows get Haiku one-liners.
5. Open a Stop event and walk the full transcript from the payload.
- **Done when:** two simultaneous Claude Code sessions stream live color-coded events with model-generated summaries, and you can filter by event type and session.

## YT-03: My Claude Code Sub-Agents BUILD THEMSELVES
**Thesis:** Sub-agents are tools of delegation for your *primary* agent — you write their *system prompts*, they respond to the primary agent (not to you) — and a meta-agent can generate new sub-agents on demand.

**Nuggets:**
- The two big mistakes: (1) not realizing the agent .md file is the sub-agent's **system prompt**, not a user prompt; (2) not realizing sub-agents **report back to the primary agent, not to you** — "the flow of information here is absolutely critical."
- Flow: you → primary agent → prompts sub-agents → sub-agents respond to primary → primary reports to you. Write the report section explicitly: "Claude, respond to the user with this message."
- The `description` field is the routing contract — it's what the primary agent reads to decide when to invoke a sub-agent. Encode trigger phrases ("If they say TTS, TTS summary, use this agent") and even *how to prompt it* ("When you prompt this agent, describe exactly what you want them to communicate").
- Use Anthropic's information-dense keywords (IDKs): "use PROACTIVELY", "MUST BE USED", "IMPORTANT:" to raise prompt adherence.
- Meta-agent: a sub-agent whose system prompt knows how to generate complete new sub-agent files from a description — "my agents are building my agents." Dan has built 50–100+ agents with it. It re-pulls live Claude Code docs on the fly rather than trusting stale context.
- Workflow discipline: **problem → solution → tech**, in that order. "Noobs and beginners start with the technology and work backward."
- Validate the workflow manually in the primary agent first (run the ElevenLabs tools by hand), *then* encode it into an agent.
- Sub-agent = context preservation (own isolated context window; saves your primary's window) — both the superpower and the trap: "it has only what your primary agent prompts it with," equivalent to a one-shot `claude -p` call with zero history.
- Cons to watch: hard to debug (you don't see internal prompts/params), decision overload as agent count grows, dependency coupling in chained agents ("you're going to change the planner agent and it's going to ruin everything else"), and sub-agents can't call sub-agents.
- "Code is a commodity. Your fine-tuned prompts can be valuable." / "If deleting causes you pain, you probably aren't deleting enough."
- Use `/all_tools` style listing prompts to discover MCP tool signatures before wiring agents to them.
- Only rule that scales: keep sub-agent workflows isolated and focused — "a focused agent is a performant agent" (foreshadows YT-09).

**Tools/tech:** Claude Code sub-agents (`.claude/agents/`), meta-agent, custom slash commands, ElevenLabs MCP server (TTS + play audio), hooks-driven TTS on Stop, Cursor for prompt editing, Claude docs.

**Repo:** `disler/claude-code-hooks-mastery` — hooks (all lifecycle events) + sub-agents + meta-agent playground.

**Drill (build):**
1. Clone claude-code-hooks-mastery; read `.claude/agents/meta-agent.md` and one simple agent (hello-world).
2. Pick a real problem (e.g., work-completion TTS summary). Validate the tool workflow manually in a primary agent session.
3. Prompt the meta-agent to generate the new sub-agent; review the generated file.
4. Tighten the `description` with trigger words + prompting instructions for the primary agent; add tool restrictions.
5. Fresh instance: trigger it via natural phrasing and confirm the primary delegates correctly.
6. Read the hook logs to trace primary→sub prompt and sub→primary response.
- **Done when:** a meta-agent-generated sub-agent fires from its description alone, and you can point to the exact primary→sub→primary information flow in the logs.

## YT-07: 5 Agent PATTERNS to Simplify Your Agentic Coding
**Thesis:** There are five agent interaction patterns — ad-hoc human-in-the-loop, reusable prompts, sub-agents, wrapper MCP server, full application — and you should climb that ladder left-to-right only as the problem earns it.

**Nuggets:**
- The bet behind everything: "a majority of the economic value of AI will come from AI agents."
- Pattern 1 — iterative human-in-the-loop: high control, "you are quite literally stuck in the loop... you are in fact the bottleneck." Great start, terrible end.
- Pattern 2 — reusable prompts (slash commands): "the 80/20 of agent interaction patterns... write it once, reuse all the time." "Three times marks a pattern" — automate on the third repetition.
- Pattern 3 — sub-agents: the decision rule is crisp — "only use sub-agents when you need **specialization and parallelization**. If you don't need to parallelize and you don't need to specialize, just create a reusable prompt." Every sub-agent is another context/model/prompt to manage.
- Sub-agent cons: Claude Code lock-in, the "gray box" debugging problem, and the primary↔sub prompt flow you must engineer.
- Pattern 4 — wrapper MCP server: build when you must integrate multiple services or expose repeat functionality behind your own interface. "The MCP server is an interface layer." And the sleeper feature: **MCP prompts** — "the real value of the MCP server is in the prompts that represent the reusable workflows of specific tool calls... insanely underrated, insanely underused."
- Pattern 5 — full application (CLI + MCP + UI + API): only with a long-term vision or non-engineering consumers. "What's the difference between a customer-facing application and a developer tool? It's the interface layer."
- Master framework: "Keep it simple, scale when needed... always go from left to right, never right to left."
- "Complexity should be earned, not assumed." / "Larger working systems are almost always built from simple working systems." / "Don't overengineer. Let the patterns emerge naturally from usage."
- Skipping levels 1–2 means "there are things you don't know about the problem... because you didn't do it by hand" — where "by hand" now means *with your agent in the loop*.
- Each level up = more compute, more complexity, more build time. For the images-for-a-presentation example he'd stop at level 2, go 3 only for 100+ images, 4 only when other services join.

**Tools/tech:** Claude Code, Gemini CLI (TOML reusable prompts), Codex CLI (dinged for lacking reusable prompts), Replicate MCP server, Qwen image edit, MCP tools/prompts/resources.

**Repo:** none.

**Drill:** watch-and-absorb. Internalize: (1) the five-level ladder and its costs — start ad-hoc, codify on the third repetition; (2) the sub-agent gate: specialization + parallelization or don't; (3) MCP servers are interface layers whose *prompts* (not just tools) carry the workflow value. Bonus: classify every automation you currently own into levels 1–5 and check nothing skipped a level.

## YT-08: Agentic Workflows — BEYOND the Chat UI (Claude Code SDK + Nano Banana)

- "A lot of engineering work is file-based" — reuse "the oldest interface known to engineers": folders and files, the file system as UI.

- Use LLMs to generate the *input files* at scale, then drop them — agents on both sides of the pipe.
- "The models, the agents, are no longer the bottleneck. It's now a complete skill issue."
- "Think about the repeat workflows you can now automate with agents" — every drop zone is an encoded, reusable solution.

## YT-09: Elite Context Engineering with Claude Code
**Thesis:** "A focused agent is a performant agent" — context engineering is managing the context window with only two moves, **R&D: Reduce and Delegate**, applied across beginner → intermediate → advanced → agentic levels.

**Nuggets:**
- The whole discipline in one frame: "There are only two ways to manage your context window: R and D — reduce and delegate."
- Beginner/Reduce #1: don't preload MCP servers. A default `mcp.json` ate 24.1k tokens (12% of the window) before work began. Delete it; load per-task with `claude --mcp-config <file>` (+ `--strict-mcp-config` to override globals).
- Beginner/Reduce #2: **context priming over CLAUDE.md**. "A CLAUDE.md file is incredible for one reason: it's a reusable memory file that's always loaded. Simultaneously it's terrible for the exact same reason." Memory files only ever grow (his bloated demo: 23k tokens ≈ 10% of the window).
- Rule for CLAUDE.md: "only the absolute universal essentials that you're 100% sure you want loaded 100% of the time" (his trimmed file: 43 lines / ~350 tokens).
- Context priming = per-task-type `/prime` slash commands (prime_bug, prime_feature, prime_cc...) — "your hot-loading memory file," fully controllable per run.
- Intermediate/Delegate: sub-agents are "a partially forked context window" — agent definitions are *system prompts*, costing the primary ~122 tokens for three agents. `/load_ai_docs` fanned out ~10 scraper sub-agents, keeping ~40k scrape tokens out of the primary.
- If you're losing track of a single agent's context, "you probably aren't yet ready for sub-agents" — master one window first. Track every agent's core four (context/model/prompt/tools).
- Advanced: **context bundles** — hooks append a trimmed log (prompt + reads/searches, not writes) per session; after a context blowout, `/load_bundle <path>` re-mounts a fresh agent to ~60–70% of the prior agent's state.
- Agentic: **primary multi-agent delegation** — `/background` boots a whole background Claude Code instance (via CLI/SDK) with a report file it must write to and rename on completion; "compute orchestrating compute, agents orchestrating agents." Get out of the loop.
- "It's not necessarily about saving tokens. It's about spending them properly. We manage our context window so that we don't waste time and tokens correcting our agents' mistakes."
- The scaling law justification: model performance degrades as context grows → "it's a safe bet to bet on context engineering."
- Ladder mantra: "What's better than a prompt? A prompt chain. What's better than a prompt chain? An agent. What's better than an agent? Many focused, specialized agents."
- Teaser: agent experts (`.claude/commands/experts/` with expertise.yaml + self-improve) as potentially the most powerful technique.

**Tools/tech:** `/context`, `claude --mcp-config` / `--strict-mcp-config`, CLAUDE.md vs `/prime` commands, sub-agents (doc-scraper), Firecrawl MCP, hooks-driven context bundles, `/load_bundle`, `/background` (CLI + Python SDK delegation), experts directory, TAC course concepts (in-loop → out-loop → ZTE).

**Repo:** `agentic-horizon/elite-context-engineering` — CLAUDE.md variants (concise/large), prime commands, bundles, background delegation, experts scaffolding.

**Drill (build):**
1. In one of your real repos, run `/context` and record the baseline (MCP tokens, memory-file tokens).
2. Delete/trim: remove default mcp.json, cut CLAUDE.md to universal essentials only; re-measure.
3. Write two prime commands (`/prime` general, `/prime_<tasktype>` focused) and use them instead of memory.
4. Wire the context-bundle hook (append prompt+reads to `agents/context_bundles/…`) and test `/load_bundle` in a fresh instance.
5. Add a `/background` command that launches a background CC instance with a report file; kick off a plan while your primary stays free.
- **Done when:** startup context is ≥90% free, a fresh agent can resume a dead session from a bundle, and one background agent completes a delegated task with a written report — no babysitting.

# Cross-video synthesis

**The through-line (chronological arc):** observe your agents (01) → understand the primitive (02) → delegate via sub-agents (03) → pick model tiers (04) → eval models fairly (05) → raise the human↔agent information rate (06) → choose the right interaction pattern (07) → leave the chat UI entirely (08) → engineer the context window itself (09).

**Recurring laws:**
- The Big Three: context, model, prompt — every feature/tool is legible through them.
- Prompt anatomy: Purpose / Variables / Workflow / Report — used in every repo.
- A focused agent is a performant agent; better agents, then more agents.
- Three times marks a pattern → codify as a reusable prompt.
- Complexity should be earned, not assumed; keep it simple, scale when needed.
- Get out of the loop: in-loop → out-loop → background/off-device agents.
- Close the loop: every prompt should include its own validation step.
