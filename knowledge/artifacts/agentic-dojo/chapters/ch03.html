The Idea — Twelve Levers, One Blind Genius

Bet on what never changes: the software development lifecycle, compressed to five steps.

The Phase-Two SDLC — Plan, Code, Test, Review, Document — is "our framework for success," the aspect of engineering that never changes while tools and models churn underneath it.

Every leverage point you control either rides inside the agent or flows through it. The Core Four (context, model, prompt, tools) are "always with your agent." The other eight are "external levers… that typically flow through the context window."

The framework for success. Plan, Code, Test, Review, Document — the loop the whole course automates.
The 12 Leverage Points of Agentic Coding. Four ride in-agent; eight flow through the context window. "Your agent can only see what you let it see."

If you don't measure it, you can't improve it.

The Agentic Coding KPIs: Size is the amount of work handed off per prompt. Attempts is the number of prompts needed to finish — target the one-shot. Streak counts back-to-back one-shot successes. Presence is "how much you the engineer have to sit, guide and correct your AI agent" — target zero.

Two more named ideas power this lesson: IDKs — Information Dense Keywords ("Types are IDKs. They point to exact locations in your codebase and represent the flow of a specific type of information") and the Agent Navigation Problem — every new agent must re-explore your codebase, so architecture and consistency stack up "for you or against you." When a workflow repeats, remember: "three time makes a pattern" — template it into a slash command.

Build your codebase for agents — the architecture checklist

  • Clear entry points; constants files; types, classes, structures
  • Meaningful, verbose names — everything you name can be an IDK
  • Files under ~1000 lines; one responsibility per file; separated services
  • Agent docs (README / CLAUDE.md) spread through the tree
  • Test tree mirroring the source tree

"Plans are just prompts… great planning is great prompting." And at the top of the stack sit Templates (reusable prompts — custom slash commands) and ADWs: "one or more agentic prompts wrapped in arbitrary code, kicked off autonomously with a trigger" — the highest level of abstraction.

◴ bad agentic code
  • "Not only do we have bad code, we have bad agentic code" — code that hides errors from agents.
  • Endpoints return raw responses, exceptions swallowed, nothing on stdout.
◵ good agentic code
  • Every exception logs all details; every successful response logs before returning.
  • Errors trace to standard out — the agent diagnoses and fixes without you.
HAND OFF ERRORS "Stop looking at error messages… give them to your agent. Only when your agent fails do you take your precious time and dig in."
MISTAKES ARE FINE "Your agent will make mistakes, just like you. The only question is: does it have the leverage it needs to correct them?"
MEASURE IT "If you don't measure it, you can't improve it." Track Size, Attempts, Streak, and Presence on every session.

The Workout

GOAL Make one real codebase legible to agents via stdout, types, and a /prime command — and verify with a one-shot fix.
PREREQUISITES Claude Code · a small client/server project (or clone disler/tac-2).

It's not about you anymore. It's about what you can do for your agent so they can work for you.

— quote of the lesson

  1. Build /prime

    Create .claude/commands/prime.md: run git ls-files, read README, summarize the codebase. Boot claude, run /prime.

  2. Build /tools

    A command that asks the agent to list all its tool definitions; read the output and note 2 capabilities you didn't know.

  3. Audit one endpoint

    If it swallows errors, prompt the agent (with @file references) to log every exception and success to stdout.

  4. Close the loop on a real bug

    Run your app's start script inside the agent with a long bash timeout; trigger a known error in the UI; ask "any issues with the server?" then "resolve".

  5. Trace a type

    Copy one core type into a fresh agent and ask for the full flow trace — file → function → purpose format.

  6. Score yourself

    Track KPIs for the session: size of task, attempts, streak, presence — write them down.

DONE WHEN The agent detects and fixes a runtime bug in one attempt purely from stdout, and your type-trace covers every layer of the app.
LEVEL UP Refactor one confusing directory using the architecture checklist (entry points, verbose names, <1000-line files, mirrored tests) and re-measure attempts on a similar bug.
