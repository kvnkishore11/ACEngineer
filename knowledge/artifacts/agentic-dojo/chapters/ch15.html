The Idea

The Agentic Layer is "the new ring around your codebase where you teach your agents to operate your application on your behalf as well and even better than you and your team ever could."

The application layer bundles everything app-side — front end, back end, DB, scripts, DevOps, even multiple repos as git submodules under apps/. The agentic layer wraps it all.

And the destination: the codebase singularity — the moment you realize "my agents can now run my codebase better than I can... Nothing ships to production without my teams of agents." "There is an agentic layer that could exist inside your codebase so powerful that your codebase runs itself."

The ring, drawn. You operate the agentic layer; the agentic layer operates the codebase. Each class wraps the last until nothing ships without your teams of agents.
Three classes, twelve grades. From a lone prime prompt to an orchestrator running AI developer workflows — agentic autonomy on top, deterministic raw code underneath.

Class 1 — in-loop agentics

  • G1 · prime prompt / memory files — "the thinnest possible agentic layer you can have."
  • G2 · plan prompts + sub-agents — fetch-docs, test-writer; specs/ for plans, ai_docs/ for pulled documentation.
  • G3 · custom tools — skills, MCP servers, prime commands with tool access: "all three give us the same thing: custom tools that enhance our agent's core four."
  • G4 · closed-loop prompts — code review, reproduce bug, test back/front end. "Request, validate, resolve." "You're effectively adding more compute to get more confidence in your agent's results."
  • G5 · templates — bug, feature, chore, new-API-endpoint: "where you truly template your engineering and teach your agents to build like you do."
  • G6 · prompt chains — "one prompt now references many prompts and/or sub-agents." Context engineering "becomes a requirement" here.
  • G7 · agent experts — mental models. "This is where we start to see your agents solving problems end to end without you" — the doorstep of the singularity.

Class 2 — out-loop

  • G1 · webhooks/triggers + a core agent SDK layer — "you can execute prompts against your codebase from an external service" (Slack, Jira, GitHub, Discord). The PITER framework realized.
  • G2 · AI Developer Workflows — "deterministic code plus non-deterministic agents. You get the best of both worlds": logging, validation, retries between agent steps. "Once you find yourself deleting your prompt chains and replacing them with concrete AI developer workflows... you will be at class two, grade two."

Class 3 — orchestrated

  • G1 · the Orchestrator Agent — "a custom agent that is a lead engineer that can CRUD, command and manage other agents."
  • G2 · Orchestrator Developer Workflows — entire multi-team workflows with open streams of communication: "we can talk to any one of these agents from this workflow at any time."
  • G3 · the orchestrator runs ADWs — agentic autonomy on top, deterministic raw code underneath. The final grade.

The Nuggets

01

The core four's origin

"Compute in its most useful form is in a prompt and a loop with tools — the agent. This transformed the big three into the core four."

02

A prompt beats an MCP

"Skills and MCP servers can both be replaced with just a simple prompt." — "MCPs are very token heavy and we can just prompt engineer properly to get our agents the tools they need."

03

The grade-three trap

"A lot of engineers do get stuck at grade three... their tools are terrible and they won't scale and they're chewing up tokens." — "Designing tools is an entire game on its own."

04

Trust is bought with compute

"Always add feedback loops... More compute should equal more trust, not less. If it's less, you're doing something wrong."

05

Templates make it yours

"When you start building templates, your agent starts operating more like you would — the way you solve a bug is very different from the way you solve a chore."

06

The winning structure

"You want all of the actual application layer code to run under apps/, and if they're coming from a different git repository, set up git submodules. This is the winning codebase structure."

We are now commanders of compute.

— "You're building the machine that builds your product now."
  • "If you have this [a prime prompt], you technically have an agentic layer."
  • "Your agentic layer should be specialized to fit and wrap your codebase... Don't focus on reuse. Focus on making these prompts great for that one codebase."
  • "I would absolutely never build a plan, build, review workflow that cannot be run individually" — composability + isolation for debugging and parallelization.
  • "You can't write a five agent long prompt chain without knowing the context that every agent will have at every step."
  • "Everything is just a context, model, prompt [and tools]. It doesn't matter what it's called... everything eventually becomes the core four."
  • "The composite type doesn't matter" — expert as prompt set, skill, sub-agent, or custom agent: "do you have a specialized agent that can operate specific parts of your codebase better than you can?"
  • "By this point you have to have adopted your agent's perspective. There's no way around that."
  • "That small chore, that small bug — you absolutely are wasting your time [doing it in-loop]. I guarantee you that."
  • "Imagine you are your agent right before you hit enter... could you solve the problem you're going to ask your agent to solve?"
  • "If you cannot encode what you would do into your prompts... you will not get repeated agentic success."
  • "You will not scale your agentic layer if you are stuck in the terminal prompting back and forth."
  • "There are two problems in there and the chance they accomplish both go down" — one agent, one prompt, one purpose.

The Workout

GOAL Grade your own codebase against the class/grade rubric — and climb exactly one grade this week.
PREREQUISITES A real repo you work in daily; workouts AH-1..AH-5 give you the pieces for grades 1–7.

  1. Audit

    Create agentic_layer_audit.md with a checklist row per grade (C1G1 prime/memory → C3G3 orchestrator + ADW). For each: have it / partial / missing, with file paths as evidence.

  2. Identify your current grade

    The highest grade where everything below is solid. Most engineers: C1G3–G4 — "a lot of engineers are probably missing agent experts."

  3. Pick the next grade and build its distinguishing artifact

    → G4: one closed-loop prompt (test_backend.md) with explicit request → validate → resolve steps that loops until tests pass.
    → G5: bug.md — a template with your exact debugging steps, a relevant-files section, and a mandatory validation step; have your agent fill it in for a real bug.
    → G6: plan_build.md chaining your existing /plan and /build — and verify each piece still runs standalone.
    → G7: build the AH-5 database expert.
    → C2G1: expose one HTTP webhook that fires claude -p "/plan_build <task>" against your repo from outside the terminal.
    → C2G2: wrap that chain in a script (deterministic code) with logging, a validation gate between plan and build, and one retry.

  4. Run one real task at the new grade

    Keep the produced artifacts — spec, review file, expertise diff — as your trail of success.

  5. Re-grade

    Update the audit file. Schedule the next climb.

DONE WHEN The audit file exists with evidence paths; one real work item shipped through the new grade's mechanism without you editing code by hand; you can state your class/grade in one sentence.
LEVEL UP Convert your most-used prompt chain into a true ADW (deterministic script + agent SDK calls + logging/validation/retries), then put your O-Agent in front of it — Class 3, Grade 3, knocking on the codebase singularity.
