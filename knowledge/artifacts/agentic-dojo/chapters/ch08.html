The Idea

Tactic #7: Target Zero Touch Engineering. "Just like you've stopped coding, you'll stop reviewing… This is YOLO mode for your AI developer workflows. Maximum confidence mode for agentic engineering."

The ZTE realization: "This human in the loop model is a bottleneck. I'm not catching any bugs anymore. I'm not adding any value outside of the agentic layer. I'm going to remove the human review for this class of problems." Threshold intuition: ~90% confidence, rising with every model, tool, and template improvement.

"You'll drop yourself off the end of the Outloop Peter framework and it becomes Pete, not Peter. You'll drop off the review."

PITER → PITE. Prompt input, trigger, environment stay; the review — you — comes off the end once the streak proves you add no value there.
Three levels of velocity. In loop → out loop → ZTE. The best out-loop coders sit at presence 2 (prompt + review); ZTE is presence 1 — the prompt only.

The scale is a progression, not a switch: "Think in the gray. We're not jumping to out-loop. We're progressively handing off more and more work." Two knobs make it practical:

ISO workflows (git worktree isolation). adw_sdlc_iso (plan → build → test → review → document, isolated), adw_sdlc_zte_iso (SDLC + ship), adw_patch_iso, adw_ship_iso. Every workflow creates its own worktree under trees/ with its own ports, env, and install (/install_worktree) — "the easiest way to parallelize your workflows." Docker and VMs work too; "it only matters that you can."

Model sets (base | heavy). An encoded IDK passed in the issue body; agents.py maps each slash command to a base or heavy (Opus-class) model, parsed by /classify_adw at workflow start — "a knob to turn to increase the compute that your workflow uses."

The ship step. Checkout main outside the tree → merge the feature branch → post success — "approve and merge the PR agentically… deploy, ship."

"The secret of tactical agentic coding is that it's not about the software developer lifecycle at all. It's about composable agentic primitives you can use to solve any engineering problem class."

— quote of the lesson

The SDLC "is powerful, but it's a remnant of the past… a package for me to deliver a message to you." What remains are the primitives — and a choice among the four postures toward the future: run away · stand still · walk toward it · sprint ("beat everyone else there").

The Workout

GOAL Run two ADWs in parallel via git worktrees, then take one trivial problem class to zero-touch (auto-merge).
PREREQS TAC-6 composed pipeline; webhook or local trigger; a repo where auto-merging to main is safe.

  1. Add worktree isolation

    At ADW start: git worktree add trees/<adw-id> -b <branch>, run /install_worktree (copy envs, install deps, assign unique ports), and run all agents with cwd inside the tree.

  2. Add a model-set knob

    A classify_adw step that parses model_set: base|heavy from the issue body, and a map from each slash command to a model.

  3. File two issues simultaneously

    One chore, one small feature — confirm both worktrees run concurrently without collisions.

  4. Write adw_ship.py

    From the root repo: checkout main, merge the ADW branch, push, close the issue with a success comment.

  5. Compose adw_sdlc_zte.py

    Plan → build → test → review → document → ship. Pick a genuinely trivial class (style tweak, copy change) and run it end to end with zero review.

  6. Verify by pulling main

    The change should already be there.

DONE WHEN Two parallel worktree runs complete cleanly, and one issue goes prompt → production merge with your presence = 1 (the prompt).
LEVEL UP Harden the ZTE gate: require N consecutive one-shot successes on a problem class (tracked in a log) before ship is allowed; add a parallel double-review — two review agents must both pass — as the merge condition.
