The Idea — the Ladder & the Lego Blocks

"We're now engineering for three audiences: you, your team, your agents. This is the stakeholder trifecta for the age of agents."

Master seven escalating prompt formats built from consistent, swappable Lego-block sections — with the workflow section as the S-tier pillar. The on-ramp is simple: "Three times marks a pattern — copy whatever you're doing and just write it as a high level prompt, then move up the levels."

The stakeholder trifecta. Every prompt you invest in multiplies for all three at once.
The seven-level ladder. "The high level prompt is a great place to start. It's a terrible place to end."
L1

High Level Prompt

"The reusable ad hoc static prompt" — the one-off you throw into a file when work repeats. 1–3 sections: Title, High Level Prompt, Purpose.

L2

Workflow Prompt

"Easily the most important one" — a sequential list of tasks the agent executes. Adds Metadata, Variables, Workflow, Report.

L3

Control Flow Prompt

The workflow gains "conditions, loops, and early returns" — e.g. "if no path to plan is provided, immediately stop and ask."

L4

Delegation Prompt

"A prompt that kicks off other agents to do work" — "our primary agent is the prompt engineer for our sub agents." S-tier useful, A-tier skill.

L5

Higher Order Prompt

"We are passing prompts into prompts" — a stable top-level scaffold with a swappable payload, e.g. /build <path_to_plan>.

L6

Template Meta Prompt

"The most powerful prompt you can write. It's the prompt that creates your other prompts" — with a Specified Format the agent fills in.

L7

Self-Improving Prompt

"We're having our agents update our agents… by having our prompts update our prompts," via a dynamic Expertise section.

Swappable Lego blocks. Input → Workflow → Output — "a very consistent three-step pattern you can use to think about how to design and build your prompts."

The sections are composable Lego blocks, each graded by Dan on usefulness / skill-to-write. "You can call these sections whatever you want. I'm using the most consistent, most information dense keywords to represent every section."

Variables come in two flavors — dynamic ($1 / $ARGUMENTS) and static in-prompt constants. Examples "can drastically increase your agent's performance." And information dense keywords (IDKs) — words like IMPORTANT — carry extra weight for models.

ONLY WHAT YOU NEED"Only add what you need — these are composable pieces of your agentic prompts."

System prompts

"The big idea is scope and level of persistence. System prompts are rules for all conversations… mistakes scale to every user prompt you run." Key sections: Purpose, Instructions, Examples — Workflow only when you're sure, because "workflows reduce agency to increase determinism."

User prompts

Scoped to one task, one run. This is where the seven levels live day-to-day — and where you'll be "creating, reading, updating and deleting your prompts at light speed."

What Dan Did

Every prompt lives in the agentic-prompt-engineering codebase — and each one was graded live on a tier-list app.

  1. Level 1 — two ad hoc prompts

    all_tools.md (title + high level prompt: list your tools from the system prompt) and start.md (adds Purpose; cd / bun install / bun dev).

  2. Level 2 — the workflow four

    prime.md (metadata, purpose, workflow, report); build.md (allowed-tools, argument-hint, PATH_TO_PLAN referenced throughout); quick-plan.md (dynamic USER_PROMPT + static PLAN_OUTPUT_DIRECTORY = specs/); prime_tier_list.md (context map + "read these files exclusively" with IMPORTANT).

  3. Level 3 — control flow

    build.md's early return demoed live; create_image.md ($1/$2 args, static vars, an XML-wrapped image_loop, Replicate MCP); edit_image.md (loop + exit-immediately conditionals, no Report section on purpose).

  4. Level 4 — delegation

    parallel_subagents.md (prompt_request + count; fired 5 agents to extract CLAUDE.md-worthy essentials); load_ai_docs.md (24-hour delete rule, a loop calling the doc-scraper sub-agent directly); background.md (delegation + control flow + appended system prompt).

  5. Level 5 — higher order

    build.md reframed: plans from /quick_plan (or chore/feature builders) passed in as the lower-order prompt.

  6. Level 6 — template meta

    meta_prompt.md — the prompt that builds prompts (reads the slash-command docs first, fills a Specified Format) — and a plan_vue_view rapid-prototype planner with a Plan Format template section.

  7. Level 7 — self-improving

    The experts/ hook expert with its dedicated Expertise section — "we're basically updating the context inside of our prompts in a live way."

  8. System vs user prompts

    Distinguished them with the doc-scraper sub-agent (a system prompt with purpose, static output dir, workflow) and the background prompt's --append-system-prompt.

The Workout

GOALBuild a seven-level prompt ladder in one repo — one prompt per level, all sharing the same section format.
PREREQUISITESClaude Code; a small app repo; the AH-1 workout done (you have prime.md).

  1. Level 1

    all_tools.md: Title + one high-level line — "List all tools available to you from your system prompt in a bullet list."

  2. Level 2

    prime.md with exactly: metadata (description, allowed-tools), Title, Purpose, Workflow (numbered reads), Report. Run it; confirm the agent's todo list mirrors your workflow steps.

  3. Level 2.5

    plan.md: dynamic USER_PROMPT: $1, static PLAN_OUTPUT_DIRECTORY: specs/; reference both variables at least twice in the workflow.

  4. Level 3

    build.md: PATH_TO_PLAN: $1; first workflow line: "IMPORTANT: If no PATH_TO_PLAN is provided, immediately stop and ask the user for it." Test by running /build with no args.

  5. Level 4

    parallel_subagents.md: PROMPT_REQUEST: $1, COUNT: $2; workflow step "design agent prompts — create detailed self-contained prompts for each agent, define clear output expectations." Run with count 3 on a research question.

  6. Level 5

    Chain them: /plan "add X" → copy the spec path → /build specs/<file>.md.

  7. Level 6

    meta_prompt.md: takes a request, reads the slash-command docs, emits a new command file matching your exact level-2 Specified Format. Use it to generate a /test.md prompt.

  8. Level 7

    Add an Expertise section to one prompt plus a self_improve.md that reads git diff and updates only that section.

"Consistency beats complexity. Consistency makes you faster."

— why every level shares one skeleton
DONE WHENAll seven commands exist and collapse to the same header skeleton; /build early-returns without args; the meta prompt generates a working new command in your format; the self-improve run edits only the Expertise section.
LEVEL UPGrade each of your sections on Dan's usefulness/skill tier list, then delete every section that isn't earning its tokens — "only add what you need."
