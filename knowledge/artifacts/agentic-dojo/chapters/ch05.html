The Idea — PITER, and Owning Your Pipeline

"Your agentic pipeline is too valuable to outsource to a third party tool… You want to own your agentic pipelines."

AFK Agents are "agents that run while we're away from the keyboard." They need four elements — PITER ("Peter"): Prompt input, Trigger, Environment, Review. Dan's defaults: GitHub issues, GitHub webhooks via a Cloudflared tunnel, a dedicated Mac mini the agent fully controls, and GitHub pull requests.

Why not Codex, Devin, or Jules? Cloud tools "are literally designed for everyone's codebases, not yours." Your templated engineering — /chore, /bug, /feature, /implement — chains into workflows that run your templates on your problems.

PITER. Prompt input, Trigger, Environment, Review — Dan's defaults shown; every slot is swappable.

"A reusable agentic workflow that combines code, agentic prompts, and agents to deliver results autonomously… the synthesis of previous-generation deterministic code and new-generation non-deterministic language models, prompt chains, and now agents."

— the ADW, fully defined. "In the future these will just be known as scripts."

The AI Developer Workflow is the highest leverage point and the highest composition level. And this lesson names something new: the agentic layer — "a net new agentic layer around your codebase" formed by two directories: .claude/commands (prompts) plus adws/ (workflows).

Two supporting patterns: issue classification — an agent classifies each issue as chore/bug/feature and routes to the right template, because "you need to be able to target specific classes of problems" — and the health check, a pre-flight ADW validating env vars, repo access, and Claude Code before any workflow runs.

Issue in, PR out. Fetch → classify → branch → plan → build → PR, "with issue comments as a live feed throughout."

What Dan Did

  1. Ran the end-to-end demo first

    Created GitHub issue "ADW documentation — /chore document the ADW directory, read everything in adws, update README" → webhook fired → the Mac mini agent environment picked it up (screen-shared live) → classified as chore → new branch → planner agent wrote the spec → implementer agent built it → PR posted back. Total: 5 minutes, with live GitHub issue comments the whole way.

  2. Cloned tac-4 locally

    Disabled the webhook, then /install — unsets remote origin, walks you through creating your own repo, copies .env files, installs deps, reports "action required" items.

  3. Set the root .env

    ANTHROPIC_API_KEY and CLAUDE_CODE_PATH via which claude — "the agent SDK currently only runs with the API key."

  4. Filed issue #33: JSONL support

    A mid-level prompt with constraints: stdlib only, concat nested fields, handle arrays, update the UI.

  5. Ran the health check

    uv run adws/health_check.py 33 — verified env, repo, Claude Code, and posted a health comment to the issue.

  6. Ran the ADW with a local trigger

    uv run adws/adw_plan_build.py 33 — unique ADW ID assigned, jsonl-support branch created, classified as feature, /feature planner ran, /implement builder ran, PR created (~17 min).

  7. Walked the ADW code

    classify_issue maps to slash commands; build_plan requests agent name, slash command, args, model; execute fires Claude Code in programmable mode with --dangerously-skip-permissions (safe in its own environment); per-session log files via hooks; per-ADW agent directories — planner, implementer, branch generator, issue classifier, PR creator, committers.

  8. Reviewed and manually tested the PR

    JSONL upload option in the UI, sample data files, comprehensive tests; regression-tested existing queries.

The Workout

GOAL Ship one GitHub issue to PR with zero keyboard time between prompt and review.
PREREQUISITES TAC-3-style templates (/chore, /feature, /implement) · a GitHub repo you own · gh CLI · ANTHROPIC_API_KEY.

You don't fix the issue — you fix the system that caused the issue.

— quote of the lesson. Fix your templates, fix your ADW.

  1. Write the ADW

    adws/adw_plan_build.py (uv single-file script): parse issue number → gh issue view for title/body → agent 1 classifies chore/bug/feature (its own prompt file) → create branch → agent 2 runs the matching template via claude -p "/feature '<issue body>'" --output-format stream-json → agent 3 runs claude -p "/implement <plan path>" → commit → gh pr create. Post gh issue comment progress updates between every step.

  2. Write the health check

    adws/health_check.py — validate env vars, repo remote, and a trivial claude -p "respond OK" call.

  3. File a real chore

    As a GitHub issue; run the health check, then the ADW with the issue number.

  4. Review only the PR

    Do not touch the branch.

  5. Upgrade the trigger

    Add a webhook: expose a tiny listener via cloudflared tunnel or ngrok that runs the ADW on issues.opened.

DONE WHEN An issue you wrote from the GitHub UI (or your phone) results in a merged-quality PR with live issue comments — and you never opened the working branch locally.
LEVEL UP Move the environment off your machine — a spare box, VM, or container that listens for webhooks 24/7 — and run a feature-class issue through it.
