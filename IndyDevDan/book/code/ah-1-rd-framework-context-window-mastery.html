01 · Agent mission

Train one agent to carry one job—and leave evidence behind

This lesson trains you to design a focused, replaceable agent. You give it a single purpose, only the tools and context that purpose requires, a programmable launch surface, and an observable definition of done; the agent plans and acts inside that box, while you remain responsible for scope, risk, acceptance, and recovery.

?

Hook: if an agent says “Done” but no test, diff, hook trace, or terminal report proves it, did the system finish—or did the conversation merely stop?

02 · Picture the actors

The cast of this agent OS

The repo contains several kinds of agency. Some reason, some launch, and some only sense or record. Treating all of them as “the AI” hides the hand-offs you need to debug.

ActorOwnsHands off
Human commander
in loop		Purpose, task boundary, credential exposure, permission level, budget, and acceptance evidence.A bounded prompt or plan; a go/no-go decision after verification.
Primary Claude Code agent
interactive		Reads the active memory and command contract, chooses tools, coordinates workers, and reports to the human.Specs, edits, reports, or a concise failure that the commander can inspect.
Sub-agents
delegated		docs-scraper, research-agent, and meta-agent own isolated research or agent-definition work in separate windows.Saved Markdown or a reduced success/failure report back to the primary agent.
Planner + builder
replaceable		/quick-plan spends context on discovery; a fresh /build agent spends context on faithful implementation.A visible spec, then a diff and git diff --stat.
Background primary
out of loop		A separate claude --print process with its own context, model, settings, keys, and report file.Continuously updated report plus a complete/failed filename state.

Verifier role
human + tools		The commander plus type checks, tests, diffs, bundles, and hook logs decide whether “done” is true.Accept, repair the contract, or restart with a known context bundle.

04 · Worked control loop

Plan → act → verify → recover

The human does not need to steer every tool call. The human does need to choose the mission, define the evidence, and intervene when the run crosses its boundary.

Human stays in the decision loop

Choose one purpose, limit the blast radius, decide what counts as proof, review the plan, and accept or reject the evidence.

Agent leaves the interaction loop

Read the scoped context, use allowed tools, update artifacts, run checks, and report a terminal state without asking for play-by-play approval.

A worked run in this repository

Frame the mission

The commander asks for one tiny wrapper change and declares that a spec, type check, and diff are required evidence.

IN LOOP

Prime the planner

/prime_cc loads the Claude Code layer only because the work concerns agent infrastructure.

OUT OF LOOP

Materialize the plan

/quick-plan "add a tiny helper to apps/cc_ts_wrapper" writes a spec under the ignored specs/ runtime directory.

OUT OF LOOP

Replace the planner

A fresh agent runs /build <path-to-plan>. Replaceability is the test: the spec, not the prior transcript, must carry the hand-off.

OUT OF LOOP

Verify the artifact

The builder reports git diff --stat; inside apps/cc_ts_wrapper/, the real package scripts expose bun run typecheck and bun test.

IN LOOP

Recover at the seam

If the builder must rediscover everything, repair the plan. If context is polluted, /clear and /load_bundle <bundle-file> remount selected state.

IN LOOP
R + D

Name the pattern: Reduce the primary window; Delegate coherent work; pass artifacts instead of transcripts; close every autonomous run with observable evidence.

05 · Why these files exist for agents

Four contracts make the agent programmable

These files are not interesting because they are Markdown, JSON, TypeScript, or shell. They are interesting because each one defines a boundary another actor can inspect.

Prompt contract

.claude/commands/quick-plan.md

The command gives a planner one purpose, one input variable, one output directory, a tool budget, and a report schema.

allowed-tools: Read, Write, Edit, Glob, Grep
description: Creates a concise engineering implementation plan...

# Variables
USER_PROMPT: $ARGUMENTS
PLAN_OUTPUT_DIRECTORY: `specs/`

Small excerpt: role, capabilities, input, and artifact.

Dan’s design intent: let the planner spend discovery context once, then make a fresh builder consume the settled artifact. Understanding is loaded by role, not accumulated forever.

Tool / permission contract

.claude/agents/docs-scraper.md · .mcp.json.firecrawl_7k.sample

The scraper receives only the surfaces required to fetch and save documentation. A strict MCP launch prevents global servers from silently joining the window.

name: docs-scraper
tools: mcp__firecrawl-mcp__firecrawl_scrape, WebFetch, Write, Edit
model: sonnet
claude --mcp-config .mcp.json.firecrawl_7k.sample --strict-mcp-config
Dan’s design intent: capability should follow purpose. Tool schemas consume attention before use; permissions also define the damage a confused agent can cause.

Harness / launcher contract

apps/cc_ts_wrapper/core.ts · .claude/commands/background.md

The SDK wrapper turns Claude Code into a callable function. The background command turns it into a separate process whose primary output is a report file.

for await (const message of query({
  prompt,
  options: {
    maxTurns: mergedSettings.maxTurns,
    customSystemPrompt: mergedSettings.systemPrompt,
    allowedTools: mergedSettings.allowedTools
  }
})) { ... }
claude --model "${MODEL}" --output-format text \
  --dangerously-skip-permissions \
  --append-system-prompt "...update ${REPORT_FILE}..." \
  --print "${USER_PROMPT}"
Dan’s design intent: agents are components you can invoke, parameterize, observe, and replace. The permission-bypass flag is course evidence of autonomy’s cost, not a default safety recommendation.

Verification contract

.claude/settings.json · context_bundle_builder.py · build.md

Hooks record selected lifecycle evidence; the build prompt demands a diff summary. Verification is distributed across the agent, scripts, and commander.

"PostToolUse": [{
  "matcher": "Read|Write",
  "hooks": [{
    "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/context_bundle_builder.py --type file_ops"
  }]
}]
# build.md report contract
Summarize the work ...
Report the files and total lines changed with `git diff --stat`
Dan’s design intent: success should leave inspectable state. A bundle proves reads; a diff proves edits; a test proves behavior; a complete/failed report state lets automation decide what happens next.

Important honesty

This repository demonstrates the contracts, but it does not close every loop. The root CLAUDE.md names absent apps/frontend/ and apps/backend/ paths and root test/lint/build commands that have no matching scripts. The wrapper marks a streamed run successful after iteration unless an exception is thrown, and the raw shell helper has launcher defects. The lesson is to inspect the agent OS—not to trust a file because it is named “settings,” “README,” or “success.”

06 · Operate like Dan

Run the system from the outside in

These commands come from the repository’s README, command prompts, and wrapper README. The sequence keeps the commander at the leverage points and lets agents own the repetitive middle.

Prepare credentials; do not put secrets in prompts

The README says to copy the sample environment and add only the service keys the chosen surface needs.

cp .env.sample .env
# ANTHROPIC_API_KEY is required for Claude API access
# ELEVENLABS_API_KEY and OPENAI_API_KEY are optional utilities

Measure the boot before changing it

Start Claude Code, run /context, and record the tool, MCP, memory, message, and free-space categories. Check external MCP scope too.

claude mcp list
/context

Start with the narrow capability set

The shipped Firecrawl-only sample is the real focused filename. Strict mode prevents user/local MCP servers from contaminating the run.

claude --mcp-config .mcp.json.firecrawl_7k.sample --strict-mcp-config

Load purpose-specific context late

Use the general prime for repository orientation and the composed prime only when the agent is working on Claude Code infrastructure.

/prime
/prime_cc

Separate discovery from implementation

Let the planner write the spec. Then clear or open a fresh agent before giving the builder the plan path.

/quick-plan "add a tiny helper to apps/cc_ts_wrapper"
/clear
/build <path-to-plan>

Verify where the code actually has checks

The wrapper package—not the repository root—declares real typecheck and test scripts. Its generated README says bun run index.ts, but that real file is only a hello placeholder; use this mismatch as an interface audit.

cd apps/cc_ts_wrapper
bun install
bun run typecheck
bun test
bun run index.ts

Reset without discarding selected state

Hooks write bundles under the ignored runtime agents/context_bundles/ directory. A fresh agent can replay the deduplicated reads.

/clear
/load_bundle <bundle-file>

Delegate an independent primary only after the contract is narrow

The README’s form launches a background primary that writes through a report channel. Remember: the command uses your API keys and explicitly bypasses permission prompts.

/background "/quick-plan ..." sonnet report.md

Close the learning loop with an expert triad

Plan, build, then improve. The final agent may update only dedicated ## Expertise sections; a no-op is valid when the diff contains no reusable learning.

/experts:cc_hook_expert:cc_hook_expert_plan "implement session logging..."
/experts:cc_hook_expert:cc_hook_expert_build <path_to_plan>
/experts:cc_hook_expert:cc_hook_expert_improve
07 · Fail the system on purpose

Common agent failures—and which contract to repair

A good operator does not respond to every failure with a smarter model or a longer prompt. Repair the seam that produced the bad state.

Mis-prompting: “do the feature”

No single purpose, artifact, or acceptance evidence exists, so the agent mixes discovery, implementation, and reporting.

Repair: prompt contract → one job, one output, one proof.

Over-permissioned autonomy

--dangerously-skip-permissions plus broad tools turns a vague instruction into a large blast radius.

Repair: tool contract → narrow repo, allowlist, MCP set, and prompt.

Always-on context rot

The concise root memory is small but still names directories and commands absent from this checkout. Short does not mean true.

Repair: memory contract → keep universals current; move observations into primes.

“Done” without verification

The output style minimizes chat, but silence cannot substitute for a test, diff, log, or terminal report.

Repair: verification contract → require durable evidence before acceptance.

Staying in the loop

The human approves every read and watches every tool call, so the agent never becomes programmable leverage.

Repair: harness → move progress into artifacts and reserve human attention for boundaries.

Delegation without a return schema

A sub-agent returns an essay or a background primary writes only at the end; the parent cannot decide or recover.

Repair: report contract → status, artifact path, evidence, blocker, terminal state.

Course-era pins treated as timeless

quick-plan.md pins claude-opus-4-1-20250805; model IDs and token counts are period detail.

Repair: launcher/config → choose an available model, preserve the role and measurements.

Raw shell helper mistaken for the finished harness

bg_claude_code_test.sh assigns both MODEL and REPORT_FILE from $2, requires an unshipped .mcp.json, and does not background the process by itself.

Repair: launcher → fix argument mapping, config path, background lifecycle, and terminal-state naming.

Success flag trusts stream completion

core.ts sets result.success = true after iteration unless an exception occurs; it does not explicitly convert every non-success result subtype into failure.

Repair: verifier → model terminal result subtypes and assert the expected artifact.

Observability becomes a data leak

The universal hook logger stores full lifecycle payloads. Prompts and tool payloads may contain sensitive material even when logs are gitignored.

Repair: evidence contract → redact, retain briefly, restrict access, and log only what recovery needs.

08 · Lab · agent ops

Harden the background-agent launcher—not application logic

The lab changes an agent interface and makes its contract observable. The target is the real scripts/bg_claude_code_test.sh teaching helper.

Mission: make report routing explicit and safe to inspect

  1. Do not run the script yet. It calls Claude at the bottom and uses permission bypass.
  2. Change REPORT_FILE=${2:-...} to read the third argument, because the second argument already belongs to MODEL.
  3. Add a launcher-only dry-run branch controlled by an environment variable. In dry-run mode, print the resolved prompt, model, report path, MCP config, and the exact Claude command without executing it.
  4. Keep the live path available, but make the permission bypass an explicit opt-in environment choice rather than an unconditional flag.
  5. Point the MCP argument at a real shipped sample or require it as an explicit argument; do not silently rely on absent .mcp.json.
  6. Run shell syntax validation and the dry run. Inspect the output as if you were the commander approving launch.
bash -n scripts/bg_claude_code_test.sh
AGENT_DRY_RUN=1 bash scripts/bg_claude_code_test.sh
git diff -- scripts/bg_claude_code_test.sh
Argument proof

The printed report path comes from argument 3; the model still comes from argument 2.

No-spend proof

Dry-run output shows the complete launch command and creates no Claude process or report.

Permission proof

The dangerous bypass is absent by default and appears only after explicit opt-in.

Capability proof

The printed MCP path names a real shipped sample or a commander-supplied path.

Scope proof

git diff changes only the launcher contract; no application behavior moves.

Syntax proof

bash -n exits zero before any live agent is permitted to run.

Why this lab matters

You are not “fixing a bash bug.” You are making the commander-to-agent boundary inspectable: parameters have owners, authority is explicit, capability is scoped, and launch can be verified without spending tokens or granting autonomy.

09 · Teach-back

Explain this agent OS in exactly six sentences

Close the page. Use one sentence for each slot. If you merge two slots, start again.

  1. Name what the human commander owns.
  2. Name what the primary agent owns.
  3. Explain how prompts, memory, and primes control understanding.
  4. Explain how allowlists, MCP, and permissions control capability.
  5. Explain how launchers, specs, and reports make agents programmable and replaceable.
  6. Explain how tests, diffs, hooks, bundles, and terminal states close the loop.

Pass condition

Your listener can point to one place where the commander may leave the interaction loop and one piece of evidence that tells the commander whether to accept, repair, or restart.
