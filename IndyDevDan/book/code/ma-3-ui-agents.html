Infinite UI Agents

The important code is not the generated screen. It is the operating system around the model: one commander interface, bounded roles, reusable workflows, path permissions, persistent memory, deterministic launchers, and a loop that refuses to call work done before it is rendered and checked.

01 · Hook · Agent mission

Train the system that makes UI, not another UI maker

Agent mission

Turn one human intent into a replaceable, multi-team production loop. The commander names the problem class, scope, constraints, budget, and evidence of success; the agent system scaffolds, briefs, generates, validates, repairs, records status, and reports—without making the human drive every worker.

The weak-student mistake is to watch the generated Aegis screens and conclude “the agent writes big Vue files.” The transferable move is one level higher: Dan makes the workflow programmable. A prompt file becomes an operation, front matter becomes a job contract, the justfile becomes an API for humans and meta-agents, schemas define acceptable state, and validators close the loop.

Clone stateAll 12 committed agents use anthropic/claude-sonnet-4-6.
Memory stateAll 12 expertise files begin as one-line stubs and grow at runtime.
Proof stateThe clone ships Aegis plus templates—not the three-brand, mixed-model live demo.

03 · Agent surface map

The repo is an operating surface with code in the middle

The agent does not “touch the repository.” It enters through named interfaces. Each interface either supplies context, grants capability, launches work, receives output, or proves success.

04 · Control loop · one worked run

The human leaves the implementation loop, not the accountability loop

Dan’s leverage comes from moving routine decisions inside a closed loop while keeping mission, authority, cost, and final acceptance outside it.

Out of loop
human
Frame the class“Generate brand-consistent pricing variants,” not “make this div.”
Bound authorityChoose product, count, models, permissions, token budget, and fallback policy.
Name the proofManifest state, files, browser routes, responsiveness, accessibility, brand compliance.
Review the systemAccept evidence, inspect failures, then improve prompts, tools, domains, or checks.
In loop
agents
1 · ParseOrchestrator extracts brand, product, tree, count, brief./generate
2 · ScaffoldSetup creates branch paths, manifest entries, generating state.
3 · BriefBrand loads merged identity; UI lead differentiates variants.
4 · Fan outBranches 1→A, 2→B, 3→C. Workers write independent leaves.
5 · TransitionSetup changes generating to validating.
6 · VerifySoft + hard validators inspect visual, brand, behavior, breakpoints, a11y.
7 · RecoverFAIL returns to the same generation owner with specific fixes, then revalidates.
8 · CloseSetup records validated/failed; Orchestrator synthesizes report.

Bubble out only when: the system needs new authority, credentials, a product decision, or a fallback that would materially change the commander’s risk/cost contract. A routine validation failure stays inside the loop.

Worked run: one command, eight teams

just generate aegis app pricing 3 "Three distinct pricing layouts using Aegis brand tokens"
  1. The launcher pipes a reusable slash-command to teams.
  2. Setup and Brand establish structure and constraints.
  3. Three generation teams own one branch each; three validation teams mirror that ownership.
  4. A failed branch loops back without asking the human to route it.

What counts as done

  • A real pricing entry and three branch statuses in Aegis app trees.yaml.
  • Three non-stub branch index.vue leaves.
  • Rendered routes under /aegis/app/gallery/pricing/….
  • Soft + hard validation evidence, with failed branches visibly repaired or recorded failed.

Name the pattern: a constant-size commander interface around a variable-size closed loop. One brief enters, replaceable specialists fan out, independent verifiers return evidence, and routine failures route back inside the system.

05 · Why these files exist for agents

Four contracts turn a model into an operator

Each contract removes a different kind of guesswork. Prompt says what the workflow means. Permission says what actions are possible. Launcher says how another program calls it. Verification says what observable state closes the job.

Prompt contract

.pi/prompts/multi-team/generate.md

The reusable prompt converts one sentence into named variables, an ordered multi-team workflow, ownership rules, a repair edge, and a report shape.

BRAND: $1   PRODUCT: $2   TREE: $3
COUNT: $4   PROMPT: $5

1. Delegate to Setup: scaffold + status generating
2. Delegate to Brand: prepare brand context
4. Round-robin branches across UI Generation A/B/C
6. Round-robin branches across Validation A/B/C
7. Route failures back to the team that generated them
8. Setup records validated or failed

Dan’s design intent: the workflow is the reusable asset. Adding branches increases machine work, not human conversations.

Tool / permission contract

.pi/multi-team/agents/*.md

Front matter binds each role to a model, memory, skills, tools, and paths. Compare a lead with a product-read-only validator.

# ui-generation-lead.md
tools: [read, write, edit, bash, delegate, tilldone]
domain: apps/infinite-ui/
  read: true   upsert: true   delete: false

# hard-validator.md
tools: [read, bash, grep, find, ls]
domain: apps/infinite-ui/
  read: true   upsert: false  delete: false

Dan’s design intent: leaders route, workers write, validators report. Replaceability comes from changing the model or worker behind the same bounded role.

Audit finding: CLAUDE.md says leads do not write, yet the committed Setup/UI leads retain write-capable tools and product upsert: true. Prompt policy is not the same as enforced permission.

Harness / launcher contract

justfile · .pi/settings.json

just is a stable calling surface for humans or a meta-agent; Pi settings register the workflow directory and manage long-session context.

generate brand product tree count prompt:
  echo "/generate {{brand}} {{product}} {{tree}} {{count}} {{prompt}}" | teams

{
  "thinking": "high", "autoCompact": true,
  "compactThreshold": 0.8,
  "prompts": ["./prompts/multi-team"]
}

Dan’s design intent: an agent system becomes programmable when another process can invoke it, wait for it, inspect it, and compose it. The drive skill adds tmux sessions, sentinels, polling, fan-out, screenshots, process cleanup, and JSON output.

Verification contract

schemas · validators · manifests

Success is a layered claim: schema-valid state, matching filesystem, rendered route, brand compliance, interaction, responsiveness, accessibility, and a final manifest transition.

const BranchStatus = z.enum([
  'draft', 'generating', 'validating',
  'validated', 'failed'
])

# Human-readable deterministic proof
just list-branches aegis app agent-stream
cd apps/infinite-ui && bun run build

Dan’s design intent: the verifier is independent and cannot rewrite the product surface. A branch does not pass because the writer says it looks good; observable gates produce the verdict.

Evidence gap: several committed agent-stream leaves are marked validated while redeclaring raw hex palettes. The loop exists, but its token-compliance gate is not yet strong enough.

06 · Operate like Dan

Run the agent system from the outside

The commands below come from the committed README and justfile. Keep the Vue app and the agent team in separate terminals; talk to the Orchestrator, not the individual workers.

  1. Install and audit prerequisites

    Run this from Claude Code. It checks Pi and the teams alias without blocking browse-only use, then checks Claude Code, Bun, Node, just, uv, the API key, dependencies, team config, prompts, and dev readiness.

    /install

  2. Start the product surface

    The app is one Vite workspace serving all brands, products, trees, branches, and leaves.

    just dev

  3. Start the one commander interface

    This opens multi-team chat with the Pi Orchestrator. Your input surface stays constant even when generation and validation scale to A/B/C teams.

    just team

  4. Create the address before producing leaves

    Inside team chat, follow the real README quick start. Structure is an explicit agent operation, not an incidental side effect.

    /new-brand mybrand /new-product mybrand myproduct

  5. Commission a problem-class run

    Ask for differentiated variants, not three color swaps. The Orchestrator owns fan-out and recovery.

    /generate mybrand myproduct landing 3 "Hero sections with bold typography"

  6. Read the system’s evidence

    Query status deterministically, then browse the gallery. A report without files and a rendered route is not closure.

    /status mybrand myproduct just list-branches mybrand myproduct landing

Commander boundary: stop a run only for new authority, missing credentials, unacceptable cost, destructive scope, or a product decision. A worker error, failed screenshot, schema defect, or branch-specific repair belongs to the in-loop recovery path.

07 · Fail · diagnose the agent OS

Common agent failures—and the interface to repair

When output is bad, do not immediately rewrite the leaf. Ask which agent interface made the failure likely or invisible.

Bootloader missing

Symptom
just team or generation commands cannot start.
Cause
Pi or the teams alias is absent.
Repair
Run /install. Browse-only just dev still works; generation waits for the member multi-team setup.

The human scales with the team

Symptom
You open separate chats for Setup, Brand, three generators, and three validators.
Cause
The Orchestrator is being bypassed.
Repair
Return to just team or a single just generate call. Put routing in prompts and team config.

Policy says “no”; permissions say “yes”

Symptom
A lead writes a complete SFC when its worker fails.
Cause
The prose boundary in CLAUDE.md is not uniformly enforced by tools and domain.
Repair
Choose explicitly: remove write/upsert for strict separation, or document a narrow emergency fallback and verify every use.

Prompt/runtime token drift

Symptom
Generated CSS invents or redeclares colors.
Cause
The Vue Generator prompt demonstrates --color-*, while the app actually injects --brand-* from src/brand/tokens.ts.
Repair
Load the real token mapper into shared context and use the exact runtime vocabulary in prompts and checks.

“Validated” is a false positive

Symptom
timeline-stack and sibling agent-stream leaves are validated yet contain raw hex palettes.
Cause
The quality gate is described but not deterministic enough.
Repair
Add a blocking static token check plus computed-style/browser evidence before the status transition.

Memory appears “missing”

Symptom
The expertise files contain only one comment.
Cause
The clone is the cold-start state; the 7,753-token file was live runtime history.
Repair
Run meaningful tasks, confirm the mental-model skill reads and updates, then validate YAML and line limits.

Status never closes

Symptom
Branches stay generating/validating, or the activity panel keeps polling.
Cause
Final Setup delegation was skipped after pass/fail.
Repair
Make the final manifest transition and activity cleanup a required workflow edge, not a courtesy.

Unlimited meta-agent authority

Symptom
A convenient launcher becomes a blanket permission bypass.
Cause
The real just prime recipe uses --dangerously-skip-permissions.
Repair
Treat it as a trusted-repo power tool, not a default for arbitrary code. Keep the commander responsible for authority boundaries.
08 · Lab · Agent ops

Harden the token contract without touching product code

This lab changes the agent operating system. You will repair the context/prompt/verification seam that lets a leaf be visually plausible while violating the brand-token rule. The gate lives in the Hard Validator role, so both normal /generate runs and standalone /validate runs inherit it.

Part A · Give every team the real token mapper

  1. Open .pi/multi-team/multi-team-config.yaml.
  2. Add the existing apps/infinite-ui/src/brand/tokens.ts to shared_context.
  3. In .pi/multi-team/agents/vue-generator.md, replace the illustrative --color-*/--spacing-*/--motion-* names with the actual --brand-*, --space-unit, --duration-*, and --easing vocabulary that the app injects.

Part B · Make the validator role reject token leakage

  1. Edit the existing .pi/multi-team/agents/hard-validator.md, which the Validation Lead delegates to during both generation and explicit validation.
  2. Add a blocking preflight to its instructions: report any raw six-digit hex inside the target leaf; return FAIL until the generator removes or justifies each occurrence.
  3. Require the validator’s report to include the command, matched file/line evidence, browser route, and final PASS/FAIL.
rg -n '#[0-9A-Fa-f]{6}\b' \
  apps/infinite-ui/src/brands/aegis/products/app/trees/agent-stream/timeline-stack/index.vue

rg -n '#[0-9A-Fa-f]{6}\b' \
  apps/infinite-ui/src/brands/aegis/products/app/trees/dashboard/v1-grid-gauge/index.vue

Pass criteria · observable, not aspirational

Contexttokens.ts appears in shared_context; the agent no longer has to infer token names.
Role contractsThe Vue Generator examples name the app’s real token surface; hard-validator.md contains a blocking raw-hex gate and evidence report.
ProofThe first command finds known leakage in timeline-stack; the second returns no six-digit hex in v1-grid-gauge.

Hard rule

Your diff changes only the three agent-system files above. No index.vue leaf is hand-edited. If you have the full member setup, a later /validate aegis app agent-stream timeline-stack run may route fixes through the agents—that is a separate, in-loop repair run.

09 · Teach-back

Explain this Agent OS in six sentences—without looking

Use exactly one sentence for each card. If you cannot complete one, revisit the interface it names rather than rereading the whole page.

Commander: The human owns…

Boot: just, teams, and Pi settings turn intent into…

Specialization: An agent becomes a real role when front matter binds…

Loop: /generate closes by moving through…

Recovery: A failed worker or branch stays survivable because…

Leverage: Dan builds a problem-class system instead of a one-off output because…

Reveal a model six-sentence answer

The human commander owns the problem class, scope, authority, budget, and evidence of success. The justfile and teams launcher call registered Pi workflows through one Orchestrator interface. Front matter specializes each role with a model, expertise, skills, tools, and path-domain permissions. /generate moves work through Setup, Brand, parallel UI Generation, parallel Validation, repair, and a final manifest transition. Worker and model failures are survivable when ownership is explicit, validators are independent, and failed branches return to their generating team. Dan’s leverage comes from programming this closed, replaceable workflow once so the human’s input does not grow with the number of agents or outputs.
