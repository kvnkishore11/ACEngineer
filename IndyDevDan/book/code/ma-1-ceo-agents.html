The lesson is not “nine prompt files.” It is a programmable boardroom: the human supplies stakes and authority, Pi supplies the operating substrate, a CEO controls specialist compute, and the commander accepts the result only after the promised artifacts exist.

01 · Hook · Agent mission

Train agents to challenge a decision, then leave receipts

This lesson trains you to command strategic compute instead of performing every reasoning move yourself. You frame one consequential question as a validated brief, choose disagreeing specialists, set the time and dollar envelope, then let a CEO agent run the meeting out-of-loop. The system succeeds only when it returns a memo, dissent, next actions, and an audit trail you can inspect—not when the terminal merely sounds confident.

↗

Dan’s leverage move: code is replaceable production. Choosing what deserves production is higher leverage. The human remains commander of intent and acceptance; agents become programmable, replaceable seats around the decision.

04 · Plan → act → verify → recover

The harness returns evidence; the human closes the loop

In-loop work is conversational steering. Out-of-loop work is a programmed meeting that keeps moving without the human supplying every next prompt.

In-loophuman and agent alternate
PlanHuman explains the decision and corrects ambiguity.
ActAgent proposes a framing or next question.
VerifyHuman reads each answer and decides what to ask next.
RecoverHuman repairs every stall manually.
Open loop: confidence ends the work⇄Closed loop: evidence changes the next action
Out-of-loopCEO owns the meeting
PlanValidated brief + roster + envelope become the run contract.
ActCEO broadcasts; board seats answer concurrently; rounds retain state.
VerifyEvery round returns constraint state; closure writes logs and requests the memo.
RecoverBlock invalid briefs, isolate seat errors, reject a missing memo, stop, or revise the OS.

One worked agent run

Contract the uncertainty

The commander chooses .pi/ceo-agents/briefs/2026-03-18-acquisition-offer/. The brief names situation, stakes, constraints, and one key question; two sibling files carry business facts.

receipt · validated headings + context count

Boot the custom harness

just ceo enters apps/ceo, installs dependencies if absent, and loads the Pi extension. /ceo-begin creates a session ID, paths, logs, and seat sessions.

receipt · startup roster + memo path

Fan out disagreement

The CEO calls converse("all", ...). The extension resolves eight targets and launches them with Promise.allSettled; a failed seat becomes an error response instead of collapsing the entire round.

receipt · responses + per-seat cost

Use evidence as control state

The returned constraint block tells the CEO elapsed minutes, dollars spent, warning zones, and whether a configured ceiling was observed at a tool boundary. That state determines another round or closure; an in-flight round can still finish beyond the ceiling.

receipt · constraint_state

Close, then verify the artifacts

end_deliberation gathers final positions, records meeting_end, marks the meeting complete, and instructs the CEO to write memo.md. It does not prove that write succeeded. The commander must verify the memo exists, contains front matter, and agrees with the JSONL record.

receipt · meeting_end first; memo must be checked

The commander still owns

  • Whether the brief is honest and sufficient.
  • Whether the seat biases fit the decision.
  • Whether authority and spend match the stakes.
  • Whether dissent changes the action.
  • Whether to accept, revise, rerun, or stop.

Pattern name: bounded adversarial delegation—one human-owned decision contract, one programmable orchestrator, replaceable specialists, and an evidence-return boundary.

05 · Why these files exist for agents

Four contracts make the board operable

Each file below exists because an agent needs a stable interface. The excerpts are evidence of contracts, not invitations to tour every source line.

Prompt contract · what the seat is allowed to understand

Front matter binds model, persistent expertise, and conditional skills. The body defines objective function, time horizon, risk tolerance, tools, workflow, and report. Runtime placeholders turn one reusable prompt into a session-specific CEO.

Tool / permission contract · what it can do

apps/ceo/TOOLS.md · apps/ceo/extensions/ceo-and-board.ts · apps/ceo/extensions/modules/subprocess.ts

The CEO receives core read, bash, edit, and write tools plus two meeting tools registered by the extension. Board subprocesses keep their core tools but start with extensions, auto-skills, prompt templates, and themes disabled. Skills re-enter only as explicit paths in the role prompt. This narrows auto-loaded surfaces; it is not a sandbox or a tool allowlist, because core bash, edit, and write remain available.

Dan’s design intent: capability should be legible and replaceable. Give the CEO coordination tools and strip ambient agent add-ons from each seat; add an actual allowlist or sandbox when containment is part of the contract.

Harness / launcher · how you call the system

justfile · apps/ceo/.pi/settings.json · apps/ceo/extensions/ceo-and-board.ts

The launcher supplies a single human-scale verb. Pi settings choose theme, default provider/model, thinking, and compaction. The extension registers the tools, replaces the CEO prompt before each agent start, locks arbitrary input, and owns all paths and state.

Dan’s design intent: stop assembling the same meeting by hand. Package the operating prescription so a short command can reproduce your best orchestration.

Verification contract · how you know it succeeded

.pi/ceo-agents/ceo-and-board-configuration.yaml · .pi/ceo-agents/memos/ · runtime conversation.jsonl and tool-use.jsonl

Verification begins before the model: configured required headings block malformed briefs. During the run, cost and time return as tool-boundary control state. After the run, meeting_end proves the meeting closed—not that the memo write succeeded. A human or verifier must confirm the memo, transcript, tool log, front matter, and any optional media form a coherent receipt bundle.

Dan’s design intent: a high-leverage decision deserves more than a polished answer. Preserve the whole path so prompts, seats, budgets, and claims can improve.

Input proof · four required headings found, context files named
Run proof · meeting_start, prompts, responses, costs, meeting_end
Tool proof · agent, timestamp, tool name, trimmed arguments
Output proof · memo exists, front matter parses, roster matches, dissent and actions are present
06 · Operate like Dan

Run the agent system, not a chat session

These are the real root README commands. The commander prepares capability once, then interacts through the deliberately tiny runtime interface.

Provide credentials without committing them

Copy the sample, then put the required provider key into the ignored .env. The extension refuses to boot if the file is absent.

cp .env.sample .env

Install the harness application

The root README uses Bun. The just ceo recipe also installs automatically when node_modules is missing.

cd apps/ceo && bun install && cd ../..

Write or choose a valid brief

Use .pi/ceo-agents/briefs/brief-template.md and its four canonical headings; runtime matching is case-insensitive, and the active YAML controls which headings are required. Put product overviews, financials, terms, or research beside it as Markdown.

Launch the dedicated agent

This loads the extension explicitly; the synthwave theme and model settings come from apps/ceo/.pi/settings.json.

just ceo

Start one deliberation

Inside the Pi TUI, select a brief. The extension validates it, loads context, creates session/log/memo paths, and injects the first message.

/ceo-begin

Observe without steering every move

Watch the roster, member states, TIME/BUDGET gauges, and returned constraint blocks. Type wrap for early synthesis or stop for a hard halt; every other input is intentionally blocked.

Accept from evidence

First confirm memo.md actually exists—the runtime can mark a meeting complete before that write. Then inspect its front matter, dissent, next actions, conversation.jsonl, and tool-use.jsonl. Revise the brief, prompt, roster, or envelope before rerunning.

Preflight

  • pi, Bun, and just installed.
  • .env exists with ANTHROPIC_API_KEY.
  • Optional provider keys exist for multimodel prompts.
  • At least one brief directory contains brief.md.
  • The active YAML points at real role files.
  • The configured editor command exists.

Do not confuse launchers. just ceo runs the decision system. just metacc launches a Claude Code maintainer with --dangerously-skip-permissions; that broader authority is not required to deliberate.

07 · Common agent failures

Most failures live around the model

A good model inside a broken operating contract still produces a broken agent system.

Mis-prompting · vague uncertainty

A generic “What should I do?” starves every seat of facts and forces the CEO to invent structure.

Repair · use the four-section brief and concrete sibling context.
Persona theater · no true conflict

Different titles produce the same cautious recommendation because objective functions and evidence standards overlap.

Repair · sharpen horizon, bias, risk tolerance, red lines, and tension partners.
Over-permission · maintainer flags leak into runtime

Using the metacc permission bypass for ordinary deliberation expands authority without adding decision value.

Repair · launch with just ceo; grant the narrowest capability that closes the loop.
Missing verification · “complete” without a memo

The runtime records meeting_end before the CEO’s memo write, so phase state alone can certify a missing artifact.

Repair · require the memo to exist and parse, then reconcile it with conversation and tool-use logs.
Staying in the loop

The human keeps typing follow-ups and becomes the scheduler again. The runtime blocks this by design.

Repair · improve the brief and agent OS between runs; use only start, wrap, or stop during a meeting.
Provider / context mismatch

Multimodel prompts need the corresponding provider credentials. Non-Markdown sibling files are not loaded as shared context.

Repair · preflight keys and use .md for brief context.
Soft-edged ceilings

Time and budget checks happen at tool boundaries; in-flight fan-out or final statements can complete after a configured maximum.

Repair · keep boundary checks, size the envelope to the decision, and add cancellation if a truly hard ceiling is required.
Stale contract · docs outrun code

The UI and prose say one thing; scheduling or enforcement does another.

Repair · triangulate prompt intent, implementation semantics, and runtime logs.
Three v1 truths to teach precisely

converse launches selected seats concurrently, so same-round cross-pollination is not ordered or guaranteed. end_deliberation also launches final statements concurrently in configuration order, so Contrarian is not serialized last. Its early-close guard checks minimum time, not configured minimum budget. These are implementation facts, not permanent laws of the pattern.

08 · Lab · Agent operations

Change the board OS and prove the runtime obeyed

Change configuration, not application logic. The deterministic experiment removes one seat, runs the same brief, verifies the new roster in two artifacts, then restores the system.

Experiment · make one agent replaceable

  1. Back up .pi/ceo-agents/ceo-and-board-configuration.yaml outside the repository or record its current diff.
  2. Choose one board member. Comment out that member’s complete three-line YAML entry: name, path, and color. Do not leave orphan fields for the simple parser.
  3. Run just ceo, then /ceo-begin, selecting 2026-03-18-acquisition-offer.
  4. Deliberately try to type a normal follow-up once. Observe that the harness blocks it; this names the pattern as one-shot, out-of-loop deliberation.
  5. Let the meeting close. Find the newest conversation.jsonl, then independently confirm the expected memo exists. A missing memo is a failed run even if the phase says complete.
  6. Verify meeting_start.board_members contains seven names and the memo front matter records the same seven-seat board.
  7. Restore the eight-member configuration. Confirm the diff is clean.

Fail → try: if boot still shows eight seats, you edited the multimodel YAML or left the active canonical YAML unchanged. If no meeting starts, inspect the validation notice before blaming the model.

Observable pass criteria

  • The edited path is the real canonical configuration file.
  • Startup / meeting_start shows exactly seven expected seat names.
  • The completed memo front matter shows the same roster.
  • Arbitrary in-meeting input was blocked.
  • A transcript and tool log exist for the run.
  • The canonical eight-seat config is restored afterward.

09 · Teach-back · close the page

Explain this agent OS in six sentences

Do not look back. Fill one idea per sentence; if two prompts collapse into one, your model is still fuzzy.

The human commander owns …
The CEO agent owns …
The board is useful because …
The harness makes the agents capable by …
The loop is closed when …
The highest-leverage IndyDevDan move is …
Reveal one strong six-sentence answer

The human commander owns the decision question, evidence, authority, spend, and final acceptance. The CEO is the primary Pi agent that frames the problem, orchestrates specialist rounds, watches constraints, and synthesizes the memo. The board is valuable because controlled biases make hidden trade-offs and dissent visible. Prompts, context files, tools, persistent sessions, settings, and the extension turn general models into a boundary-aware decision machine. The loop closes only when a human or verifier confirms the memo and logs exist and uses them to accept, repair, or rerun. Dan’s leverage move is to template this judgment workflow so replaceable agents can repeat it while the human moves up to commanding the system.
