Code deep-dive · Issue → agents → pull request

The agent is not the workflow

Dan’s AFK system works because ordinary Python keeps regaining control. It chooses the next bounded agent, checks the returned shape, persists evidence, and stops on error.

  • 23,453 logical lines
  • 8 Claude calls per successful run
  • 13 command templates

Your target: trace one issue number through the controller, name the artifact at every boundary, and explain why “let one agent do everything” is not this architecture.

00 · HOOK

Eight fresh agents finish one chore while the human is away

The checked-in evidence contains a complete run: issue #9 enters at 05:19:07, PR #10 exists at 05:24:57, and run ID 5f2e861e joins every prompt, result, log, commit, and review artifact.

The surprising part

No agent remembers the whole job

The classifier returns only /chore. The branch agent returns only a branch name. The planner writes a plan. The implementer later receives only that plan path. Two commit agents return commit messages. The PR agent returns a URL. Python carries the sequence.

InputGitHub issue JSON
Controladw_plan_build.py
Judgmentfresh Claude CLI processes
Evidenceissue + files + commits + PR

What “AFK” removes

The human courier

You no longer copy issue → planner → implementer → git → PR by hand.

What “AFK” keeps

The human reviewer

The pull request, plan, comments, and raw traces make the result inspectable.

01 · DIAGRAM

Map of the repo: PITER outside, deterministic spine inside

First memorize the perimeter. Then zoom into the controller. The application is the work target; it is not the orchestration engine.

Prompt input

GitHub issue: title, body, number, metadata.

→
Trigger

Webhook, polling cron, or a manual uv run.

→
Environment

Repo checkout, Claude CLI, gh, keys, shell tools.

→
Review

Issue feed, saved plan, commits, raw traces, pull request.

fetch→classify→branch→plan→find plan→commit→implement→commit→PR

Agentic layer

.claude/, adws/, agents/, logs/, scripts/, specs/.

Boundary function

execute_template() turns a slash command plus arguments into one isolated Claude process and one typed response.

Application layer

app/ is the FastAPI + Vite system the agents inspect and change.

Why this design

Non-deterministic reasoning is useful inside a step. Deterministic ownership is useful between steps. Dan combines both: Claude decides within a bounded prompt; Python decides whether the workflow may advance.

03 · WALK THE CODE

Follow control, contracts, then evidence

These are the files that explain the system’s behavior. Open or collapse the walkthroughs as you go.

adws/adw_plan_build.pyThe deterministic spine: order, gates, progress comments, and stop behavior

Purpose. Accept an issue number and optional run ID, then own every transition until a PR URL exists or an error forces an exit.

  1. Load environment, parse arguments, make or reuse an eight-character ADW ID, and create a per-run logger.
  2. Resolve the GitHub remote and fetch a typed GitHubIssue.
  3. Call eight narrow agent roles in a fixed order.
  4. After each call, check_error() posts a failure comment and exits with status 1 if the boundary failed.
  5. Post progress to the issue, leaving the full prompt and stream in agents/{adw_id}/.
controller shapePython
issue_command, error = classify_issue(issue, adw_id, logger)
check_error(error, issue_number, adw_id, "ops", "Error classifying issue", logger)

branch_name, error = git_branch(issue, issue_command, adw_id, logger)
issue_plan_response = build_plan(issue, issue_command, adw_id, logger)
plan_file_path, error = get_plan_file(issue_plan_response.output, adw_id, logger)
commit_msg, error = git_commit(AGENT_PLANNER, issue, issue_command, adw_id, logger)
implement_response = implement_plan(plan_file_path, adw_id, logger)
commit_msg, error = git_commit(AGENT_IMPLEMENTOR, issue, issue_command, adw_id, logger)
pr_url, error = pull_request(branch_name, issue, plan_file_path, adw_id, logger)

Design choice: the controller never asks one session to “keep going.” Each return value is a boundary Python can validate and record.

adws/agent.pyThe execution membrane between typed Python and Claude Code programmable mode

Purpose. Construct the exact prompt, save it, launch Claude, stream every event to JSONL, convert that stream to readable JSON, and return the last result message.

  1. execute_template() joins the slash command and arguments.
  2. save_prompt() persists the exact request before launch.
  3. get_claude_env() builds a small environment allowlist and maps GITHUB_PAT to GH_TOKEN.
  4. prompt_claude_code() runs claude -p with stream-json, verbose output, model selection, and skipped permissions.
  5. parse_jsonl_output() searches backward for the final type: result.
one micro-agent callPython
cmd = [CLAUDE_PATH, "-p", request.prompt]
cmd.extend(["--model", request.model])
cmd.extend(["--output-format", "stream-json"])
cmd.append("--verbose")

if request.dangerously_skip_permissions:
    cmd.append("--dangerously-skip-permissions")

with open(request.output_file, "w") as f:
    result = subprocess.run(cmd, stdout=f, stderr=subprocess.PIPE, text=True, env=env)

Important gap: the code catches TimeoutExpired, but this subprocess.run call supplies no timeout=. The apparent five-minute timeout message is therefore not enforced here.

adws/data_types.pyPydantic contracts for GitHub input, agent requests, and agent results

Purpose. Replace loose dictionaries at the main seams with named shapes. The issue class is restricted to three slash commands; models are restricted to sonnet or opus.

the boundary vocabularyPython
IssueClassSlashCommand = Literal["/chore", "/bug", "/feature"]

class AgentTemplateRequest(BaseModel):
    agent_name: str
    slash_command: SlashCommand
    args: List[str]
    adw_id: str
    model: Literal["sonnet", "opus"] = "sonnet"

class AgentPromptResponse(BaseModel):
    output: str
    success: bool
    session_id: Optional[str] = None

ClaudeCodeResultMessage documents the final stream shape, but the parser currently returns raw dictionaries instead of instantiating that model. The contract exists more strongly on paper than at runtime.

adws/github.pyThe GitHub CLI adapter: remote discovery, issues, comments, labels, and polling data

Purpose. Keep gh subprocess details out of the controller and translate JSON responses into Pydantic models.

  1. get_repo_url() asks git for origin; extract_repo_path() turns HTTPS URLs into owner/repo.
  2. fetch_issue() requests the full issue JSON shape used by the workflow.
  3. make_issue_comment() publishes the compact live feed.
  4. fetch_open_issues() and fetch_issue_comments() support the polling trigger.
  5. mark_issue_in_progress() exists, but the main workflow never calls it.

Why an adapter: the controller can speak in domain verbs—fetch issue, post comment—without knowing CLI flags or authentication environment rules.

adws/trigger_webhook.py · adws/trigger_cron.pyTwo trigger shapes: immediate detached launch and serial polling

Webhook. Accept an opened issue or a newly created comment whose normalized body is exactly adw. Generate the run ID before launch, then use Popen from the project root so GitHub receives an immediate response.

trigger_webhook.pyPython
cmd = ["uv", "run", trigger_script, str(issue_number), adw_id]
process = subprocess.Popen(
    cmd,
    cwd=project_root,
    env=os.environ.copy()
)

Cron. Every 20 seconds, fetch open issues; process issues with no comments or a latest comment exactly equal to adw. Its subprocess.run is blocking, so qualifying issues execute serially. Its processed sets live only in memory.

Boundary warning: the webhook does not validate a GitHub signature or delivery ID. In this course tree, exposure through a public tunnel depends on environmental isolation, not authenticated webhook payloads.

adws/health_check.py · adws/utils.py · adws/README.mdPreflight, trace IDs/logging, and operator documentation

health_check.py checks required environment, git remote, gh authentication, and a live Claude 2+2 round-trip; it can post a compact result to an issue. utils.py creates the eight-character ID and a file-DEBUG/console-INFO logger under agents/{id}/adw_plan_build/.

adws/README.md is useful orientation but not executable truth. It claims automatic retry with exponential backoff, points model selection to a stale line number, and documents a commit shape that differs from .claude/commands/commit.md. Read code when they disagree.

Subtle mismatch: agent.py defaults CLAUDE_CODE_PATH to claude, and the health check treats a missing path as noncritical. The main workflow’s check_env_vars() still requires the variable.

.claude/settings.json · .claude/hooks/Permission policy plus append-only lifecycle capture

settings.json registers PreToolUse, PostToolUse, Notification, Stop, and SubagentStop hooks. Each script reads JSON on stdin and appends it beneath logs/{session_id}/. Stop also copies the JSONL transcript to readable chat.json.

pre_tool_use.py is the only enforcing hook: it blocks dangerous recursive removals and access to live .env files. The other hooks are evidence collectors and deliberately exit cleanly on malformed input.

pre_tool_use.pyPython
if is_env_file_access(tool_name, tool_input):
    print("BLOCKED: Access to .env files containing sensitive data is prohibited", file=sys.stderr)
    sys.exit(2)

if tool_name == "Bash" and is_dangerous_rm_command(command):
    sys.exit(2)

notification.py --notify records notification events but does not perform TTS or any other notification action in this version.

app/server/ · app/client/The ordinary NL→SQL application the agentic layer operates

app/server/server.py wires FastAPI routes for upload, query, schema, insights, health, and table deletion. Core modules convert CSV/JSON with pandas, inspect SQLite, call OpenAI or Anthropic, validate generated SQL, and compute insights. Pydantic contracts mirror app/client/src/types.d.ts.

app/client/src/main.ts owns browser state and DOM events; src/api/client.ts owns typed HTTP calls; vite.config.ts proxies /api to port 8000. The app matters because plans and implementations must navigate a real codebase, but no application module triggers or coordinates an ADW.

Separation of concerns: removing adws/ would leave a manually operable web app. Removing app/ would leave an orchestration shell with no product to change.

specs/Durable planning artifacts and the handoff seam between fresh contexts

Key idea: the plan is not chat memory. It is a named, diffable asset the planner creates, a committer preserves, and a fresh implementer reads.

scripts/Operational helpers for app lifecycle, webhook exposure, and demo cleanup

They exist so an agent can research provider syntax and environment options without depending on conversation memory. Treat model names and API examples as repository-era evidence, not a promise of current provider behavior.

04 · END-TO-END FLOW

How the saved run actually works

Trace run 5f2e861e. The artifacts prove the sequence; no single transcript proves the whole workflow.

  1. Issue #9 is fetched

    github.fetch_issue() turns gh issue view --json … into a typed GitHubIssue. The controller posts “Starting ADW workflow.”

  2. The classifier chooses the plan family

    /classify_issue {issue JSON} runs in session 7ba9… and returns exactly /chore.

  3. The branch agent changes git state

    /generate_branch_name checks out and updates main, creates chore-9-5f2e861e-update-readme-animation, and returns that name.

  4. The planner creates a durable specification

    /chore reads repository context and reports a new plan at specs/readme-animation-framework-update.md. The saved run proves that historical handoff path; the plan is not present in today’s checked-in tree.

  5. A separate agent resolves the path

    /find_plan_file converts the planner’s prose report into the exact relative path the controller needs.

  6. The first commit freezes the plan

    /commit sdlc_planner chore … stages the working tree and returns sdlc_planner: chore: update readme animation framework.

  7. A fresh implementer reads only the plan path

    /implement specs/readme-animation-framework-update.md edits README.md and reports 75 inserted lines. Its hidden reasoning is not handed forward.

  8. The second commit preserves the implementation

    A new committer returns sdlc_implementor: chore: add animation framework documentation.

  9. The PR agent builds the review surface

    It inspects diff and commits, pushes the branch, opens PR #10, and returns its URL. The controller posts completion at 05:24:57.

Control flow versus data flow

Control stays in Python: call, check, comment, advance, or exit. Data crosses as issue JSON, a slash command, branch name, plan path, commit message, implementation report, and PR URL. Prompts and streams are copied to disk as evidence beside that flow.

05 · COMMON FAIL + FIX

Where weak AFK systems fool you

These are visible in the checked-in code and artifacts, not generic warnings.

Fail 1

“The README says it retries”

The controller exits on the first failed boundary. There is no exponential backoff or resume loop. Fix: treat executable code and saved traces as truth; repair drift in docs.

Fail 2

“The timeout will stop a hung agent”

The exception handler exists, but the subprocess has no timeout argument. Fix: wire a real timeout, kill the child safely, and test the failure path.

Fail 3

“The webhook came from GitHub”

The endpoint trusts headers and JSON without verifying a signature. Fix: validate the webhook secret before launching any process.

Fail 4

“No final result still means success”

If JSONL has no result event, agent.py returns the raw stream with success=True. Fix: make a missing result an explicit failure contract.

Fail 5

“Skipped permissions is an agent feature”

It is a host permission decision. Fix: use a disposable checkout without production credentials and keep review as the gate.

Fail 6

“Generated prose must be true”

The saved run documents Motion One without installing it; other course artifacts name plausible files that do not exist. Fix: review claims against the diff and push the rule back into the template.

08 · TEACH-BACK

Explain the system without saying “the agent handles it”

Pass when every vague verb becomes a file, function, artifact, or return contract.

Your 90-second explanation

  1. What turns an opened issue into a background process?
  2. Which file owns step order, and which file owns one Claude invocation?
  3. Why is the plan a better handoff than the planner’s conversation?
  4. Where are the exact prompt, raw stream, readable stream, chat transcript, and controller timeline stored?
  5. What does check_error() do on a failed boundary?
  6. Why are app/ and adws/ separate layers?
  7. What is unsafe about the webhook and skipped-permission configuration?
  8. Which saved artifact proves that a missing environment fails before agent work begins?
Reveal the answer spine

trigger_webhook.py validates the event shape loosely, makes an ADW ID, and launches adw_plan_build.py with Popen. The controller owns order; agent.execute_template() owns one isolated Claude run. The plan is a named, committed artifact that a fresh implementer can read. Exact prompts and streams live under agents/{id}/{agent}/; reconstructed chats and hook events live under logs/{session}/; the controller timeline is agents/{id}/adw_plan_build/execution.log. check_error() logs, comments, and exits. app/ is the target product; adws/ is the operating layer. The webhook lacks signature verification, and skipped permissions require a disposable environment. Run 338dc8a6 proves preflight failure.

Why does the plan finder exist if the planner already reports a path?

It converts free-form planner output and git state into the narrow relative-path contract the controller needs. It is an extra model call because the planner report is not machine-typed.

Why are there two commit agents?

Plan and implementation are separate reviewable checkpoints. Each fresh committer inspects the current diff, creates one commit, and returns the exact message.

What makes the live issue feed insufficient for debugging?

It reports compact milestones. The exact prompt, tool events, raw stream, reconstructed chat, and controller debug log live in the filesystem evidence layers.
