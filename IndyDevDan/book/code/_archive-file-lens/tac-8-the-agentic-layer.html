TAC-8 · Code deep dive

The Agentic Layer

Dan does not hide autonomy inside a clever prompt. He builds a control layer around ordinary applications: prompt contracts, typed decisions, durable state, isolated worktrees, event receipts, and human-visible queues.

Hook

If the model is the engine, where is the car?

A model can write code. It cannot, by itself, decide which task is eligible, prevent two workers taking the same job, create a safe workspace, remember what phase finished, publish evidence, or tell a human what happened.

Dan’s answer: those responsibilities belong to an agentic layer around the application. The model is one replaceable worker inside that layer—not the layer itself.

TAC-8 is best read as five versions of the same idea. Each app keeps the earlier mechanism and adds one missing system property: execution, concurrency, visibility, human task routing, then production delivery and an embedded agent experience.

The application remains ordinary code. The agentic layer decides when, where, and under what contract an agent may change it—and what evidence survives.

The design in plain English

Six moves Dan repeats

01

Prompts are interfaces

Inputs, constraints, output shape, and evidence live in slash-command files.

02

State leaves the chat

Task marks, specs, JSON, SQLite, branches, and state files carry truth.

03

Isolation enables parallelism

Unique worktrees and ports stop concurrent workers sharing a world.

04

Claim before work

Status changes make ownership visible before a long phase begins.

05

Events are product data

Hooks are validated, stored, streamed, filtered, and visualized.

06

Autonomy has levels

Human review, SDLC, and zero-touch merge are separate workflows.

Walk the code · app 1

Start with the smallest useful layer

App 1 needs only an application, slash-command contracts, a programmatic runner, and durable outputs. That turns “ask Claude” into a repeatable workflow.

.claude/commands/*.mdThe stable interface the model must obey.contract

chore.md and feature.md require a plan file and exact returned path. implement.md consumes it. prime.md inspects tracked files; start.md starts both toy apps. The prompts are more structured than the one-line applications because the wrapper is the lesson.

A spec is not the checkout

The specs propose apps/server.py, but it does not exist. The real application files are only apps/main.py and apps/main.ts.

adws/adw_modules/agent.pyCrosses from deterministic Python to probabilistic work.core seam
agent.pylines 590–628
def execute_template(request: AgentTemplateRequest) -> AgentPromptResponse:
    prompt_parts = [request.slash_command]
    prompt_parts.extend(request.args)
    prompt = " ".join(prompt_parts)

    output_dir = os.path.join(
        "agents", request.adw_id, request.agent_name
    )
    output_file = os.path.join(output_dir, "cc_raw_output.jsonl")

    prompt_request = AgentPromptRequest(
        prompt=prompt,
        adw_id=request.adw_id,
        agent_name=request.agent_name,
        model=request.model,
        dangerously_skip_permissions=True,
        output_file=output_file,
        working_dir=request.working_dir,
    )
    return prompt_claude_code_with_retry(prompt_request)
  1. One slash command plus arguments is the agent-facing API.
  2. Every role gets a receipt directory under runtime-created agents/{adw_id}/{agent_name}/.
  3. Stream JSON is saved raw and normalized for debugging.
  4. Typed retry codes separate transient failure from bad input.
High-trust execution

The runner adds --dangerously-skip-permissions. Narrow prompts, working directories, environment allowlists, and receipts help, but the authority remains substantial.

adw_chore_implement.py + CLI/SDK runnersCompose plan → implement and show alternate transports.orchestration

The composed script extracts the planner’s spec path, then starts a builder. adw_prompt.py and adw_slash_command.py are CLI gateways. agent_sdk.py and adw_sdk_prompt.py show tool-enabled, async, interactive, and resumable SDK calls. Transport can change while the prompt contract stays recognizable.

Walk the code · app 2

Add a queue, then earn concurrency

App 2 promotes Markdown into a task state machine. A cron loop groups eligible tasks, claims them, creates sparse worktrees, and launches independent workflows in parallel.

tasks.md + data_models.pyHuman-readable outside; typed invariants inside.state model
MarkMeaningConsequence
[]PendingEligible when the group is unblocked.
[⏰]WaitingRequires successful tasks above.
[🟡, id]In progressClaimed; skip duplicate pickup.
[✅ hash, id]DoneRecords commit and run.
[❌, id]FailedPreserves run and failure note.

Task.is_eligible_for_pickup() and WorktreeTaskGroup.get_eligible_tasks() move rules from prose into Pydantic-backed methods. /process_tasks interprets Markdown; Python validates its JSON before scheduling.

adw_trigger_cron_todone.pyPoll → decide → claim → isolate → launch.scheduler
  1. Precheck.

    A regex avoids an agent call when no pending marks exist.

  2. Structure.

    /process_tasks returns strict JSON grouped by worktree and tag.

  3. Claim.

    /mark_in_progress writes the ADW ID before launch.

  4. Isolate.

    /init_worktree creates a sparse trees/<name>.

  5. Route.

    The tag chooses direct build or plan→implement; Popen runs groups concurrently.

The sentiment directory is the workload agents can change. Its notebook, 499-row dataset, metadata, and lockfile are product context—not scheduler logic.

Move the human out of the loop—but not out of sight

Walk the code · app 4

Make the board a human–agent protocol

App 4 swaps tasks.md for Notion and adds prototype tags. Humans create/review/continue familiar database rows; the layer translates each into a specialized workflow.

NotionTask in data_models.pyEligibility is a domain rule, not a prompt hunch.typed contract

A task is eligible only when status is Not started or HIL Review and the execution trigger is execute or begins with continue. It also carries model preference, workflow tags, page ID, and optional prototype type.

Walk the code · app 5

Production delivery outside; resumable agents inside

App 5 combines a natural-language SQL product, an isolated GitHub-to-PR layer, and an Agent Embedded Application. Separate those boundaries before reading details.

state.py + worktree_ops.pyStop, restart, and find the same isolated world.durable state
state.pylines 34–40
def update(self, **kwargs):
    core_fields = {
        "adw_id", "issue_number", "branch_name", "plan_file",
        "issue_class", "worktree_path", "backend_port",
        "frontend_port", "model_set", "all_adws"
    }
    for key, value in kwargs.items():
        if key in core_fields:
            self.data[key] = value

State validates and writes runtime agents/{adw_id}/adw_state.json. Planning creates trees/{adw_id}/, maps IDs into backend ports 9100–9114 and frontend ports 9200–9214, finds fallbacks, and writes the isolated environment. Later phases load the same pointers.

adw_sdlc_iso.py + adw_sdlc_zte_iso.pyAutonomy level is explicit composition.workflow

Standard SDLC runs plan → build → test → review → document. It warns and continues after test failure but fails fast on plan/build/review/docs. ZTE stops on test/review failure, tolerates docs failure, then invokes adw_ship_iso.py to approve and merge. The risk lives in a separate executable.

workflow_ops.py owns classify/plan/build/branch/commit/PR/patch logic. git_ops.py, github.py, r2_uploader.py, and worktree_ops.py isolate side effects. Cron and webhook translate GitHub activity into named workflows.

adw_trigger_aea_server.py + adw_aea_patch.pyA conversational agent inside the app.AEA boundary
  1. Create.

    POST /aea/new_agent stores a SQLite row and generates a name.

  2. Prompt.

    The server changes idle → working, appends the user message, and starts the patch worker.

  3. Resume.

    The worker adds --resume when cc_session_id exists and saves first-turn IDs.

  4. Poll.

    Each window fingerprints meaningful fields and adapts its interval by state.

  5. Restore/archive.

    Refresh restores non-archived IDs; close terminates work and archives the row.

Two context strategies

Delivery phases hand off artifacts and benefit from fresh judgment. Interactive AEA chat needs dialogue continuity. App 5 starts a fresh OS process per prompt while intentionally resuming the Claude session inside it.

app/server/ + app/client/The ordinary product the layer operates around.application

FastAPI accepts CSV/JSON/JSONL, flattens into SQLite, exposes schema, asks OpenAI or Anthropic for SQL, validates and executes it, generates insights/random queries/data, and exports CSV/JSON. sql_security.py centralizes safeguards; tests cover ingestion, providers, queries, exports, generation, and injection.

The TypeScript client renders product flows. AEADevConsole opens with Cmd/Ctrl+P; window, chat, and polling classes layer draggable agents over the app. The backup database has 20 users and 32 products.

End-to-end flow

How one production-shaped run works

  1. Intent enters GitHub.

    An issue or comment names an adw_* workflow, optional existing ID, and model set.

  2. The trigger returns quickly.

    It validates workflow shape, saves initial state, comments, and launches a background process.

  3. Planning creates an isolated world.

    Class, branch, worktree, ports, dependencies, and real spec path become durable.

  4. Build consumes the artifact.

    A separate phase loads state, validates the tree, implements, commits, pushes, and updates the PR.

  5. Tests create repairable evidence.

    Typed results feed bounded, failure-specific resolver prompts.

  6. Review compares result with promise.

    It uses the spec and isolated ports, classifies severity, patches blockers, and uploads screenshots.

  7. Docs close the loop.
