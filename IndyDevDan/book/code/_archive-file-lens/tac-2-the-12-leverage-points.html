00 · HOOK

The browser knows. The agent does not.

Upload orders_(32).csv. A human can see the SQLite syntax error in the browser, but the committed server prints no handler traceback. Same bug, two radically different observers.

Human path

UI → visible error

The route catches the exception and returns it in FileUploadResponse.error. The client reads that field and paints a red message.

Agent path

Terminal → silence

The same route has no print() or logger call. Unless the agent owns the browser or receives the response, the failure never enters its context.

The architecture lesson

Dan’s app is a leverage laboratory. Each boundary—DOM, fetch, Pydantic, prompt, SQL guard, database, response, test—is a place where information can become clearer or disappear.

Keep this sentence in your head

Files do not “talk to each other.” A running function creates a value, crosses a named boundary, and hands that value to the next function.

The rest of this page names those functions and boundaries. If you get lost, return to the value currently moving: a File, a Pydantic request, a schema dictionary, a SQL string, a result dictionary, or a JSON response.

app/client/src/api/client.tstyped HTTP boundary

Purpose. Centralizes base URL choice, fetch error handling, JSON parsing, request headers, and endpoint return types.

client.ts:8–33one generic transport
async function apiRequest<T>(
  endpoint: string,
  options: RequestInit = {}
): Promise<T> {
  const response = await fetch(`${API_BASE_URL}${endpoint}`, options);

  if (!response.ok) {
    throw new Error(`HTTP error! status: ${response.status}`);
  }

  return response.json();
}

Control flow. Public methods build either FormData or JSON, then delegate to apiRequest<ExpectedResponse>. The generic is a compile-time promise; it does not validate JSON at runtime.

Why this design. UI code says api.processQuery(...) instead of repeating URLs and headers. One seam also makes authentication or richer error parsing easy to add later.

Sharp edge. Table deletion bypasses this wrapper and calls fetch directly in main.ts, so not every endpoint benefits from the same base URL and error behavior.

app/server/server.pyHTTP orchestrator

Purpose. Composes the backend. It loads environment variables, constructs FastAPI, configures CORS, ensures the database directory exists at runtime, and turns six HTTP endpoints into calls to focused core functions.

server.py:86–119query orchestration
@app.post("/api/query", response_model=QueryResponse)
async def process_natural_language_query(request: QueryRequest):
    schema_info = get_database_schema()
    sql = generate_sql(request, schema_info)

    start_time = datetime.now()
    result = execute_sql_safely(sql)
    execution_time = (datetime.now() - start_time).total_seconds() * 1000

    if result['error']:
        raise Exception(result['error'])

    return QueryResponse(
        sql=sql,
        results=result['results'],
        columns=result['columns'],
        row_count=len(result['results']),
        execution_time_ms=execution_time
    )

  • 86–119Query: read schema, route to provider, execute generated SQL, measure database time, shape response.

  • 156–199Insights and health: expose supporting capabilities; the shipped UI does not call them.
  • 201–230Delete: validate identifier, parameterize the existence check, drop the table, return an HTTP-shaped error when needed.

app/server/core/file_processor.pybytes → DataFrame → SQLite

Purpose. Provides parallel CSV and JSON conversion functions. Each produces the same result dictionary: table name, schema, row count, and up to five sample rows.

file_processor.py:12–41CSV happy path
df = pd.read_csv(io.BytesIO(csv_content))

    col.lower().replace(' ', '_').replace('-', '_')
    for col in df.columns

Control flow. Parse bytes → normalize column names → replace the table → introspect SQLite schema → read five sample rows → count all rows → close → return plain data.

Why two explicit functions? Parsing and validation differ. JSON must decode to a non-empty array; CSV delegates shape validation to pandas. After a DataFrame exists, the functions intentionally mirror each other.

The planted failure

The server sanitizes spaces in the uploaded filename but not parentheses. orders_(32).csv becomes table name orders_(32). That name is interpolated unquoted into PRAGMA table_info(...), so SQLite parses the parentheses as syntax.

Test seam. Tests patch sqlite3.connect to return an in-memory connection, then feed real fixture bytes. No web server or disk database is needed.

app/server/core/llm_processor.pyschema + question → SQL

Purpose. Formats schema context, builds provider-specific API calls, strips accidental Markdown fences, and routes to OpenAI or Anthropic based on available keys.

llm_processor.py:121–157shared prompt context + routing
def format_schema_for_prompt(schema_info):
    lines = []
    for table_name, table_info in schema_info.get('tables', {}).items():
        lines.append(f"Table: {table_name}")
        lines.append("Columns:")
        for col_name, col_type in table_info['columns'].items():
            lines.append(f"  - {col_name} ({col_type})")
        lines.append(f"Row count: {table_info['row_count']}")
    return "\n".join(lines)

def generate_sql(request, schema_info):
    if os.environ.get("OPENAI_API_KEY"):
        return generate_sql_with_openai(request.query, schema_info)
    elif os.environ.get("ANTHROPIC_API_KEY"):
        return generate_sql_with_anthropic(request.query, schema_info)
    # otherwise call the requested provider, which produces a clear key error

Why this design. Provider adapters share the same schema formatter and near-identical prompt rules. Tests mock SDK clients, so they verify model names, temperature, token limit, cleanup, errors, and routing without network calls.

Read the priority literally. If both keys exist, OpenAI wins even when the request says anthropic. If only the Anthropic key exists, Anthropic wins even when the request says openai. Request preference is reached only when neither key is found.

app/server/core/sql_processor.pyschema reader · guarded executor

Purpose. Owns the two database read paths used by querying: inspect every table’s columns/count, and execute a generated statement after a simple keyword blocklist.

sql_processor.py:11–52execute and normalize

            'results': [],

Why sqlite3.Row matters. It preserves column names, allowing each row to become a JSON-ready dictionary without hand-zipping columns and values.

Beginner trap. “Safely” is the course function name, not a production security proof. Substring blocking can reject innocent text, and it is not equivalent to parsing SQL or enforcing a read-only database connection.

Contract quirk. A valid query with zero rows returns both results: [] and columns: []; the test suite explicitly locks in that behavior.

04 · END-TO-END FLOW

How a run actually works

There are two coupled pipelines. Upload creates queryable state. Query reads that state twice: once as prompt context and once as the database to execute against.

Phase A · startup and upload

1
The shell establishes two working directories.

start.sh launches Python from app/server and Vite from app/client. That makes relative database and asset paths line up.

2
The browser bootstraps on DOM ready.

main.ts attaches handlers and immediately calls GET /api/schema so the UI reflects persistent tables.

3
A user or sample button produces a File.

Browse, drop, and sample fetch all converge on handleFileUpload(file).

4
The API wrapper sends multipart form data.

api.uploadFile appends the file under field name file and posts it to /api/upload.

5
FastAPI delegates by suffix.

The route reads bytes and calls either convert_csv_to_sqlite or convert_json_to_sqlite.

6
Pandas and SQLite create queryable state.

The converter builds a DataFrame, normalizes column names, replaces a table, introspects its schema, samples rows, and counts records.

7
The client closes the loop.

A typed upload response produces success or error UI. On success, the client fetches the schema again instead of guessing how the server stored the table.

Phase B · natural language query

1
The query button freezes its own transition.

It reads trimmed text, disables itself, shows a spinner, and sends { query, llm_provider: "openai" }.

2
Pydantic validates the request.

QueryRequest constrains the provider to two literal values and gives OpenAI as the default.

3
The server turns the database into model context.

get_database_schema returns table names, columns, types, and row counts. format_schema_for_prompt turns that structure into readable text.

4
Provider routing creates one SQL string.

The selected SDK receives the schema, user question, SQLite rules, low temperature, and a demand for SQL-only output. Fence cleanup normalizes the reply.

5
The guard checks, then SQLite executes.

execute_sql_safely blocks listed substrings, uses named rows, fetches all results, and returns dictionaries plus column names.

6
The response becomes DOM.

displayResults exposes the original question and SQL, then createResultsTable creates headers and cells using the response’s explicit column order.

The leverage chain

Context makes SQL generation possible. Types make the crossings traceable. Architecture narrows the search. Tests validate local pieces. Stdout should expose runtime truth—but in the committed version, that link is intentionally weak.

05 · COMMON FAIL

Seven ways to misunderstand this code

These are not reasons to dismiss the MVP. They are the pressure points that teach where a production version would deepen the design.

MisreadWhat the code actually doesBetter mental model
“The filename is sanitized.”Only lowercasing and space replacement happen at the route; column names replace spaces and hyphens. Parentheses survive.Normalization is a declared policy. List allowed characters and test the boundary.
“Only SELECT can execute.”The executor blocks ten substrings. It does not parse SQL or explicitly require a SELECT statement.A blocklist is a coarse guardrail, not a SQL sandbox.
“TypeScript validates the response.”apiRequest<T> casts the developer’s expectation at compile time; response.json() is not runtime-checked.Static type and runtime validation are separate leverage points.
“The requested provider wins.”Existing environment keys determine priority: OpenAI first, Anthropic second. The request preference is the final fallback.Name routing policy from code, not from the request field alone.
“All endpoint errors are HTTP errors.”Most routes return a typed 200 response with an error field; delete raises HTTP exceptions. The client handles both patterns differently.Error shape is part of the API contract and should be consistent.
“All rendered text is escaped.”Result cells use textContent; query and SQL metadata use template-string innerHTML.Audit the DOM sink, not just the source value.
“The spec is the source tree.”The plan proposes more components and utilities than the shipped flat MVP contains.Plans communicate intent; the checked-in tree and tests describe reality.

The most common student mistake

Jumping straight into file_processor.py and patching punctuation treats the symptom. Dan’s sequence first improves what the running system communicates, then asks the agent to diagnose, then adds a regression loop. The code change is smaller than the systems lesson.

  2. Where does a DataFrame become persistent queryable state?
  3. How does the current SQLite schema enter the LLM prompt?
  4. Which function chooses the provider, and what actually determines priority?
  5. Where is generated SQL checked, executed, and converted to JSON-ready rows?
  6. Why can the browser observe the planted failure while a terminal-only agent cannot?

  8. Which of the twelve leverage points are strong in the checked-in repo, and which is intentionally weak?
Reveal the answer spine

handleFileUpload sends multipart data; FastAPI’s upload_file awaits file.read(); the converter calls DataFrame.to_sql; get_database_schema feeds format_schema_for_prompt; generate_sql uses key-first routing; execute_sql_safely checks and executes; sqlite3.Row enables row dictionaries; route exceptions become response error fields but no stdout; SQLite is real and in-memory in processor tests while provider SDKs are mocked. Types, docs, architecture, tests, plan, and templates are strong; runtime stdout is the designed gap; ADWs are only a placeholder.

Why does the client fetch schema after upload instead of appending a table card from the upload response?

Reveal answer

The server and SQLite remain the source of truth. Refetching handles replacement semantics and gives the UI the complete current catalog in one normalized response shape.

Why is DatabaseSchemaResponse a better navigation handle than searching for “schema”?

Reveal answer

It is a precise cross-language identifier. The same name reaches the Pydantic contract, TypeScript contract, API return type, and consuming flow with far less noise.

What makes the tests agent-friendly?

Reveal answer

They are local, deterministic, mirrored to the core modules, use small meaningful fixtures, avoid network calls, and produce narrow failures tied to named behaviors.
