Hello Agentic Coding

Do not tour the seven files as code. Read them as a tiny operating system for one agent: intent enters through a prompt, authority enters through settings, execution enters through a launcher, and trust enters through returned evidence.

01 · Who acts?

The cast is smaller than the hype

TAC-1 has one actual agent. The human, launcher, and verification commands surround it with direction, placement, and judgment. Naming those roles correctly is the first systems skill.

Commander · human

Chooses the mission and owns the risk

Audits permissions, selects the interactive or headless path, establishes clean Git state, reviews traces and diffs, and decides whether the evidence is good enough.

Worker · Claude Code CLI

Plans and carries the tool chain

Interprets the runbook, reads and writes files, invokes UV and Git through allowed tools, observes results, preserves progress, and returns a report.

Placement · launcher script

Calls the agent; it is not the agent

Shell, Python, and TypeScript read the same prompt and invoke claude -p. They decide where the worker can be fired and how output or failure reaches the caller.

Judgment · verifier role

Checks claims against repository reality

The agent runs the programs, but TAC-1 has no separate verifier agent. The human independently checks branch, outputs, and commit. Verification is a role here, not a file.

RoleWhat exists in this lessonSystem consequence
SubagentsNone declaredOne serial worker carries the whole prompt; parallel delegation is outside this lesson.
HooksNone in tac/tac-1No automatic pre-tool gate or post-tool check exists beyond the settings allowlist.
SkillsNone in tac/tac-1Reusable behavior lives in a raw prompt.md, discovered and launched manually.
Memory fileNo lesson-local CLAUDE.mdWorking context comes from the prompt, current repo state, and files the agent reads during the run.
Dan’s leverage move: make every supporting role replaceable. The prompt can change without rewriting the launcher; the launcher language can change without rewriting the workflow; the agent product can eventually change if another runtime satisfies the same contracts.

03 · Control loop

Plan → act → observe → return → recover

The same inner agent loop runs in two placements. Interactive mode keeps the commander beside the run. claude -p moves the commander outside the execution path and makes the report the hand-off boundary.

Human decisionAgent-internal moveEvidence and recovery path

In-loop move

The commander starts claude, pastes the README prompt, watches the checklist, and can answer or redirect. Good for learning the trace; expensive as a permanent operating model.

Out-of-loop move

A launcher reads prompt.md, calls claude -p, waits, and returns output. The human is absent during execution, so starting state, permissions, evidence, and process status matter more.

Do not overstate the closure

TAC-1 has an observable loop, not a fully self-healing one. The agent runs the files and REPORT returns their outputs, but no separate verifier automatically compares claims to reality or repairs a mismatch. The human closes that outer loop.

04 · Why these files exist for agents

Four contracts make the worker operable

The code is evidence here, not the subject. Each snippet proves one system contract: understanding, authority, invocation, or trust.

1

Prompt contract

What the agent must understand and carry

The shared prompt is a compact workflow specification. Its headings expose state transitions instead of hiding them in prose. The headless variant creates both runtime files, so it does not depend on the earlier interactive demo, and REPORT declares what must cross back to the caller.

Dan’s design intentTurn a prompt from a text request into a repeatable unit of engineering work. The important artifact is the action sequence, not the two print statements.
programmable/prompt.mdworkflow evidence
RUN:
    checkout a new/existing "demo-agentic-coding" git branch

⋮ CREATE blocks omitted here ⋮

RUN:
    uv run main_aic.py
    uv run main_tac.py
    git add .
    git commit -m "Demo agentic coding capabilities"

REPORT:
    respond with the exact output of both .py files
2

Tool and permission contract

What the agent can actually do

The allowlist predicts the reachable workflow before the run begins. File tools permit inspection and change; UV turns code into observed behavior; the four Git patterns isolate and record the result. git push is absent. WebSearch is allowed, although this prompt does not require it.

Dan’s design intentRead settings before letting the worker loose. A perfect prompt cannot cross a missing permission, and a broad permission is still authority you must be prepared to defend.
.claude/settings.jsonauthority evidence
{ "permissions": { "allow": [
  "Read", "Write", "Edit",
  "Bash(uv run:*)",
  "Bash(git checkout:*)",
  "Bash(git branch:*)",
  "Bash(git add:*)",
  "Bash(git commit:*)",
  "WebSearch"
] } }
3

Harness and launcher contract

How a larger system calls the agent

All three launchers share one shape: read the prompt, invoke the terminal agent, return output. That tiny seam is the lesson’s systems breakthrough. It relocates the worker from an app you visit to a component a program can call.

The wrappers differ at the failure boundary: Python prints stderr and propagates Claude’s return code; Bun catches failure and exits 1; the minimal Shell wrapper echoes stdout but its final echo can hide the child’s non-zero status.

Dan’s design intentMake host language replaceable. The workflow belongs to prompt.md; Shell, Python, and TypeScript are interchangeable placements around the same agent.
programmable/programmable.shinvocation evidence
PROMPT_CONTENT="$(cat programmable/prompt.md)"
OUTPUT="$(claude -p "$PROMPT_CONTENT")"
echo "$OUTPUT"
4

Verification contract

How you know the agent succeeded

REPORT makes the invisible run legible, but report-back is still a claim. The commander checks the claim against independent observations: current branch, actual program outputs, and the most recent commit subject.

Dan’s design intentClose the first observability loop. Headless work must return something a person—or later, another program—can inspect. Trust grows from evidence, not from a confident completion sentence.
$ git branch --show-current
$ uv run main_aic.py
$ uv run main_tac.py
$ git log --oneline -1

Course-era seam, modern destination

The lesson extracts flag three evolutions: raw prompt files can now be packaged as skills; bare claude -p can grow into richer headless or SDK integration; flat allowlists can grow into modes, hooks, and sandboxing. Keep TAC-1’s primitive visible first: behavior, authority, placement, evidence.

05 · Operate like Dan

Run the system, then inspect the wake

The weak-student path is intentionally concrete: see one small workflow, run it interactively, remove yourself from the execution path, then prove what changed.

  1. Enter the lesson root and audit authority.

    Work from tac/tac-1. Read .claude/settings.json before starting. The launchers use relative paths, so the current working directory is part of the harness contract.

  2. Run the interactive A/B.

    Start claude. Paste the README’s small AI Coding Prompt, then its Agentic Coding Prompt. Compare transitions—not just final files: branch, creation, execution, staging, commit, and report.

  3. Reset to a known starting state.

    For a clean reproduction, return to main and remove demo-agentic-coding. Starting state is input. An existing branch is valid under “new/existing,” but it makes the rerun harder to reason about.

  4. Fire one launcher with no mid-run relay.

    Choose any real README command below. Watch the repository change while the host program waits for claude -p to return.

  5. Verify outside the agent’s story.

    Compare REPORT with real program output, current branch, and commit history. If a claim fails, change the agent system—prompt, permission, starting state, or launcher error handling—then rerun.

Exact programmable commands from README.md

Shell

Smallest proof of the invocation seam.

sh programmable/programmable.sh

Bun + TypeScript

Same worker, a different host runtime.

bun run programmable/programmable.ts

UV + Python

The most explicit stdout, stderr, and status handling.

uv run python programmable/programmable.py

Pattern name

Programmable agentic coding: a program supplies a workflow prompt to a bounded agent and receives evidence back. The three languages prove replaceability; the shared prompt and runtime carry the semantics.

06 · Common agent failures

When the Agent OS is wrong, better code generation does not save it

Diagnose the surrounding system before blaming intelligence. Most TAC-1 failures are contract mismatches at a boundary.

FailureWhat is misconfiguredRecovery move
Prompt too smallThe request describes an artifact but not the branch, execution, commit, or evidence path.Rewrite it as ordered state transitions with an explicit REPORT.
Missing permissionThe prompt asks for a transition—such as commit—that the allowlist cannot authorize.Inspect settings, decide whether that authority is justified, change deliberately, and rerun.
Over-permissionThe worker receives actions unrelated to the mission. WebSearch, for example, is allowed here but unnecessary for the demo.For production, grant only the smallest tool surface that carries the verified chain.
State driftThe demo branch already exists or the launcher begins from the wrong branch.Declare and verify starting state; reset comparable runs from main.
Wrong working directoryThe launcher cannot resolve programmable/prompt.md because its path is relative.Run from the lesson root or make path resolution explicit in a future harness.
Report worshipA fluent completion message is treated as proof even though no independent check agrees with it.Compare returned claims with UV output, branch state, Git history, and exit status.
Hidden process failureThe minimal Shell wrapper ends with echo, which can obscure Claude’s failing status.Prefer explicit status propagation like the Python launcher when another system depends on success/failure.
Human stays in-loopThe operator keeps pasting, rescuing, or hand-editing, so the workflow never becomes callable.Run the headless launcher hands-off; return only at the evidence boundary.
Imaginary architectureThe operator assumes subagents, hooks, a skill, or a verifier exist because modern agent systems often have them.Design from the real repo: one serial agent, one allowlist, one shared prompt, three callers, human verification.

Core Four debugging scan

Ask, in order: Context—did it see the right state? Model—could it reason through the exception? Prompt—was the transition and check explicit? Tools—did the required action exist and have permission?

07 · Lab · Agent ops

Change the Agent OS, not the toy application

The lab changes the report contract, fires the real headless harness, and grades externally visible evidence. The two generated print programs remain deliberately boring.

Lab 1A · Add branch identity to REPORT

  1. From the TAC-1 lesson root, start Claude Code. Do not edit files directly.
  2. Ask the agent to change programmable/prompt.md so REPORT still includes the exact output of both Python files and also includes the current Git branch name.
  3. Review the prompt diff. Confirm the existing branch, create, run, add, and commit instructions are unchanged.
  4. Return to main and remove the existing demo-agentic-coding branch so the run begins cleanly.
  5. Run uv run python programmable/programmable.py with no mid-run interaction.
  6. Compare the report’s branch with git branch --show-current, then compare both reported outputs with independent UV runs.

Observable pass criteria

  • The prompt still requires both exact outputs.
  • REPORT includes demo-agentic-coding.
  • The branch claim matches Git reality.
  • Both output claims match independent execution.
  • The required commit exists.
  • The Python launcher exits successfully.
  • No application code was typed by hand.

Optional failure injection

Through Claude Code, temporarily remove Bash(git commit:*), rerun, and record the exact blocked transition. Restore the permission before finishing. Pass only if you explain why prompt correctness could not overcome the tool boundary.

08 · Teach-back

Explain the Agent OS in exactly six sentences

Close the page first. One sentence per boundary; no definitions by slogan.

State what the human commander owns.

Name the only actual agent and distinguish it from the launchers.

Explain where intent and working context enter.

Explain how authority is bounded.

Explain what claude -p changes about placement.

Close with evidence, recovery, and rerun.

Reveal one six-sentence model answer
  1. The human commander chooses the outcome, audits authority, starts the run, and judges the evidence.
  2. Claude Code is the only actual agent in TAC-1; the three scripts merely call it.
  3. README.md or programmable/prompt.md supplies a workflow-shaped prompt, while repository state supplies working context.
  4. .claude/settings.json bounds what the agent can do with files, UV, Git, and WebSearch.
  5. A launcher turns that prompt into an out-of-loop call by passing it to claude -p.
  6. The agent plans, acts, observes, commits, and reports, after which the human verifies and repairs the prompt, permissions, or starting state before rerunning.

Mastery test

Pass if a listener can draw the surface map from your six sentences and can predict what happens when Bash(git commit:*) disappears.

09 · Optional appendix

Raw file index for the curious

Seven real files, one line each. This is an index, not the teaching lens.

Open the seven-file index
  • README.md — interactive A/B prompts, the three real launcher commands, and the pointer to enabled tools.
  • .claude/settings.json — project permission allowlist for file, UV, Git, and WebSearch actions.
  • .env.sample — an empty ANTHROPIC_API_KEY placeholder; none of the three launchers loads it explicitly.
  • programmable/prompt.md — the self-contained headless workflow and REPORT contract shared by every launcher.
  • programmable/programmable.sh — minimal Shell reader → claude -p → stdout wrapper.
  • programmable/programmable.py — Python wrapper with stdout/stderr capture, exception handling, and return-code propagation.
  • programmable/programmable.ts — Bun TypeScript wrapper using the same shared prompt and a simple failure exit.
Generated during a run, not committed source: the prompt creates main_aic.py, main_tac.py, the demo-agentic-coding branch, and the named Git commit. They are outputs of the Agent OS, not additional interfaces in the starting repository.
