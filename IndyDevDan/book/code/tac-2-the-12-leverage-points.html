Agent Systems Companion · TAC-2

The 12 Leverage Points

The application is the worksite. The lesson is the operating system that lets an agent enter it, see it, change it, and prove the change.

  • Lens · agent systems
  • Core four · context, model, prompt, tools
  • Loop · plan → act → verify → recover

Agent mission

Train a human commander to turn a brilliant-but-blind coding agent into a reliable operator by designing its starting context, prompt, permissions, runtime harness, and returned evidence.

Success test: a fresh agent can orient, run, observe, repair, and verify without the human becoming its memory, terminal, or test runner.

Browser knows Agent does not The planted CSV error is visible to the UI user but absent from detailed server stdout. The first repair is to the information path, not the model.

01

Cast the system before you cast the code

Several kinds of intelligence appear in TAC-2. Only one is the coding agent, and several expected agent layers do not ship at all.

ActorWhat it ownsWhat it must not silently own
Human commander Outcome, safety boundary, repository choice, review judgment, and the decision to increase autonomy. Relaying every error, typing the repair, running every check, or carrying hidden state between fresh sessions.
Claude Code / CLI agent Prime itself, inspect files, use permitted tools, run the app, read stdout, edit, test, and return evidence. Assuming it can see a browser or outside terminal, inventing repository guides, or declaring success without a check.
Fresh-session verifier Re-enter with zero conversational memory and independently trace a contract such as DatabaseSchemaResponse. Pretending to be a separately configured verifier agent. In TAC-2 this is a role played by another fresh CLI session.
Shell harness scripts/start.sh launches both services, checks startup, prints endpoints, waits, and traps shutdown. Reasoning. It is deterministic orchestration around the agent, not an autonomous agent itself.
Application LLM OpenAI or Anthropic converts a natural-language data question into SQL inside the demo application. Editing the repository. The app’s provider model and the coding agent are different systems.
Not shipped agents/, adws/, and trees/ are empty scaffolds with README placeholders. No committed subagent definitions, verifier configuration, hooks, skills, CLAUDE.md, or Claude launcher should be inferred.

Name the pattern

Replaceability is a design property. Dan can open a fresh agent because the operating knowledge lives in repository interfaces—README, command prompts, settings, types, tests, and scripts—rather than only in one long conversation.

A useful repository map shows where information enters the agent, where capability is granted, and where evidence comes back.

03

Close the loop where the agent can see it

A human-readable error is only a fact. It becomes leverage when the acting agent can observe it, compare it with a check, and choose the next move.

In-loop: the human is middleware

  • Human watches the browser and outside terminal.
  • Human pastes the error into chat.
  • Human types or steers each repair.
  • Human runs tests and reports the result.

Out-of-loop: the system returns evidence

  • Agent owns the long-lived process in its tool context.
  • Runtime details arrive through stdout.
  • Agent diagnoses and edits from its own observations.
  • Agent runs focused and full checks before handoff.

Dan’s design intent

Presence falls only when evidence stays high. “Out of the loop” does not mean “unable to inspect”; it means the commander reviews returned proof instead of continuously operating the workflow.

04

Why these files exist for agents

The key files are not trivia. Each one defines a contract between the human, the agent, and the environment.

01 · Prompt contract

Give a fresh session a repeatable beginning

/prime says what to execute, what to read, and what to return. It is deliberately small: tracked files plus the README, then a summary.

# Prime
> Execute the following sections to understand the codebase then summarize your understanding.

## Run
git ls-files

## Read
README.md

Dan’s design intent

Move cold-start memory into the repository so replacement sessions can orient without inheriting a private conversation.

02 · Tool / permission contract

Capability is policy plus interface

The settings auto-allow selected command families and writes, while explicitly denying force-push forms and recursive force removal.

{
  "allow": ["Bash(uv:*)", "Bash(npm:*)", "Write"],
  "deny": ["Bash(git push --force:*)", "Bash(rm -rf:*)"]
}

Dan’s design intent

Make the safety boundary executable. Also audit the gap: /prime asks for git ls-files, and the launcher uses sh, but neither family appears in the automatic allow list.

03 · Harness / launcher

Collapse two services into one observable process

scripts/start.sh checks for app/server/.env, starts FastAPI and Vite, checks both child PIDs, prints the three useful URLs, traps exit signals, and waits.

uv run python server.py &
BACKEND_PID=$!

npm run dev &
FRONTEND_PID=$!

trap cleanup EXIT INT TERM

Dan’s design intent

Give either human or agent one stable entry point. Important distinction: this script launches the application, not Claude. The lesson’s programmable agent seed is the external CLI call claude -p "/tools".

04 · Verification contract

Return proof in text

Backend tests mirror the core modules. The frontend build combines strict TypeScript checking with Vite. Health and schema routes provide deterministic runtime observations.

cd app/server && uv run pytest cd app/client && npm run build curl http://localhost:8000/api/health curl http://localhost:8000/api/schema

Dan’s design intent

A claim of success should be replaceable by observations another session can inspect. The deterministic upload/schema/test path does not require a live LLM key.

Repository truth over convention. TAC-2 has no CLAUDE.md, no hooks, no skills directory, and no committed .claude/commands/start.md. README plus /prime perform the cold-start role; start.md is a student-created lesson artifact after the action repeats.
05

One worked agent run: make blindness debuggable

Follow the ownership handoffs. The application bug matters because it exposes exactly where the agent system loses information.

1Human

State outcome and no-relay rule

Ask for an independently observed diagnosis and verified repair. Do not paste the browser error or type the application fix.

2Agent

Prime from repository truth

Run /prime. Inspect README, tracked files, commands, settings, the long specification, types, and nearby tests as needed.

3Boundary

Install observability first

The committed handlers return error strings but do not print detailed success/failure traces. Have the agent instrument stdout before asking it to solve the planted defect.

4Agent

Own the runtime

Run sh ./scripts/start.sh with a 300-second Bash tool timeout. The timeout is a tool-call property, not an argument understood by the shell script.

5Human trigger

Produce the event once

Upload app/client/public/sample-data/orders_(32).csv. The human causes the event; the agent must receive its consequence through owned stdout.

6Agent

Diagnose from its own trace

The expected chain is filename → table name orders_(32) → pandas table creation → unquoted PRAGMA table_info(...) failure.

7Agent

Repair and create feedback

Use the lesson prompt resolve: replace bad chars and escape. Require focused sanitizer cases and the full backend suite.

8Agent → Human

Return the proof bundle

Hand back the diff, focused and full test output, valid table identifier, and schema evidence showing 32 rows and 7 columns.

Name the pattern

System-first debugging: repair the observation path, keep the model constant, and rerun the same failure. If the same agent now diagnoses it, the added leverage—not magical reasoning—explains the improvement.

06

Operate like Dan

Use the repository’s real commands. Keep application setup, agent invocation, and verification as three separate layers.

1 · Install the worksite

The README’s manual path is explicit and uses the lock-aware package managers already chosen by the repo.

cd app/server && uv sync --all-extras cd app/client && npm install

2 · Configure the boundary

The launcher refuses to start without app/server/.env. Copy the sample, then add keys locally only if you need the optional natural-language query.

cd app/server cp .env.sample .env

3 · Launch through one harness

Run from repository root. Success prints frontend, backend, and API-doc URLs; Ctrl+C triggers graceful child cleanup.

./scripts/start.sh

4 · Give the process to the agent

After stdout is useful, run the same harness inside the agent. Configure the Bash tool timeout separately so the process remains observable long enough for the event.

sh ./scripts/start.sh

5 · Verify both halves

Tests prove backend behavior; the production build proves strict TypeScript plus bundling. Ask the agent to return both outputs.

cd app/server && uv run pytest cd app/client && npm run build

6 · Call a prompt programmatically

This course demonstration is outside the README and outside the repo’s scripts. It invokes the Claude CLI in print mode, runs the committed /tools prompt, then returns control to the shell.

claude -p "/tools"

Do not conflate the layers

start.sh is an application launcher. claude -p is an agent launcher. A full ADW would still need wrapper code that composes prompt calls plus an autonomous trigger; TAC-2 does not commit that layer.

07

Common agent-system failures

When a run misses, diagnose the operating system before switching models or adding a paragraph of pleading.

Mis-prompting an impossible task

“Any issues with the server?” cannot work when the process lives outside the agent and emits no detailed trace.

Recover: move the runtime and its evidence into the tool context.

Permission drift

/prime asks for git ls-files and the lesson uses sh, but the settings auto-allow list does not name those command families.

Recover: audit required transitions and narrowly approve or explicitly supervise the missing ones.

Over-permission

scripts/stop_apps.sh uses kill -9; the deny list blocks recursive removal and force push, not every destructive shell effect.

Recover: treat the allow/deny file as a policy artifact to review, not a complete safety proof.

Missing verify

An edited file plus a confident summary is not a closed loop. The agent may have repaired one path and broken another.

Recover: require focused checks, full suite, frontend build, and behavioral evidence.

Human as hidden context

The commander remembers ports, yesterday’s diagnosis, and the open browser, then assumes a fresh agent does too.

Recover: cold-prime from local truth and make every needed observation reproducible.

Stale documentation

The specification names files and commands that the final implementation does not ship, including a component tree and npm run type-check.

Recover: use the spec as plan evidence, then verify operations against README, package scripts, and actual paths.

Invented agent layers

Empty agents/ and adws/ directories look suggestive, but they contain no implemented workflows.

Recover: distinguish a destination scaffold, a prompt template, and a running autonomous system.

Presence without leverage

The human watches every token, relays every failure, and calls the interaction “autonomous” because an LLM wrote the code.

Recover: increase size, reduce attempts, build streak, and lower presence only after observation and checks are reliable.
Size ↑More meaningful work per handoff
Attempts ↓Fewer corrections toward one-shot
Streak ↑More consecutive green runs
Presence ↓Less live human mediation
08

Lab · harden the cold-start contract

Change the agent system, not the SQL application. Make one existing prompt produce a measurably better fresh-session operator.

Agent ops lab · improve .claude/commands/prime.md

  1. Baseline. Open a fresh agent, run the current /prime, then ask it to report the application launcher, backend test command, frontend build command, automatic permission gaps, and whether TAC-2 ships subagents. Save the answer.
  2. Design. Ask the agent to propose a minimal expansion of prime.md that reads only the repository facts needed to answer those five questions. Keep it a cold-start interface, not a dump of every source file.
  3. Change. Have the agent edit the existing prompt. Good source candidates are README.md, .claude/settings.json, app/server/pyproject.toml, app/client/package.json, and the three empty scaffold READMEs.
  4. Cold verify. Exit. Start another fresh session with no prior conversation, run the revised /prime, and repeat the same five questions.
  5. Recover. If an answer is still wrong, diagnose whether the problem is missing context, an ambiguous prompt, or an unverifiable claim. Change one condition and rerun.
  6. Optional permission audit. Compare every command the revised prime or launcher needs with .claude/settings.json. Propose the narrowest policy change; do not add a blanket shell wildcard.

Observable pass criteria

  • A zero-history agent names scripts/start.sh, uv run pytest, and npm run build with source paths.
  • It distinguishes auto-allowed commands from commands that may need approval.
  • It states that no subagent, hook, skill, CLAUDE.md, or Claude launcher is committed.
  • Its answer cites repository evidence instead of relying on conversation memory.
  • The revised prompt is shorter than copying the whole spec and remains understandable to a human reviewer.

The pattern you just installed

You converted repeated human briefing into a reusable prompt interface, then verified it with a replacement agent. That is the move from presence to programmability in miniature.

09

Teach-back · six sentences, no peeking

Close the page. Explain the agent OS of TAC-2 in exactly six sentences. Use one sentence for each job below.

  1. Name the mission and divide responsibility between commander and coding agent.
  2. Explain how prompts and local context make a fresh session replaceable.
  3. Explain what the permission contract enables and what it still cannot prove.
  4. Distinguish the application harness from the programmable agent invocation.
  5. Walk plan → act → observe → verify → recover through the planted CSV failure.
  6. Land the leverage thesis with size, attempts, streak, and presence.

Self-check: if your explanation says only “give the agent a better prompt,” you missed the lesson. It must name at least one context surface, one permission surface, one harness, and one verification surface.
