1

Git is his distribution channel

You cannot learn the loop from the commit history, because the commit history does not contain it.

Nine of ten repositories open with a single commit that dumps a finished project — up to 124 files and 14,000 lines at once. The rest is README churn. The real building happens off-git and gets squashed at publish time.

Anyone who tells you they reverse-engineered this workflow from GitHub is pattern-matching on a press release.

Every history is dead flat on main. The topology never survives publish.
2

One session leaked

Exactly one repository caught him actually building — 94 minutes on 2025‑06‑06. The order is emphatic, and it is the opposite of how most people set up a project.

The machine comes before the work. A slash command and vendor docs land in commit one, before a single line of application code. CLAUDE.md arrives on day four.
THE TELL CLAUDE.md at commit 15 is a retrospective summary — it enumerates files that already existed and even hedges, "prime.md — Additional command (if present)." It is generated documentation of a working system, not a plan for one.
3

Five commands, not twelve

There is no /feature and no /bug anywhere in the corpus — 255 command files, 160 unique once you dedupe the mirrored copies.

The 2025 course teaches three separate templates. Every production repo converged on one parameterised /plan whose first instruction is to work out the task type itself.

Build one file, not three that drift.

.claude/commands/plan.md — the deciding line
- Determine the task type (chore|feature|refactor|fix|enhancement)
  and complexity (simple|medium|complex)

Task type then gates sections conditionally, inside one template.

Prime beats memory

Twenty of thirty repos have no memory file at all — including the flagship ones.

The "keep it ~40 lines" advice is real — it traces to a genuine quote, and four course repos are exactly 43 lines, three of them byte-identical.

But the practice is more extreme than the doctrine. His default is not to have one.

And prime.md is written backwards: it is born as a one-line git ls-files and only gains READ: README.md three days later — after the README exists. You point it at artifacts once they are real, never before.

"I'm saying that this arrangement of ADWs is completely arbitrary. There is no one way to do this. The one way is the way that ships in your code base."

— TAC-7, on his own framework
