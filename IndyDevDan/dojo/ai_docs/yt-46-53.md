- Prompt engineering gem: tell agents **what to ignore**, not just what to find — don't nitpick syntax; structured XML findings with severity classifications.
- **JSONL output over JSON/YAML**: the file is always valid mid-stream, immediately readable, streamable; they act on step-finish events for cost tracking, error detection, and retries (length-cutoff → retry).

- Context engineering: diffs saved to patch files, each sub-reviewer reads only its domain's patch + one shared context file — duplicating full context would multiply cost 7x.
- Bias toward approval + a human "break glass" escape hatch — agent-forward, never hard-blocking engineers.
- System resilience S-tier: per-task timeouts, retry budgets, model fallback chains, error classification (model's fault vs not), provider hot-swap via CI job, and incremental re-reviews that carry prior review context.

- Weak spots in the ranking: one mega custom tool (spawn_reviewers does everything — C tier), agents.md rot policed by yelling at humans (self-improving: F), not always-on, humans still in the loop.
- **ZTE (zero-touch engineering) is the North Star** — "phase three... I haven't seen anyone doing zero-touch work yet." Vibe coding is not looking; ZTE is having built systems so good you don't have to look.

**Tools/tech:** opencode (+SDK), GitLab CI, plugin architecture (bootstrap/configure/post-configure lifecycle), BrainTrust distributed tracing, JSONL streaming, fusion/concatenation prompt pattern, model stack (Opus tier / workhorse / Kimi K2.5), prompt-injection prevention, agents.md.

**Repo:** none (breakdown of Cloudflare's engineering blog post by Ryan Skidmore).

**Drill:** watch-and-absorb. ## YT-50: PLANS For Fable 5: Rebuilding My /Plan Skill for Mythos Class Models
(DzbqeO_diOQ · 1:02:49 · upload 2026-06-22)

**Thesis:** Great planning is great engineering — never outsource your planning to the built-in /plan black box; hand-build a planning meta-skill that templates your engineering, because Mythos-class models will repay every token you spend on HTML+image-rich, living, self-validating plans.

**Nuggets:**
- "Great planning is great engineering." And: "The future is created by those who plan it, not those who vibe code it."
- Handing planning to the model "assumes the model knows what you're looking for" — part of "the mass deprecation of raw engineering talent." **You should not outsource your thinking.**
- The plan skill is a **meta skill** — a prompt that creates other prompts. Rule: the more a skill will be reused, the more upfront investment it deserves; the plan prompt is the most important tool you and your agents have.
- Method: start by hand. Open `raw.md` and just type — purpose, priorities, properties. "Property-based engineering": list the properties you want the output to have before building anything.
- Declare priorities explicitly: **performance > speed >= cost**. "We're spending to win here."
- Audience trifecta: every plan is consumed by (1) you, (2) your engineering team, (3) AI agents — and must serve all three. Most engineers over-index on just one.
- Plans become **living artifacts**: updatable header metadata (created, modified-list, commits, agent names, session IDs), back references and forward references (append-only lists), and an Amendments section recording post-build changes.
- The plan format: HTML-first, hero image, purpose/problem/solution, existing-vs-new files, phased implementation with per-phase step-by-step tasks, per-phase testing strategy, embedded live checklists with four task states (idle / WIP / done / failed), and validation commands that gate completion — "the plan is not complete until every box is checked and every command passes" (closed loop).
- One skill, five workflows routed by a table: create plan, update plan, update references, build plan, image generation. Self-contained — no cross-skill dependencies.
- Build workflow: fresh-context agent ("one agent, one prompt, one purpose") reads all images + back refs depth 1, executes phases top to bottom, announces each phase, loops until validation passes, updates metadata.
- Image discipline (GPT Image 2): professional, 1–2 ideas per image, under 10 words of text, synced visual identity with the HTML theme. "An image is worth a thousand words. Let's put that into action."
- Templating doesn't constrain the model **if** you add a free-run Notes section: "Let the agent say what it needs to say" (it self-added a feature parity matrix there).
- Watch your restrictions: changing "2–4 sentences" to "2–8" is a real design decision on the model.
- "We stopped coding a long time ago... A lot of us are becoming skill atrophied. That's natural. But you do not want to outsource your thinking."
- "It is your specific domain knowledge and expertise that differentiates you — encode it into your work." Templating your engineering is what gets you out of the normal distribution of results.
- HTML gives agents more useful tokens (the Anthropic "unreasonable effectiveness of HTML" idea); next up: SVG diagrams, then audio and video in multimodal specs.

**Tools/tech:** Claude Code + Opus 4.8 (high thinking effort), Pi coding agent, meta-skill (skill that writes skills), GPT Image 2 via a ~200-line Astral UV single-file script, plan F3 skill, Iron (Tailscale-for-applications P2P networking, the test spec subject), agent comms network on MiniMax 3, VS Code (dropped Cursor).

Contains `RAW.md` (the by-hand thinking doc from the video), `legacy_v1_meta_plan.md` (the year-old V1 spec prompt), `prompts/`, `specs/`, and images. **Drill:**
