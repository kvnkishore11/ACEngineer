15 recurring thinking patterns

1. Problem classes, not one-offs

Template the class (/chore /bug /feature), not the ticket.

2. Three-times rule

Once = novel. Twice = maybe. Three times = automate into slash command / ADW now.

3. In-loop → out-loop (gray, progressive)

Prototype in chat; promote to script/trigger. Don’t live in chat.

4. Fresh agents always

Free context; force reusable prompts; enable AFK. One agent, one task, one mission.

5. Prioritize agentics

≥50% time on the ring. Application work is often the distraction.

6. Fix the system

Failed run → improve template/ADW/validators, not the one PR by hand.

7. KPIs as north star

Size↑ Attempts↓ Streak↑ Presence↓. Broken streak → missing leverage point.

8. IDKs

Types, “think hard”, model_set, issue tags — dense steering with few tokens.

9. Plan is the prompt

Meta-prompt writes plan; HOP implements plan path. Great planning = great prompting.

10. Own the pipeline

Cloud agents are generic. Your templates encode your engineering.

11. Proof over vibes

Screenshots (read back), tests as law, issue comments, ADW JSONL logs.

12. Compose primitives

SDLC is one molecule. Atoms: prompt, template, ADW step, validator, trigger.

13. Belief update

Invest until streaks prove classes. Limiting belief about “my codebase” is fatal.

14. Minimum context

R&D: reduce & delegate. Specialization over god-agent. Compact is a bandaid.

15. Autonomy ladder

Chores → bugs → features → ZTE. ZTE only after ~90% confidence streak.

How he builds (typical demo / session)

  1. Clone real course repo / open real app — not toy slides; live NL→SQL etc.
  2. Setup /install — env, deps, agent-facing structure already present.
  3. Show end-state first when possible (issue→PR while teaching guts).
  4. In-loop only for discovery — /prime, one closed-loop experiment, inspect stdout.
  5. Template the class — meta-prompt writes specs/; never ad-hoc forever.
  6. Fresh agent implements — /implement or ADW step; YOLO only in isolated env.
  7. Validators in the prompt — request/validate/resolve; re-run full stack on fail.
  8. Promote to ADW — adw_*.py, health_check, classify, state.json, logs under agents/<adw-id>/.
  9. Wire PITER — issue/Notion/tasks.md + webhook/cron + dedicated box/worktree + PR/board review.
  10. Compose — plan_build_test_review_document[_ship]; ISO parallel on worktrees.
  11. Post-mortem on system — miss → fix template/review prompt, not blame model.
  12. Score KPIs — then decide whether class is ready for ZTE.

The agentic layer

Everything outside application source that teaches compute how to operate the app. Dan’s edge is not “more prompting” — it’s this ring: prompts + plans + uv scripts that shell Claude (or Pi), compose via state/stdout, and thicken along real problem classes.

Gateway script pattern

Core move: deterministic Python shells to Claude CLI. Never bury prompts as ad-hoc strings.

# Essential command shape (adw_modules/agent.py)
cmd = [CLAUDE_PATH, "-p", request.prompt]
cmd.extend(["--model", request.model])
cmd.extend(["--output-format", "stream-json"])
cmd.append("--verbose")
if request.dangerously_skip_permissions:
    cmd.append("--dangerously-skip-permissions")
subprocess.run(cmd, stdout=output_f, env=get_safe_subprocess_env(), cwd=working_dir)

Composition rules (how primitives nest)

L0  Prompt file (.claude/commands/*.md)     # one purpose
L1  execute_template / adw_slash_command    # one agent run
L2  Phase ADW (adw_plan_iso, adw_build_iso) # state + git + github
L3  Chain ADW (adw_plan_build_test_iso)     # subprocess composition
L4  Trigger (cron/webhook/tasks.md/Notion)  # external event → L3
L5  Orchestrator (AH) / CEO board (MA)      # agents that launch ADWs
  1. One agent, one prompt, one purpose — planner ≠ builder ≠ tester; separate agent_name dirs.
  2. Stdout is a leverage point — chore must return parseable plan path; tests return JSON for fan-out.
  3. Plan is the prompt — implement is basically “read plan; execute; report.”
  4. State file chains phases — adw_state.json holds branch, plan_file, ports, worktree.
  5. Tags/IDKs route thickness — {opus}, prototype tags, etc.
  6. Isolation before parallelism — worktrees + port ranges.
  7. Feedback loops close with code — hooks block bad tools; validate gates; resolve_failed re-enters.
  8. Specialize per codebase — don’t build generic layers; duplicate and specialize.

How to code like him on the layer

  • Create only adws/, .claude/commands/, specs/ first — zero app code in them.
  • Write /prime (Run/Read/Report) before anything clever.
  • Write template meta-prompts that emit fixed Plan Format into specs/.
  • Write HOP /implement that only takes a plan path.
  • Build agent.py that shells claude -p … --output-format stream-json, filters env, retries, logs under agents/.
  • Add gateway adw_prompt.py then adw_slash_command.py.
  • Chain with stdout parsing (plan path), not shared memory.
  • Add validation commands in every plan; later automate as adw_test + resolvers.
  • Add triggers only after manual gateway works.
  • Add worktrees before parallel fan-out.
  • Add hooks for safety and observability (block first, summarize second).
  • Specialize prompts to problem classes.
  • Measure time: ≥ half of engineering on the layer.
  • Ask daily: agentic layer or application layer?

App1 — Agent Layer Primitives (MVAL)

Thinnest real ADW stack

No hooks, no triggers, no worktrees, no GitHub. Pure gateway + chore→implement chain. Start here.

Workflow: human/CLI → gateway → 1–2 agents → specs/ + app edits + agents/{id}/ logs.

App2 — Multi-Agent ToDone (file board)

tasks.md is the two-way prompt UI. Cron claims tasks, marks in-progress, worktree, plan/build, update with ✅/❌ + commit hash.

  • Status emojis: [] [🟡] [✅] [❌] [⏰] = control plane
  • Tag-driven routing: {opus, adw_plan_implement_update_task}
  • Trigger: adw_triggers/adw_trigger_cron_todone.py

App3 — Out-Loop Multi-Agent Task Board (observability)

Same multi-agent pattern as app2, plus full hooks + Vue/Bun observability product. Hooks POST events → SQLite → WebSocket → UI. The app layer is the observability product; agentic layer still at repo root.

.claude/ ├── commands/ ├── hooks/ pre/post_tool_use, stop, subagent_stop, send_event… └── settings.json apps/client + apps/server ← observability product

App4 — Agentic Prototyping (Notion + tags)

External board (Notion) + prototype tags like {{prototype: uv_mcp}} route to specialized plan templates. Template meta-prompts solve whole problem classes (UV MCP servers, Vite Vue, Bun scripts). deep_specs/ for heavy architecture.

App5 — NLQ-to-SQL AEA (full SDLC / ZTE)

The thick end: ~30 commands, full ISO pipeline, GitHub issue → classify → worktree + ports → plan → build → test (JSON) → fan-out resolvers → review → document → optional ZTE ship. Playwright MCP. Exception to 1-1-1: in-app agents can continue sessions by session ID (/aea).

1
R&D Framework · Context Window Mastery

Only two moves: Reduce and Delegate

Context is scarce temporal attention. 12 techniques: measure /context, purposeful MCP, prime ≫ CLAUDE.md, output styles, sub-agents, planner/builder, clear+prime not compact, context bundles, one purpose, system-prompt control, background primaries, experts preview.

“A focused agent is a performant agent.” · “What gets measured gets managed.” · “If you aren’t managing context, you’re vibe coding.”
2
Seven Levels of Agentic Prompt Formats

Prompt = fundamental unit of engineering

Stakeholder trifecta: you, team, agents. Levels: (1) High-level (2) Workflow [S-tier] (3) Control flow (4) Delegation (5) Higher-order (6) Template meta (7) Self-improving + Expertise. Pattern: Input → Workflow → Output.

“The high-level prompt is a great place to start. It’s a terrible place to end.” · “Three times marks a pattern.”
3
Building Domain-Specific Agents

Better → more → custom

OOTB agents are for everyone’s codebase. System prompt is the law. Ladder: Pong → Echo → Calc → QA → Tri-copy → Micro SDLC → UltraStream. disallowed_tools, overwrite vs append, hooks for safety.

“Agentic coding is about what we can teach our agents to do.”
4
O-Agent · Multi-Agent Orchestration

Single interface over a fleet

Three pillars: Orchestrator · CRUD agents · Observability. Agents = deletable single-purpose resources; produce concrete assets; scout→build→review via sleep/poll. Never does the work itself; tails logs only.

“Treat your agents as deletable temporary resources.” · “If you lose track of your agents, you lose control of results.”
5
Agent Experts

Act → Learn → Reuse

Agents forget ⇒ they don’t learn. Expert = self-improving template meta-prompt. Structure: .claude/commands/experts/<domain>/{expertise.yaml, question, plan, self-improve, plan_build_improve}. Expertise = mental model, not source of truth (code is). Deploy first on high-risk domains (billing #1).

“One executes and forgets; the other executes and learns.”
6
Building Agentic Layers · Codebase Singularity

Grade yourself; climb one grade

Singularity = agents run codebase better than you. Class/grade map:

  • C1 in-loop: G1 prime → G2 plans/ai_docs/subagents → G3 skills/MCP → G4 closed loops → G5 BFC templates → G6 chains → G7 experts
  • C2 out-loop: webhooks → ADWs (code + agents)
  • C3 orchestrated: O-Agent → orchestrator workflows → orchestrator runs ADWs

Multi-Agent extras · Trust & scale

CEO · Lead · UI · Verifier

Four lessons on a customized Pi harness. Theme of 2026: trust and scale. Hierarchy of thinking: CEO decides → Lead coordinates → UI operates product → Verifier buys trust with tokens for time.

The arc

MA-1 · CEO Agents

Thesis: Uncertainty in → memo out. CEO + adversarial board (Revenue, Architect, Compounder, Product, Contrarian, Moonshot). Brief requires Situation / Stakes / Constraints / Key Question. Time+budget constraints engine. Expertise stacks across briefs. One-shot: ceo begin.

“It’s not just you making key decisions anymore… it’s you, your team, and a country of geniuses in a data center.”

MA-2 · Lead Agents

Thesis: One agent is not enough. Three-tier: orchestrator → leads → workers. Domain locking (holy grail for mid/large codebases). Mental models grow. Zero micromanagement skill. Opus thinkers / Sonnet workers. Cognitive input stays flat as agent count grows.

“You stopped using agents that forget and you started using agent experts.”

MA-3 · UI Agents

What he rails against

Antipatterns &
failure modes

Cargo cult familiarity is the enemy. Optimize for metabolism: encode → act → learn → verify.

Mindset traps

  • Still typing / clinging to coder identity
  • Vibe coding without tests, plans, templates
  • Babysitting multi-turn in-loop as the end state
  • Limiting belief (“won’t work on my codebase”)
  • Blaming the model first — blame skills and ADWs
  • Premature ZTE without streak/confidence

Architecture antipatterns

The Monolithic Agent

One giant agent does everything → context overload, undebuggable. Fix: specialize.

The Tangled Layer

Mixing agentic and application code. Fix: strict ring outside src/.

God-agent / max context

Pollution; compact as bandaid. Fix: R&D, fresh agents, one purpose.

Ad-hoc prompt strings in code

Unversioned, unimprovable. Fix: commands in .claude/commands/.

Operations antipatterns

  • Outsourcing the agentic layer to generic cloud agents for your domain
  • Fixing symptoms (hand-edit one failure) instead of templates
  • Bad agentic code — swallowed errors, no stdout, hidden failures
  • One-off fixes instead of class solutions
  • Skipping validation / e2e while claiming AFK or ZTE
  • Review without proof (screenshots not read)
  • Infinite agent loops without depth limits / fail-fast
