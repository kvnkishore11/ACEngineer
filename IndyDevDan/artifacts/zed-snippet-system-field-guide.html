02 — The idea underneath
why he bothers

The point is not typing speed. It is never deciding twice.

A snippet that saves you four seconds is a toy. A snippet that removes a decision from your day — and from your agent's context window — is infrastructure.

"Create reusable formats so that you don't have to think about it — and so that your agents don't have to think about your prompt format."

— yt-28 @5:04

Read that twice. There are two beneficiaries, and the second one is the surprising one.

When every prompt you write has the same skeleton — the same section names in the same order — the model stops spending attention on parsing your format and spends it on the task. Consistency is a context-window optimisation disguised as a text expander.

The same six bones in every prompt. You fill the flesh; the skeleton is never up for debate.
01

You stop deciding

No more "does this one need a Report section?" The template already answered.

02

Your agent stops guessing

Familiar shape, familiar section names — attention goes to the work, not the wrapper.

03

Your team can read it

Every prompt in the repo looks like every other prompt. Review becomes skimming.

NEWCOMER NOTE A "reusable prompt" here means a markdown file in .claude/commands/ that you invoke as a slash command. The snippet writes the file's skeleton; the slash command runs it later. Snippet is the authoring tool, not the running tool.

03 — The grammar
twelve sections, seven levels

Every prompt he writes is built from the same parts list.

This is the part that is genuinely documented — not inferred. The section vocabulary and the level ladder are both written down in his own course repo.

documentedagentic-prompt-engineering/README.md
In this chapter 1The twelve sections 2The seven levels
1

The twelve sections

There is a fixed, ordered vocabulary. You never use all twelve at once — you pick the ones the job needs, but you always keep them in this order.

Four of them carry most of the weight: Purpose says why, Variables says what comes in, Workflow says what happens, Report says what comes out. The other eight are situational.

Clay = load-bearing. Grey sections appear only when the prompt actually needs them.
WHY ORDER MATTERS The model reads top to bottom. Constraints (Instructions) land before the steps that must obey them (Workflow), and the output contract (Report) lands last so it is freshest when the agent starts writing.
2

The seven levels

The same parts list scales. A level is not a difficulty rating — it is a statement about what the prompt is allowed to do. Higher levels earn their complexity by taking on more.

Complexity should be earned, not assumed. Levels 2 and 3 cover most real work. Reach higher only when the job demands it.
◴ reaching too high
  • A metaprompt for a task you run twice
  • Subagents where a loop would do
  • An Expertise section nobody updates
◵ the right altitude
  • Level 2 for anything you have done three times
  • Level 4 only when you need parallelism and specialisation
  • Level 7 only where knowledge genuinely accumulates

What agp actually produces

.claude/commands/your-prompt.md — after expansion
---
description: What this prompt does
argument-hint: [arg_one] [arg_two]
allowed-tools: Read, Write, Edit, Bash, Glob, Grep
model: sonnet
---

# Prompt Title

## Purpose

High level description of what this prompt accomplishes.
Follow the `Instructions` and execute the `Workflow` to
deliver the `Report`.

## Variables

FIRST_INPUT: $1
SECOND_INPUT: $2

## Instructions

- Guardrail or constraint the agent must respect.
- IMPORTANT: The one rule that must never be broken.

## Workflow

1. Read / gather context.
2. Do the work.
3. Report the results based on the `Report` section.

## Report

- Describe the exact output format returned to the engineer.

Fourteen tab stops.

Each italicised placeholder above is a cursor position. Press Tab and you land on the next one — description, then argument hint, then tools, then model, and on down through the body.

The two $1 and $2 markers in Variables are not tab stops. They are Claude Code's positional arguments and they survive into the finished file — a detail that takes deliberate escaping to get right. Chapter six explains it.

05 — Driving it
the gesture, and the one restart

Type three letters. Hit control-space.

That is his exact gesture, quoted from yt-22, and it is now yours. There is one setup step first.

  1. Restart Zed once

    Your settings.json now carries "snippets": true under auto_install_extensions. On next launch Zed fetches and installs the Snippets extension by itself. Nothing to click.

  2. Open any markdown file

    A new .claude/commands/whatever.md, a SKILL.md, anything ending in .md.

  3. Type the prefix, then force completions

    Type agp. Press ctrl space. Pick it from the menu.

  4. Tab through the placeholders

    Tab moves forward, shift Tab moves back. The final stop drops your cursor at the end of the file.

The whole loop. Three keystrokes to a structure that would take two minutes to type by hand — and would drift every time.
2

GSTC, rebuilt as a task

His git checkpoint does not insert text — it runs a command. So it cannot be a snippet.

In Zed the right home for it is a task. It is registered in tasks.json and bound to space g c in normal mode, sitting right beside your existing space g g lazygit binding.

It stages everything and commits with the message progress — which is why his repos are full of commits saying exactly that.

~/.config/zed/tasks.json
{
  "label": "gstc",
  "command": "git add -A && git commit -m \"progress\" || true",
  "use_new_terminal": false,
  "reveal": "on_error"
}

The trailing || true keeps a no-op commit from surfacing as an error.

06 — Gotchas & extending
two traps, one recipe

The dollar sign will bite you exactly once.

Everything else about writing your own snippets is mechanical. This one thing is not obvious, and it fails silently.

In this chapter 1The dollar-sign trap 2Where snippets do not work 3Adding your own
1

The dollar-sign trap

Snippet placeholders are written $1, $2, $0. Claude Code's positional arguments are also written $1 and $2.

They collide. Write $1 naively inside a Variables section and the editor eats it as a tab stop — your finished prompt file ends up with the argument marker missing, and you will not notice until the command misbehaves at runtime.

◴ swallowed by the editor
  • "body": ["INPUT: $1"]
  • Renders as an empty tab stop
  • The argument marker never reaches the file
◵ escaped, survives to disk
  • "body": ["INPUT: \\$1"]
  • Emits a literal $1
  • Claude Code reads it as argument one

Two layers are in play. JSON consumes one backslash, so \\$1 in the file becomes \$1 by the time the snippet engine sees it — and a backslash-escaped dollar is the engine's way of saying "this is text, not a placeholder."

The same applies to $ARGUMENTS and to shell variables like $CLAUDE_PROJECT_DIR inside hook commands. All of them are escaped in the shipped file.

2

Where snippets do not work

NOT IN THE AGENT PANEL Snippets are an editor feature. They expand in file buffers only. Typing agp into Zed's Agent Panel chat box will do nothing — that input is not a buffer.

This is less limiting than it sounds, because it matches how the workflow actually runs. You author prompts as files, then invoke them as slash commands. The snippet belongs to the authoring half.

If you do want reusable text inside the agent panel itself, Zed has a separate mechanism for that — the Rules Library, reachable from the command palette.

3

Adding your own

~/.config/zed/snippets/markdown.json
{
  "My scaffold": {
    "prefix": "mine",
    "description": "Shows in the completion menu",
    "body": [
      "# ${1:Title}",
      "",
      "## Purpose",
      "",
      "${2:What it does}",
      "",
      "## Variables",
      "",
      "INPUT: \\$1",
      "$0"
    ]
  }
}

Three keys and you are done.

prefix is what you type. description is what the menu shows beside it. body is an array of lines.

${1:Title} is a tab stop with default text. $0 is where the cursor finally rests — always put one, or you will end up back at the top of the file.

Zed reloads the file on save. No restart needed after the first one.

KEEP THE GRAMMAR When you extend the library, hold to the twelve canonical section names in their documented order. The value compounds only while every prompt looks like every other prompt — a bespoke section in one file undoes the consistency you installed this for.
