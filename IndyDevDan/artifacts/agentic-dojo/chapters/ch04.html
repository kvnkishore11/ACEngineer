The Idea — Encode How You Solve Problems

"Plans are prompts scaled up for high impact… great planning is great prompting."

A scaled prompt is "a plan, a specification, a PRD." Tactic #3 — Template Your Engineering — means "you encode your problem solving into reusable units that you, your team, and your agents can see, use, and importantly, improve."

Two prompt species make it work. A meta prompt is "a prompt that builds a prompt" — /chore generates a plan from a template. A Higher Order Prompt (HOP) takes another prompt as an argument — /implement <path-to-plan>, "plans getting passed into plans," like passing functions into functions. A high-level prompt is "a prompt void of detail" that templates expand into detailed plans, landing in specs/ — "staging environments for code that will be generated."

The pipeline. This chore "has been completed agentically with two prompts — one for the planning phase and one for the coding/building phase."
Anatomy of a template. Purpose, Instructions, Relevant Files, Plan Format, and an $ARGUMENTS slot.

Always run fresh agents. Three reasons.

One — free the context window: "one agent, one task, one mission." Two — it forces prompts, plans, and templates to be "isolated, reusable, improvable assets with zero dependencies." Three — "prepare for true off-device agentic coding": "we need to decouple our performance from the conversational context window."

Inside the templates, Anthropic's encoded IDK "think hard" activates the reasoning model — "throw more compute at the problem." And together, the first three tactics — Stop Coding, Adopt Your Agent's Perspective, Template Your Engineering — form the Pareto 80/20 of agentic engineering.

The Workout

GOAL Build a chore → plan → implement pipeline from templates and ship one chore with exactly two prompts.
PREREQUISITES Claude Code · a repo with at least one test command (or disler/tac-3).

The plan is the prompt — and that means great planning is great prompting.

— quote of the lesson

  1. Write the meta prompt

    Create .claude/commands/chore.md: Purpose ("create a plan in specs/ to resolve the chore"), Instructions, Relevant Files, a Plan Format (Chore / Description / Relevant Files / Step-by-Step Tasks / Validation Commands / Notes), ending with Chore: $ARGUMENTS.

  2. Write the HOP

    Create .claude/commands/implement.md: "Read the plan at $ARGUMENTS. Think hard. Implement every step in order. Run the validation commands. Report: summary + files changed."

  3. Generate a real plan

    Run /chore "<one real small task in your repo>" and read the generated plan in specs/.

  4. Implement fresh

    Open a NEW terminal + fresh Claude instance; run /implement specs/<plan>.md.

  5. Verify and commit

    Run the plan's validation commands yourself; commit specs + code.

  6. Repeat headlessly

    claude -p "/chore '<another chore>'" --output-format stream-json --verbose > run.jsonl — and watch the stream.

DONE WHEN One chore ships end-to-end with two prompts, the plan file exists in specs/, and validation commands pass on rerun.
LEVEL UP Add /bug (Steps to Reproduce + Root Cause Analysis) and /feature (user story + phased implementation) templates; specialize one template to a specific subsystem of your codebase.
