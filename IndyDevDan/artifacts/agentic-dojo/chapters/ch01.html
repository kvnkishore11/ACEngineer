The Evolution: from prompt to fleet

Dan's whole body of work is one idea, compounding.

It starts with the Big Three — context, model, prompt — the levers of AI coding. Agentic coding adds the fourth: tools, and reliably long chains of tool calls. That is the Core Four, and it is his anti-hype instrument: every feature, framework, skill, MCP server, and sub-agent you will ever meet is "just" context, model, prompt, and tools with ergonomics.

Then the unit of work climbs. First "the prompt is the fundamental unit of engineering." Then, as models learn to prompt-engineer their own sub-agents: "if you master the agent, you master knowledge work." The endgame is agents managing agents — and you, out of the loop, orchestrating.

The compositional unit keeps climbing. Master each rung before the next; the rungs never go away.

Focus on principles, not tools, not models. Principles never change.

— IndyDevDan, the line under everything

The Laws: twelve invariants of the house style

You will meet each of these a dozen times across the volumes. Treat them as laws of physics for agentic work.

L1

A focused agent is a performant agent

The context window is precious, ephemeral, temporal. Protect it above all else.

L2

R&D: Reduce & Delegate

The only two ways to manage a context window. Everything else is commentary.

L3

The plan is the prompt

Great planning is great engineering. Never outsource your thinking — template it.

L4

Template your engineering

Encode how you build into committable prompts, plans, and workflows — then fix systems, never one-off issues.

L5

One agent, one prompt, one purpose

Specialization all the way down. Avoid context pollution like production debt.

L6

Always add feedback loops

Request → validate → resolve. Agents that test their own work win, full stop.

L7

Agents + code beats either alone

Code is deterministic, light-speed, zero tokens. Never give an agent a step code can do.

L8

Scale your compute to scale your impact

Best-of-N, parallel fleets, sandboxes. More compute should equal more trust — or you're doing it wrong.

L9

Three times marks a pattern

The third repetition is your signal: codify it into a reusable prompt, skill, or workflow.

L10

Measure or you're vibe coding

Context meters, observability, KPIs, evals. "If you don't measure it, you can't improve it."

L11

Own your harness

"Whoever controls the agent harness controls your results." CLIs over MCP; the system prompt is the product.

L12

Build the system that builds the system

Spend 50%+ of your time on the agentic layer. Implementation is commoditized; orchestration is not.

◴ vibe coding
  • Not knowing what will happen — and not looking.
  • Prompting one agent back and forth, forever in the loop.
  • Ad-hoc prompt strings that die with the session.
◵ agentic engineering
  • Knowing your system so well you don't need to look.
  • Showing up only at the two ends: planning and review.
  • Every prompt a committed, improvable, versioned asset.

The distinction that defines the era.

Planning and reviewing are the two constraints of agentic coding. Everything Dan builds — meta prompts, ADWs, verifier agents, orchestrators — attacks one of those two bottlenecks. When you're deciding what to build next in your own agentic layer, ask which constraint it relieves.
