The Catalog — the whole gym floor

These repos are video artifacts, and that changes how you read them.

Dan ships whole ideas per commit: the initial drop is labeled 🚀 and usually contains the entire working system; later commits are progress polish plus the occasional real feature drop with a meaningful message. So don't read these repos like products with long histories — read them like 26 finished exercises, each one training a specific muscle.

Six zones cover the floor: hooks and observability, orchestration, skills, security, benchmarking, and infrastructure. Every repo below sits in one of them.

Six zones, one gym. Every disler repo trains one theme — and reuses the same skeleton underneath.

The Recurring Patterns

Twenty patterns repeat across the catalog — ten of them so consistently they amount to a house architecture.

The most telling one is pattern №1: a /prime context-priming command — read the README, run git ls-files, scan the key directories, report understanding — exists in virtually every repo, with variants like prime_cc, prime_obox, and prime_tts.

Dan never lets an agent start cold.

— pattern №1, /prime — present across all 26 repos
The canonical anatomy. Docs feed context left into .claude/; specs feed plans right into apps/. Every repo below is a variation of this drawing.
01

/prime context priming

Read README, git ls-files, key dirs, report understanding — in virtually every repo, with per-domain variants. The agent never starts cold.

02

uv single-file Python scripts

PEP 723 inline deps: every hook, validator, and tool is standalone uv-runnable; whole apps ship as one file (sfs_agentic_drop_zone.py).

03

The copied hooks stack

pre/post_tool_use, stop, notification, subagent_stop, user_prompt_submit + llm/tts utils with fallback chains, logging every payload to logs/. A portable artifact carried repo to repo.

04

send_event.py observability bus

Hooks POST summarized events (--source-app, --event-type) to a local server; SQLite + WebSocket/SSE + a Vue dashboard. Rebuilt for Pi too.

05

apps/ monorepo layout

Every runnable codebase lives at apps/<name> with its own pyproject.toml or package.json; the repo root is the agentic layer.

06

ai_docs/ curated documentation

Scraped, condensed third-party docs checked into the repo for /load_ai_docs — often maintained by a docs-scraper sub-agent.

07

specs/ plan-first directory

Plans as markdown (later HTML) that drive generation — versioned specs v1 → v4 in infinite-loop. Great planning is great engineering.

08

justfile + agentic /install

just recipes for humans, agents, and CI; an /install slash command does toolchain checks and setup interactively.

09

HOP/LOP prompt orchestration

One higher-order prompt fans out to N parameterized lower-order prompts and aggregates results — nano-agent's perf evals, /infinite, /ui-review, /review-finances.

10

Skills that ship their own tooling

SKILL.md + cookbook/ + prompts/ + an embedded CLI or scripts dir; progressive disclosure so the agent only reads what it needs.

…and the other ten, in brief

11 · Meta-agents & meta-skills — things that generate the things: meta-agent.md writes agents, planf3 writes plans, the-library manages skills.

12 · Model-tier variants — the same prompt at haiku / sonnet / opus; the performance-speed-cost trifecta as a file-naming discipline.

13 · The safety ladder — bypassPermissions only inside sandboxes or watched zones; otherwise blacklist → whitelist → no-bash custom tools.

14 · Deterministic validation — agents validate their work with scripts, not vibes: validator hooks, committed eval results, QA reports in ai_review/.

15 · Cross-agent portability — CLAUDE.md + AGENTS.md + GEMINI.md triplets; Dan builds for the category, not one vendor.

16 · TTS + personalization — completion announcements with your ENGINEER_NAME; fallback chain ElevenLabs → OpenAI → pyttsx3.

17 · Output styles + status lines — versioned status lines (v1 → v9) and portable style sets as an observability UI.

18 · README as video companion — one-line hook, YouTube link in the first five lines, hero image, Quick Start, "Master AI Coding" footer.

19 · Team agent patterns — builder + validator team dirs, plan_w_team commands, lead/worker 3-tier cmux teams.

20 · Emoji/terse commits — 🚀 for the initial drop, progress for iteration, meaningful messages reserved for real feature drops.

The Canonical Layout

any-disler-repo/ .claude/ commands/ # prime.md · install.md · hop_*.md — prompts as programs agents/ # sub-agents · meta-agent.md · team/ builder+validator hooks/ # pre_tool_use.py … uv single-file scripts + utils/llm, utils/tts skills/ # SKILL.md + cookbook/ + embedded tooling settings.json # hook wiring + permission allowlists ai_docs/ # curated third-party docs — /load_ai_docs specs/ # plans drive generation (markdown, later HTML) apps/ # every runnable codebase — own pyproject/package.json logs/ # every hook payload, logged as JSON images/ # README hero + architecture diagram justfile # the launch pad — humans, agents, CI CLAUDE.md # + AGENTS.md + GEMINI.md — cross-agent portability README.md # the video companion

This tree is why the patterns travel so well.

Because the root is always the agentic layer and the code always lives under apps/, whole subsystems copy cleanly between repos. The hooks stack, the TTS utils, the meta-agent, the observability bus — each is a portable artifact that appears near-identical in hooks-mastery, observability, nano-agent, big-3, and agent-experts.

When you build your own repos this way, you get the same effect: every new project starts at 80%, because the agentic layer comes with you.
