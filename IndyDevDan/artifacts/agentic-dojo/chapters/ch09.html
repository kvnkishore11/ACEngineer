The Idea

Tactic #8: Prioritize Agentics. "Agentics refer to systems or entities capable of autonomous action and decision-making. This tactic represents all others… all tactics are compressed into this tactic."

The agentic layer is "the combination of traditional deterministic code stored in your ADWs directory as a scriptable layer, with the new non-deterministic agentic technology — the language model, the agent, Claude Code and whatever comes next… the old world of deterministic code and the new world of agentic prompts."

Against it sits the application layer: DevOps + infrastructure + database + the raw app. The rule of thumb: at least half your engineering time on the agentic layer. "Command your agentic layer to run and control your application layer."

The ring. Deterministic scripts + non-deterministic agents wrap the application and operate on it — the layer where 1x input becomes 10x output.

"Am I working on the agentic layer, or am I working in the application layer?"

— the final guiding question. "If you forget everything else, this is the only question you need."

The Minimum Viable Agentic Layer has three pieces, kept strictly isolated from the application: an ADWs directory (any scripting layer — uv, bun, shell), prompts (.claude/commands), and plans (specs/).

Its thinnest expression is the gateway script, adw_prompt — a script that calls one Claude Code agent with one prompt and manages surrounding state and logging. "This script is the gateway into agentic coding."

And the endgame framing: "with agentic coding, not only is code a commodity, but the implementation as well" — early signs of "the commoditization of engineering." Value moves up to system design, system architecture, encoding your domain expertise, quality control, and most importantly creative problem decomposition.

Eight tactics, one compression. The canonical order, collapsing into the tactic that represents all others — and the one question you ask every day.

The Workout

GOAL Bootstrap a minimum viable agentic layer on YOUR real codebase and prove it with one gateway run and one chained ADW.
PREREQS Any real project you maintain; Claude Code; uv (or bun / shell).

  1. Create the three pieces

    adws/, .claude/commands/, specs/ — strictly outside your app directories.

  2. Write /prime.md and /start.md

    For this codebase; verify in-loop.

  3. Write the gateway script

    adws/adw_prompt.py: takes a prompt string, calls claude -p with stream-json output, logs raw + parsed output to agents/<id>/. Run it with a read-only question about your repo.

  4. Port your templates

    Bring /chore + /implement from TAC-3 with THIS codebase's plan format and validation commands.

  5. Chain two agents

    adws/adw_chore_implement.py: the plan path parsed from agent 1's output, passed to agent 2.

  6. Run a real chore, then answer the question

    Ship one item from your backlog through the chain. Then answer, in writing, today's guiding question: what % of your day was agentic layer vs application layer?

  7. Schedule the layer's growth

    Pick the next problem class (bugs), and the trigger you'll add — cron file-watcher, GitHub webhook, or a task board.

DONE WHEN A real chore in your real repo ships via the chained ADW with logs under agents/, and your agentic layer directories contain zero application code.
LEVEL UP Build one of the alternative shapes: a tasks.md + cron trigger multi-agent worktree system, or a Notion / issue-board prototyper — whichever matches how work actually arrives in your life.
