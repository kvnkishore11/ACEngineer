The Prompt Is the Fundamental Unit

YT-10 · Agentic Prompt Engineering with Claude Code (For you, your team, and your AGENTS)

"The prompt is now the fundamental unit of engineering." The 2–100x returns come from engineering every reusable prompt for the stakeholder trifecta — you, your team, and your agents: "There's a new user... it's your agent."

Seven levelled formats built from swappable Lego-block sections. Workflow is S-tier usefulness at C-tier difficulty — "the most important section you'll write is the workflow" — the play your agent maps straight into its todo list.

Variables in, Workflow works, Report defines what returns.
  • "One well-crafted prompt can generate tens and hundreds of hours of productive work. One bad prompt compounds failure at the same rate."
  • Variables are "super underappreciated" (A-tier): dynamic ($1, $ARGUMENTS) take input; statics are defined once, referenced everywhere — change one line, the whole prompt updates.
  • Metadata and Codebase Structure are C-tier — the latter is really "a context map" that spares the agent burning tokens on search.
  • Instructions are guardrails around the steps — "a lot more valuable for your system prompt versus your workflow."
  • Control flow (level 3) is plain natural language: "If no path to plan is provided, immediately stop and ask the user to provide it."
  • Only add sections you need — composable pieces; no output requirements, no Report section.
  • Delegate prompts (level 4, S-tier): "we're writing prompts that write prompts" — your primary agent becomes its subagents' prompt engineer; nondeterminism becomes a feature when you fan out N agents.
  • "Consistency is the greatest weapon against confusion for both you and your agent." "Consistency beats complexity."
  • "Great prompting is great communicating" — the coworker test: could a colleague run your prompt top to bottom?
  • Information-dense keywords (IMPORTANT, exclusively) when the agent must not deviate.
  • Push to B-tier to "capture most of the value"; levels 3–4 cover 90% — template metaprompts (level 6, "the prompt that builds the prompt") scale velocity hardest.
  • CRUD your reusable prompts "at light speed at the right level" — delegation is the D in R&D (Reduce & Delegate).

Custom Agents Are the Endgame

YT-11 · Agentic Coding ENDGAME: Build your Claude Code SDK Custom Agents

The single path: better agents → more agents → custom agents. Out-of-the-box tools are "built for everyone's codebase, not yours" — the endgame is your own specialized agents on the Claude Code SDK, starting with the system prompt.

Overwrite it and "the Claude Code agent that you know and love is now gone... This is not Claude Code anymore." Two modes — overwrite for a true custom agent, append to merely extend Claude Code. Both valid; know which you're doing.

"The system prompt is the most important element of your custom agents with zero exceptions."

— "all of your work is multiplied by your system prompt"
  • The SDK loop: "you set up your options, you set up your agent... you run the query, and then you handle the response" — all incrementally adoptable.
  • query for one-off prompts; ClaudeSDKClient for continuous conversations with memory.
  • Custom tools ship as an in-memory MCP server (create_sdk_mcp_server) — "the description of your tool tells your agent how to use it."
  • The default toolset leaks: ask "list your available tools" and find ~15 you didn't ask for. "Everything that's going into your agent winds up in the context window... it consumes space in your agent's mind." Fix with allowed_tools.
  • Downgrade the model when the job is simple — the echo agent runs Haiku: "It doesn't need powerful intelligence."
  • "Keep track of the core four [context, model, prompt, tools]... you will understand compute."
  • Micro SDLC: planner → builder → reviewer on a kanban, streaming via WebSockets, on their own codebase — "this work shipped with a single prompt outside the loop" (in-loop → out-loop → ZTE).
  • "If you're doing one-size-fits-all work, use the out-of-the-box agent." Custom agents are for specialized, high-ROI work — "this is where all the alpha is in engineering."
  • "Agentic coding is not so much about what we can do anymore. It's about what we can teach our agents to do."

Skills Are Composition, Not Replacement

YT-16 · I finally CRACKED Claude Agent Skills (Breakdown For Engineers)

Skills don't replace MCP, sub-agents, or slash commands — they're a higher-level compositional unit for packaging repeat, agent-invoked solutions. The prompt remains the primitive underneath everything.

What distinguishes them: agent-triggered + context-efficient + a "dedicated modular directory structure" — "the approach that's new," not the capability. Progressive disclosure is the killer feature: metadata, SKILL.md, on-demand resources. "Unlike MCP servers, which just straight-up tortures context window."

Skills

Automatic, agent-invoked behavior.

MCP

External integrations — Jira, DBs, weather APIs.

Sub-agents

Isolated, parallelizable workflows.

Slash commands

Manual triggers — the "super primitive".

  • "Whenever you see parallel, you should always just think, just jump to sub-agents" — nothing else runs parallel; accept losing that context afterward.
  • Converting all your slash commands to skills is "a huge mistake" — never use a skill for a one-off a prompt or sub-agent can do.
  • The graduation rule: one prompt creates a worktree; managing worktrees (create, list, remove, merge) is a problem set — "this is where one prompt is not enough" — that's a skill.
  • "Do not give away the prompt. The prompt is the fundamental unit of knowledge work and of programming. If you don't know how to build and manage prompts, you will lose."
  • "Every agent is the core four" — context, model, prompt, tools; every feature is built on top of them.
  • Hierarchy: skills at the top (they can use prompts, other skills, MCP servers, sub-agents); MCP lower; slash commands both primitive and composer; sub-agents can't nest sub-agents.
  • The worktree-manager skill's instructions literally say "use the {slash} command tool" — skill composes prompt.
  • Starting out? "Just build a prompt. Don't build a skill. Don't build a sub agent. Don't build out an MCP server. Keep it simple."
  • Biggest complaint: skills "don't go all the way" — no commands/ or agents/ directories inside the bundle for nesting.
  • Reliability: an explicit slash-command sequence runs in order, guaranteed; a chain of five skills isn't (yet).
  • Hot take: "skills are effectively opinionated prompt engineering plus modularity... What's actually new here? I think the answer is not that much" — still a solid 8/10.
  • "Build the thing that builds the thing" — the meta-skill (a skill that creates skills) is "a very, very, very powerful agentic abstraction." Hooks stay the deterministic lifecycle layer — balance agent judgment with determinism (the ADW theme).

Beyond MCP: Raw Code as Tools

YT-18 · Why are top engineers DITCHING MCP Servers? (3 PROVEN Solutions)

"My MCP server just ate 10,000 tokens before my agent even started working." One modest server burns ~5% of context; "stack up two or three more MCP servers, and I'll be bleeding 20% plus context in no time."

Three raw-code alternatives — CLI + prime prompt, file-system scripts, and skills — give the same tool access with progressive disclosure, full control, and a fraction of the cost. The unifying theme: "use raw code as tools." Everything reduces to the core four.

Four implementations, one API. Less garbage context, better agent.
  • CLI approach: a ~25-line prime prompt (/prime_kalshi_cli_tools) reads ONLY a README + the CLI file — "do not read any other Python files" — cutting context from ~10% to ~5.6%.
  • Scripts approach: a README maps "a condition mapped to files — this is a powerful agentic data structure you can use to activate or ignore context" — under 1%, ~2K tokens.
  • The trick: "I will not read scripts themselves unless --help doesn't provide information needed" — progressive disclosure by hand, "and it's not a complex prompt."
  • "Even before context comes prompt engineering… it is THE critical skill for engineers in 2025 and beyond. The prompt shows up before the context gets in your context window."
  • Skills = same scripts, different invocation: "with a skill, the prime prompt is the skill.md file" — model-invoked, self-contained, but "a Claude-specific lock-in mechanism."
  • Anthropic's "code execution with MCP" blog wraps scripts around MCP calls; Dan and Mario Zechner: "you can just cut the MCP server out completely" — benchmarks show "no degradation in quality by going right for scripts."
  • Single-file UV scripts (deps declared at top) buy isolation and portability; the duplication is worth it — "when you have less garbage context, your agent can perform better."
  • MCP still wins on features engineers gloss over — "tools, resources, prompts, elicitation, completion, sampling" — and zero-effort setup for external servers.
