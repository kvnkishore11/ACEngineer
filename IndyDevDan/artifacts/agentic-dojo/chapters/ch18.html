The Idea

"Without the agent harness, there are no agents, no agentic coding… no agentic engineering."

Harness engineering is "one of the most viable skills an agentic engineer can learn." The harness gives you "deterministic code, token caching, agent orchestration, prompts, skills, and of course, model control." The one takeaway from the Claude Code source leak: a $2.5B-ARR business is the harness, not the model — and you can build a domain-specialized harness that captures "fractions of that ARR."

The lesson's demo domain is itself a pitch for the adjacent opportunity, agentic security — "anyone can sit down right now and just write a prompt to exploit an application." The flagship brand, Aegis, is an agent security command center.

The harness is the product. Everything above the model line is yours to engineer — and it's where the $2.5B-ARR business actually lives.
The infinite UI system. Brand → product/application → tree → branch/leaf versions. "Design a system that allows us to build infinite UIs within a consistent brand design."

"When you stop vibe coding and you start agentic engineering teams of agents in your agent harness, you can solve problem classes, not just one-off tasks."

It's the same three tiers as MA-2 — "Leads don't work, orchestrators don't work — they think, they plan, and then they delegate the building" — but the workers are domain specialists now: scaffold worker, view generator, animation specialist, brand analyst, soft/hard validators. Each is path-scoped by a domain block in front matter, and each obeys one agent, one prompt, one purpose: "Specialization and that focused context window… is a massive advantage in these multi-agent team systems."

The big three themes of the lesson: "harness engineering, multi-agent orchestration, and then trust and scale. Trust and scale really underlines these first two."

A

The till-done list

"Not a to-do list, not a to-done list, a till-done list. Our agents are going to work until all these tasks are complete."

B

Orchestrator as prompt engineer

"I have taught my orchestrator how to prompt engineer" — the orchestrator writes full prompts to teams; leads prompt workers. Meta, then meta again.

C

Claude Code as meta builder

"80% of the time I'm spinning up Claude Code agents to not work on the actual product… I'm building the system that builds the system." In ands, not ors.

D

Input must not scale

Horizontal team scaling behind a single orchestrator: "our input to the system doesn't scale with the number of agents that we have. This directly limits what you can do."

What Dan Did

Dan framed the Claude Code source leak as evidence the harness is the product — then demoed the infinite UI agents codebase, the third Agentic Horizon asset: an implementation of MA-2's multi-team tool pointed at a domain.

The product is a workspace of three brands — Aegis (the agent security command center), plus AgentX and AgentDan — each brand → applications → trees → branch/leaf UI versions, all rendered in a navigable gallery. The existing UIs (threat dashboards, false positives, coverage, performance, deployment control, activity logs) were built by the agent teams in consistent brand style.

One pasted prompt, one product operated. Orchestrator → till-done list → setup team scaffolds → horizontally scaled UI-gen teams A/B/C in parallel → validation loops fixes → three new agent-stream prototype UIs inside Aegis (glassmorphism dashboard, agents-chatting sidebar, timeline view, compact dashboard), brand-consistent.

  1. Paste one stored prompt

    A reusable prompt creates a net-new application: the orchestrator writes a till-done list, then at-mentions the setup team with a full engineered prompt.

  2. Watch the fan-out

    Scaffold worker builds three trees; the orchestrator deploys UI-generation teams A, B, C in parallel — A/B on open-source MiniMax 2.7 and Step 3.5-flash, C on Sonnet — and leads prompt the view-generator and animation-specialist workers.

  3. Survive the failure

    Open-source workers return "no response"; team A and B leads break the no-write rule — "The task must complete. Let me update and write the component myself." Validation flags two variants; the orchestrator re-delegates fixes to teams A and C until done.

  4. Walk the harness

    The custom multi-team/ structure, agents-os/ variants, the expertise directory, min (9 agents) vs full (15 agents) configs, the view-generator's front matter (expertise file, hot-loaded skills, tools, domain), and the /generate command.

The Workout

GOALTurn MA-2's team pattern into a system that operates a product: an N-variant generator producing brand-consistent artifacts (UI pages) in parallel, with validation and till-done tracking.
PREREQUISITESMA-2 workout completed (three-tier team + domain locking); a static-site or Vite playground repo; a brand token file.

  1. Define the domain model on disk

    brands/<brand>/brand.yaml (colors, type, radii as CSS custom properties) and apps/<brand>/<product>/<tree>/<branch-N>/index.html for generated leaves.

  2. Build the team config

    A setup team (scaffold worker), ui-gen teams A/B/C (view-generator + validator workers), one orchestrator. Domain-lock each ui-gen team so it can only write inside its assigned branch directories — parallel writes can't collide.

  3. Teach the orchestrator prompt engineering

    Its system prompt must require it to (a) write a till-done list of every branch, (b) send each team a complete prompt (brand file path, target dir, brief), (c) keep re-delegating until every item is done.

  4. Write the reusable command

    generate.md with parameters <brand> <product> <tree> <count> <brief> and a numbered Workflow: scaffold dirs → load brand context → write N briefs → round-robin generate across teams A/B/C → validate → fix failures → finalize.

  5. Run it

    /generate <yourbrand> app landing 3 "bold hero with live activity feed" — then open the three generated leaves in a browser.

  6. Chaos-test resilience

    Point team B at a flaky or cheap model; confirm the run still completes (another team or the lead picks up the work) and the till-done list ends fully checked.

  7. Prove the rebrand

    Change one token in brand.yaml and regenerate — confirm all variants pick up the rebrand (no hardcoded values).

DONE WHENOne command yields N distinct, brand-consistent UI variants written by different teams in parallel; a validator catches at least one issue that gets fixed without you prompting; a dead model does not stall the pipeline; zero hardcoded brand values in the output.
LEVEL UPAdd a brand-analyst worker that scores variants against brand.yaml; add model rotation on failure; add a second brand and prove the same team serves both; use Claude Code as your meta agent to improve the team's own prompts — "build the system that builds the system."
