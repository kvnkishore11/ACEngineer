The Idea

These are not coding agents. This is a CEO and a board built to make strategic decisions on your behalf.

The system has a function signature: uncertainty in, decision out. Three nodes carry it. The brief is the input — and the harness rejects any brief missing its required sections (Situation, Stakes, Constraints, Key Question): "We are kind of forcing great prompt engineering as a pattern into the agent harness." The deliberation is the debate — a multi-agent adversarial pattern where perspectives deliberately don't agree, "so we can really flesh out the mental model that we need to make the best decision possible." The memo is the output: a Jeff-Bezos-style recommendation with a decision map SVG, board stances, tensions, risks, next actions, and an ElevenLabs MP3 summary.

And it is a one-shot multi-agent system. Freeform prompting is refused; the only command is ceo begin. "This is not a conversation."

Uncertainty in, decisions out. The three nodes — brief → deliberation → memo — with six opinionated seats debating in parallel under a hard time and budget cap.
The three innovations. Each alone is nice; stacked, they promote agents from workers to decision-makers.

Why now? Three innovations converged. A true 1M-token context window at one flat price — "the core four just got a massive buff" (context, model, prompt, tools). A customizable agent harness — Pi, where "there are many coding agents, but this one is mine." And agent expertise: "Memory is quite vague, but expertise is memory and patterns surrounding a specific problem" — per-agent scratchpad files that persist and grow across deliberations (Dan's production ones run tens of thousands of tokens).

A constraints engine keeps the meeting honest: time (2–5 min) and budget ($1–$5) are enforced in code, and the harness injects "we're over time/budget, wrap it up" straight into the CEO's conversation.

The Nuggets

"At this next tier of agentic engineering, it's not just you making key decisions anymore… It's you, your team, and a country of geniuses in a data center."

— the quote of the lesson

This lesson is a tier shift, not a tooling tip.

"We're engineering and solving problems with our agents. We're not just coding anymore." Coding, in Dan's framing, "is just the beginning… it's the lowest hanging fruit." And the 1M window cuts both ways: in-loop, you simply compress less; out-loop, plugged into your systems, "the leverage you can get is now massive."

01

Price the decision

"How much is a high-leverage decision really worth to you?" Size time and budget to the value of the decision, not to habit.

02

Inputs, then outputs

"You must know what's your inputs and what's your outputs" — then design the workflow between them.

03

Spot the fan-out

Whenever a single node goes out to multiple agents, "immediately think multi-agent orchestration."

04

The 250K reality

Around 250K tokens, long-context retrieval starts degrading — but "you don't need perfect retrieval. You need retrieval that doesn't lose the key ideas."

05

Template your engineering

"If you template your engineering, your agents can do exactly what you did."

06

Serious in, serious out

"Don't just write a stupid two-sentence prompt. Think. Give your agents serious information to work with and it will give you a serious result."

07

Prompt engineering lives

"Prompt engineering is very much still alive — don't let anyone make you think that it's not."

08

Same page, every seat

Every board member gets ALL the extra context — product overview, business metrics: "they're all on the same page. This is key."

09

Measure or stall

"Observability is a key element of building powerful agentic systems. If you don't measure it, you cannot improve it, full stop." Full conversation.jsonl plus tool-use logs.

10

Engineer the conflict

You want agents "opposing each other at odds, so that they poke holes in each other's strategy."

11

Model diversity

"Agent model diversity is super super important for creating better conflict and unique opinion" — the one constraint: every model must hold long context.

12

Specialization → trust

"Specialization is the advantage, and specialization once again increases the trust we have in our agents."

"If you get a bunch of Chads on your team, every Chad is going to say 'Yeah, we should use React.'"

— why you engineer diverse, conflicting personas

The seats even argue visually — every agent can generate SVGs "to visually compel the CEO toward their argument." This depth is the moat: "If you're not building specialized agents… and customizing your agent harness, you're in the normal distribution of what everyone else is getting." And "this is where vibe coders have no shot… The awareness just isn't there" — you have to know the primitives, down to the system-prompt and subprocess level.

The result is "micro applications that do one thing extraordinarily well, the agentic way." And the value compounds: as briefs and memos stack per domain, you get "a chain and a stack of decisions… that's where there's real value" — expertise gets more valuable with every brief.

What Dan Did

Dan built the CEO-and-board app as a Pi extension — roughly 2,000 lines, one extension file — with its own directory layout.

"With the Pi agent harness you can make your own structures." Each board persona is a markdown file with front matter (expertise, skills, model) parsed by the harness and hot-loaded into the system prompt at boot with runtime variables — over the classic prompt format: Purpose / Variables / Instructions / Workflow / Context / Report. The revenue agent even drew a bull/base/bear multi-year exit plan as an SVG; a tts skill reads the memo aloud via ElevenLabs.

.pi/ceo-agents/ agents/ # ceo.md + six opinionated board personas config.yaml # meeting time (2–5 min) + budget ($1–$5) expertise/ # per-agent scratchpads — persist and grow briefs/ # uncertainty in deliberations/ # conversation.jsonl — full observability memos/ # decisions out
launch — the whole interface
j ceo        # J = alias for `just` — boots the extension
ceo begin    # the only accepted command. lists available briefs.

  1. Run the acquisition brief

    Mock company BlendStack (D2C supplement-stack builder) gets a $12M cash offer — 11x its $1M ARR — from PE firm Neutra Holdings. Auxiliary files business-metrics.md and product-overview.md ride along to every board member.

  2. Watch the deliberation

    CEO gathers context → updates its expertise file → broadcasts via its converse tool → all six seats respond in parallel → loop repeats while inside time and budget → harness injects "[MAX REACHED]" → CEO demands "final position, one statement each" → end_deliberation → memo written.

  3. Read the memo

    Board recommends accepting the $12M offer roughly 5-to-1, with conditions: a retention-linked earnout and a 90-day knowledge transfer. Moonshot dissents — "reject and run a 30-day investor test."

  4. Prove reuse

    Dan kicked off a second deliberation (an FDA-warning brief), having earlier run a shorts-platform marketing brief (verdict: fix the retention engine first, then YouTube Shorts).

"Nobody in three rounds could name the root cause of five quarters of decelerating growth. And that silence was the signal."

— the memo's TTS kicker
COSTThe entire live deliberation — six seats, multiple rounds, memo, SVGs, audio — ran about $2.50.
The one-shot meeting. No back-and-forth with you — the workflow runs itself from brief to memo, and the constraints engine ends it.

The Workout

GOALBuild a one-shot "board meeting" multi-agent decision system: brief in → parallel opinionated debate → memo out, under a time/budget constraint.
PREREQUISITESAny scriptable agent harness (a Pi extension, or Claude Code + headless claude -p subprocesses), a model with long context, and just.

  1. Lay out the three nodes

    mkdir board && cd board && mkdir agents briefs memos deliberations expertise — mirroring Dan's essential nodes: briefs, deliberation, memos.

  2. Write the personas

    agents/ceo.md plus 4 board seats with front matter (model, expertise, skills) and fully overridden system prompts: revenue.md (maximize cash in 90 days), compounder.md (multi-year compounding advantage), contrarian.md (attack assumptions), moonshot.md ("What if we're thinking too small?"). Give each Temperament / Reasoning patterns / Decision-making heuristics sections.

  3. Enforce the brief

    Write briefs/_template.md with required sections ## Situation, ## Stakes, ## Constraints, ## Key Question — and a validator that refuses to run a brief missing any section.

  4. Build the orchestration loop

    CEO reads the brief plus every .md context file in the brief's folder, broadcasts to all board members in parallel (each a separate agent process with a persistent session, preloaded with the same context), and appends every message to deliberations/<id>/conversation.jsonl (from/to/message).

  5. Add the constraint engine

    After every round, append elapsed time and cumulative cost to the CEO's context; at 80% of max, tell it to wrap; at max, force "final position, one statement each," then the memo.

  6. Add expertise

    Each agent reads expertise/<name>.md on boot and appends notes after the meeting.

  7. Run a real brief

    Write a brief about a real decision you're facing (job offer, pricing change, stack migration) with two auxiliary context files; run it end-to-end; read the memo.

DONE WHENA malformed brief is rejected; a valid brief produces a memos/<id>.md containing a recommendation, per-member stances, at least one explicit dissent, and unresolved tensions; conversation.jsonl replays the whole debate; and the meeting self-terminates within your time/budget caps.
LEVEL UPPut different vendors' models behind different board seats (model diversity → better conflict); add an SVG-generation skill so members argue visually; add "backroom talk" (member-to-member messages); grow one agent's expertise file across 5 briefs in the same domain and compare memo quality on brief #1 vs #5.
