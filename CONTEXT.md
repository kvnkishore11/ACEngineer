# CONTEXT — the domain model

The words this repository uses, and what they mean here. Where a word has a
loose everyday meaning and a precise meaning in this archive, the precise one
wins. See `docs/agents/domain.md` for the convention this file follows.

---

## Track

One body of course material. There are three, and the prefix of every lesson key
tells you which:

| Prefix | Track | What it is |
|---|---|---|
| `tac` | Tactical Agentic Coding | The foundational 8-lesson course |
| `ah` | Agentic Horizon | The 6 mastery-level modules |
| `ma` | Member Assets | Bonus lessons released publicly on YouTube |

A **video** (`yt` prefix) is not a track — see below.

## Lesson

One unit of course material: a recording, a transcript, metadata, and usually a
codebase. One directory under `catalog/courses/`.

## Lesson key

The identifier for a lesson, and the join key across the whole repository:

```
<track>-<n>-<slug>          e.g. tac-1-hello-agentic-coding
```

The same key names the lesson everywhere it appears:

| Where | Path |
|---|---|
| Catalog folder | `catalog/courses/tac-1-hello-agentic-coding/` |
| Finished video | `media/final/tac-1-hello-agentic-coding.mp4` |
| Raw capture | `media/raw/tac-1/` *(short form — see below)* |
| Raw VTT dumps | `transcripts/tac-1-hello-agentic-coding/` |

**Short key** (`tac-1`, `ah-3`) is the older, shorter form. It survives in
`media/raw/` subdirectory names and in the builders' `short_key` field. It is
not the lesson key and should not be used as one.

## Video

A YouTube upload, keyed `yt-NN-<slug>` and catalogued under `catalog/youtube/`.
Numbered oldest-first across a rolling ~13-month window, so **`yt-NN` numbers
are not stable across time** — an old video ageing out does not renumber the
others, but a fresh inventory can. When you need stability, join on the YouTube
video id recorded in each video's metadata, e.g.
`catalog/youtube/yt-01-i-can-see-everything-claude-code-hooks-for-multi-agent-obser/metadata/video-info.json`.

Some videos cover the same material as a paid lesson. Those get their
`codebase/` symlink pointed at the course codebase rather than a public repo.

## Codebase

A tree of code built or referenced in a lesson or video. All of them live under
`codebases/`, in four sub-trees by where they were used: `tac/`, `ah/`, `ma/`,
`yt/`.

Every codebase is a **vendored upstream snapshot**: the files as they stood at a
recorded commit, with no `.git` of its own. They are read, never edited.
Provenance — upstream URL and pinned commit — is in `REPOS.md`.

A lesson reaches its codebase through a symlink: `catalog/courses/<key>/codebase/`
→ `codebases/<tree>/<name>/`. The symlinks are generated by
`tools/catalog/build_catalog.py` and `tools/youtube/attach_codebases.py`, which
own their shape. Do not hand-edit them.

## Raw transcript vs stitched transcript

Both are "the transcript". They are not interchangeable.

| | Raw | Stitched |
|---|---|---|
| Path | `transcripts/<key>/*.vtt` | `catalog/courses/<key>/transcript/<key>.md` |
| Granularity | One chapter, often 60–90 seconds | The whole lesson |
| Format | WebVTT with timings and cue ids | Readable markdown |
| Read this? | Only to re-stitch | **Yes** |

Reading one raw chapter and answering from it is the single most common
avoidable error in this repository.

A lesson's transcript directory may also hold `<key>-notes.md` — the loot-box
notes companion. That is a **companion, not the transcript**.

## Distillation

A compressed answer derived from the archive, in `knowledge/distilled/`. One
file per topic; the thing to reach for first, before re-deriving anything.

Distinct from:

- **Research** (`knowledge/research/`) — the long-form working analysis behind a
  distillation. Read when you need the reasoning, not the conclusion.
- **Artifact** (`knowledge/artifacts/`) — a *rendered deliverable*, usually a
  self-contained HTML field guide or codex, meant to be read or shared as-is.
- **Draft** (`knowledge/drafts/`) — unfinished, superseded, or process residue.
  Nothing here is authoritative.

## Catalog

`catalog/` — the read-only front door. It holds no original bytes: the video is
a hardlink into `media/final/` and the codebase is a symlink into `codebases/`.
Its two indexes (`catalog/INDEX.json`, `catalog/youtube/INDEX.json`) are
generated and must contain repo-relative paths only.

## Manifest

`media/MANIFEST.md` — path, size and SHA-256 for every file under `media/`. The
bytes are not in git, so the manifest is how a checkout is audited:
`make check-media`.

## Hardlink, in this repository specifically

`media/final/<key>.mp4` and `catalog/courses/<key>/video/<key>.mp4` are the same
inode, not two files. This is why 18 lessons of video cost 8.9 GB rather than
17.8 GB. `mv` on one volume preserves it; `cp` or `rsync` without `-H` silently
doubles the disk cost. `stat -f '%l'` reporting `2` is correct.
